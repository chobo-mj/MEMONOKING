# v1.8 PPT 요구 추적표

작성일 2026-11-10. 사용자 제공 PPT **총 15장**을 기준으로 정리했다. 원본 PPT·추출 이미지는 저장소에 포함하지 않는다. 상세 계약은 [22 PPT 반영 계획](../plans/22-ppt-requirements.md), 통합 시험은 [08](../plans/08-tests-acceptance.md)에 있다.

최신 검증: [v6 확인 범위](visual-qa-v6.md), 자동시험 68개·clippy·release 빌드 통과. 실제 OS 창 확인과 자동 렌더링 시험을 구별한다.

최신 추가 지시인 [23 프로젝트 단일 분류·아이콘 도구](../plans/23-projects-icon-toolbar.md)가 분류와 도움말/도구 배치보다 우선한다. 라벨 분류는 폐기되었다.

이 표는 **요구 등록부**다. 상태 `검증 대기`는 구현 누락/완료를 단정하지 않으며, 개발 후 실제 동작·화면·시험 증거를 연결하여 갱신한다. 이전 v1.7 시험 통과를 이번 PPT 요구의 통과로 전용하지 않는다. 이번 단계는 UI/조작 우선이며, 후속 범위의 화면은 미리보기다. 잠금은 화면 가림 시뮬레이션으로, 실제 암호화·보안 통제를 제공하지 않는다.

## 해석·결정 사항

1. 6장의 최소화 항상위 off는 5장의 설정과 함께 적용한다. 기본은 자동 해제하며 사용자가 옵션을 끄면 유지한다. 복원 시 압정 복구 정책은 실제 UI 안내와 맞춰 기록한다.
2. 10장의 ‘재설정’은 원래 알림 정보를 지우지 않는 전달 중지/재개 기본안이다. 과거 알림 재전달 정책은 실제 알림 단계에서 확정한다.
3. 14장의 ‘행너비 일정하게’는 행 높이 균등화로, 미완성 문구 ‘이미지 삽입시 들여쓰기가 된 구간’은 현재 문단의 가용폭 안에 이미지 배치로 기록했다.
4. 15장의 폴더 생성은 선택이 없으면 최상위, 폴더 선택 시 그 안에 생성이다. 선택 해제를 제공해 형제 폴더를 만들 수 있게 한다.
5. 11/14장의 프로젝트 자동 입력은 Space가 최신 기본이며 기존 Enter는 호환 가능하다. 메모 본문 임의 위치의 #문자열을 프로젝트로 변환하지 않는다.

## 결과 기록 방법

상태는 `검증 대기 / 부분 확인 / 통과 / 결함 / 후속 구현`으로 갱신한다. 통과에는 빌드·시험·시각 확인 범위와 증거 경로를 연결한다. 실제 저장/보안/OS 연동이 없는 요구는 설정 화면을 확인했어도 제품 기능 통과로 기록하지 않는다. 기존 검증 기록은 당시 버전의 증거이며 이 표의 새 동작을 자동 입증하지 않는다.
