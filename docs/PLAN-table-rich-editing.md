# PLAN — Rust egui 메모장 Word형 표 편집 기능

> 사용자가 제공한 참고 문서. 표 기능(셀 직접 편집, Tab 키 이동, 드래그
> 다중 셀 선택, Excel 붙여넣기/복사의 CF_HTML 처리, Undo/Redo 통합 등)을
> 본격적으로 확장할 때 이 문서를 먼저 다시 읽고 Phase 0(기존 코드 조사)부터
> 순서대로 진행한다. 현재는 후순위로 미뤄둔 상태이며, 지금까지 구현된
> `insert_table`/`table_sizes`/`inline_tables`/`paint_tables`/
> `table_widget`/`BlockRec::TableV2`(`docs/WORKLOG-2026-11-13-table-paste-real-merge-and-position.md`
> 참고)가 Phase 0에서 조사할 "현재 구조"에 해당한다.

## 프로젝트 목표

기존 Rust + egui 메모장에 Microsoft Word와 유사한 인라인 표 편집 기능을 구현한다.

현재 구현된 `insert_table`, `table_sizes`, `inline_tables`, `paint_tables`, `table_widget`, `TableV2`를 먼저 조사하고 가능한 코드를 재사용한다.

표는 이미지처럼 표시되는 장식 요소가 아니라 메모 본문의 정식 편집 요소여야 한다.

기존 메모장 기능, 저장 데이터, 이미지 처리, 자동 저장, 실행 취소 및 기타 UI 기능을 최대한 보존한다.

## 공통 개발 규칙

1. 실제 저장소 코드를 확인하기 전에는 현재 아키텍처를 추정하여 변경하지 않는다.
2. 단계별로 구현하고 각 단계의 컴파일 및 테스트를 통과한 뒤 다음 단계로 진행한다.
3. 기존 저장 데이터를 파괴하는 변경은 금지한다.
4. 기존 메모 파일을 새로운 형식으로 저장하기 전에 마이그레이션 및 롤백 정책을 검증한다.
5. 기존 이미지, 텍스트, 클립보드 기능의 회귀 테스트를 수행한다.
6. 폐쇄망에서도 동작해야 하므로 런타임 인터넷 의존성을 추가하지 않는다.
7. 새 라이브러리는 기존 의존성으로 해결할 수 있는지 먼저 검토하고, 추가가 필요하면 이유와 오프라인 빌드 영향을 보고한다.
8. 각 단계 완료 후 변경 파일, 구현 내용, 테스트 결과, 남은 문제를 보고한다.

## Phase 0. 기존 코드 조사

다음 사항을 확인한다.

- 메모 본문이 단일 TextEdit인지, 블록 기반 편집기인지
- 표 위치를 저장하는 방식
- 이미지 인라인 삽입 구조
- TableV2의 직렬화 구조
- rowspan 및 colspan의 내부 표현
- 현재 표 셀의 입력 처리 방식
- Undo/Redo 구현 여부
- 자동 저장 및 변경 감지 구조
- 클립보드 읽기/쓰기 구현
- 메모 파일 버전 및 마이그레이션 방식

**산출물:** 기존 구조 분석, 재사용 가능한 코드, 변경 대상 모듈, 위험 요소 및 단계별 수정 계획.

기존 구조를 확인한 뒤 후속 Phase의 자료구조를 실제 코드에 맞게 조정한다.

## Phase 1. 문서 블록 모델

텍스트, 이미지, 표를 하나의 문서 안에 순서대로 배치할 수 있도록 문서 모델을 설계한다.

필수 조건:

- 안정적인 블록 ID
- 문서 내 블록 순서 보존
- 텍스트 블록과 표 블록 사이 커서 이동
- 표 앞뒤에 문단 추가 가능
- 기존 이미지 인라인 기능 유지
- 저장 후 블록 순서 완전 복원
- 기존 저장 형식에서 새 구조로 안전하게 변환

기존 TextEdit를 즉시 제거하지 말고, 새 모델과 연결하는 단계적 전환을 우선 검토한다.

**완료 기준:** 텍스트 → 표 → 텍스트 → 이미지 → 텍스트 순서의 문서를 생성, 편집, 저장, 재열기 할 수 있다.

## Phase 2. 셀 직접 편집

기존 table_widget을 개선한다.

- 셀 클릭 시 바로 텍스트 입력
- 더블클릭으로 셀 내부 단어 선택
- 셀 내부 커서 이동
- 셀 내부 텍스트 부분 선택
- Ctrl+A의 범위 정의
- 셀별 독립적인 TextEdit ID
- 셀 포커스 유지
- 한글 IME 조합 입력 지원
- 여러 줄 텍스트 지원
- 내용 증가에 따른 행 높이 자동 조절

편집 중 매 프레임 위젯 ID가 바뀌지 않도록 안정적인 셀 ID를 사용한다.

**완료 기준:** 한글과 영문을 연속 입력해도 포커스가 사라지거나 커서가 튀지 않는다.

## Phase 3. 키보드 탐색

다음 동작을 구현한다.

- Tab: 다음 셀
- Shift+Tab: 이전 셀
- 마지막 셀에서 Tab: 새 행 추가
- 방향키: 셀 내부에서는 문자 커서 이동 우선
- Ctrl+C / Ctrl+X / Ctrl+V: 선택 상태에 따라 처리
- Escape: 셀 편집 모드 종료
- Delete: 선택된 셀 내용 삭제
- Enter: 셀 안에서 줄바꿈
- Ctrl+Z / Ctrl+Y: 편집 취소 및 복구

Tab 이벤트는 셀 편집 상태에서 우선 처리하되, 일반 본문 및 다른 UI의 키보드 동작에 영향을 주지 않도록 한다.

**완료 기준:** 마우스 없이 표 전체를 입력할 수 있다.

## Phase 4. 셀 선택 모델

선택 상태를 다음과 같이 구분한다.

- 일반 텍스트 선택
- 단일 셀 활성화
- 셀 내부 텍스트 선택
- 여러 셀 범위 선택
- 표 전체 선택

여러 셀을 드래그하면 직사각형 범위가 선택되도록 구현한다.

병합 셀이 선택 범위에 걸쳐 있을 경우 선택 범위를 자동 확장하여 논리적으로 일관된 셀 집합을 만든다.

셀 텍스트 드래그와 여러 셀 선택 드래그가 충돌하지 않도록 시작 위치와 편집 모드에 따른 명확한 정책을 적용한다.

**완료 기준:** 여러 셀을 선택해 복사하거나 내용을 삭제할 수 있다.

## Phase 5. 행과 열 편집

우클릭 메뉴에 다음 기능을 추가한다.

- 위에 행 삽입
- 아래에 행 삽입
- 왼쪽에 열 삽입
- 오른쪽에 열 삽입
- 행 삭제
- 열 삭제
- 표 전체 삭제
- 셀 병합
- 셀 병합 해제
- 행 높이 자동 맞춤
- 열 너비 자동 맞춤

병합 셀을 가로지르는 행·열 삽입/삭제 시 span과 점유 좌표를 재계산한다.

모든 구조 변경은 실행 취소할 수 있어야 한다.

**완료 기준:** 병합 셀이 포함된 표에서도 행·열 편집 후 데이터 구조가 유효하다.

## Phase 6. 병합 셀 안정화

기존 rowspan/colspan 구현을 검증한다.

필수 불변 조건:

- 모든 셀의 row_span과 col_span은 1 이상
- 병합 영역은 표 범위를 벗어나지 않음
- 서로 다른 논리 셀의 점유 영역은 겹치지 않음
- 병합 영역 내부에 중복 활성 셀이 존재하지 않음
- 모든 격자 좌표는 정확히 하나의 논리 셀에 속함

병합 시 기존 셀 내용의 보존 정책을 정의하고, 병합 해제 시 복원 가능하도록 한다.

손상된 외부 HTML 표는 무조건 받아들이지 말고 유효성 검사 및 안전한 대체 처리를 수행한다.

**완료 기준:** 병합, 해제, 저장, 재열기를 반복해도 셀 내용과 구조가 손실되지 않는다.

## Phase 7. 크기 조절과 레이아웃

- 열 경계선 드래그로 너비 변경
- 최소 열 너비 제한
- 행 높이 자동 계산
- 필요 시 수동 행 높이 지원
- 긴 텍스트 자동 줄바꿈
- 표가 본문 너비를 초과할 때의 정책 정의
- 본문 스크롤과 표 렌더링 동기화
- DPI 배율 변경 대응
- 창 크기 변경 대응

레이아웃 좌표는 egui의 논리 좌표계를 기준으로 일관되게 관리한다.

**완료 기준:** 창 크기와 디스플레이 배율을 변경해도 표 경계, 입력 위치, 마우스 판정이 일치한다.

## Phase 8. Excel 붙여넣기

Windows 클립보드의 CF_HTML과 CF_UNICODETEXT를 지원한다.

우선순위:

1. 유효한 HTML 표
2. TSV 텍스트
3. 일반 텍스트

HTML에서는 table, tr, td, th, rowspan, colspan, 셀 내용 및 지원 가능한 기본 서식을 파싱한다.

CF_HTML의 오프셋과 인코딩을 정확히 처리한다.

외부 HTML은 신뢰할 수 없는 입력으로 취급하고 스크립트, 외부 리소스, 위험한 태그 및 속성은 무시한다.

TSV는 빈 셀, 마지막 빈 열, 여러 줄 데이터, 따옴표 처리 및 Excel의 실제 복사 형식을 테스트한다.

붙여넣기 위치에 따라 다음을 구분한다.

- 일반 본문: 새 표 삽입
- 단일 셀: 해당 셀을 시작점으로 데이터 배치
- 여러 셀 선택: 선택 범위 교체
- 단순 텍스트: 일반 텍스트로 삽입

대상 표보다 붙여넣기 데이터가 큰 경우 자동 확장 여부를 정책으로 정의한다.

**완료 기준:** Excel에서 복사한 일반 표와 병합 표가 의도한 위치에 들어간다.

## Phase 9. Excel로 복사

선택한 셀 범위를 다음 형식으로 내보낸다.

- CF_UNICODETEXT: TSV
- CF_HTML: HTML table

병합 셀의 rowspan/colspan을 유지한다.

일반 텍스트 편집 중 Ctrl+C는 셀 전체가 아니라 선택한 텍스트를 복사해야 한다.

셀 범위 선택 중 Ctrl+C는 셀 범위를 복사해야 한다.

**완료 기준:** 메모장에서 복사한 표를 Excel에 붙여넣으면 행·열과 병합 구조가 가능한 범위에서 유지된다.

## Phase 10. Undo/Redo 및 저장

표 편집 명령을 기존 실행 취소 시스템과 통합한다.

다음 작업을 지원한다.

- 셀 텍스트 입력
- 여러 셀 붙여넣기
- 행·열 삽입/삭제
- 병합 및 병합 해제
- 열 너비 변경
- 표 삽입 및 삭제

연속 타이핑은 적절히 하나의 Undo 단위로 묶는다.

IME 조합 중에는 불완전한 편집 기록이 생성되지 않도록 한다.

저장 시 문서 버전과 데이터 유효성을 확인한다.

기존 파일은 읽을 수 있어야 하며, 새 버전 저장 후 구버전 프로그램에서 열 수 있는지 여부를 명확히 문서화한다.

가능하면 기존 파일의 최초 마이그레이션 전에 백업을 생성한다.

**완료 기준:** 표를 편집하고 저장한 뒤 재실행해도 내용, 병합, 열 너비, 문서 위치가 보존된다.

## Phase 11. 안정성 및 성능

다음 테스트를 수행한다.

1. 2×2, 10×10, 50×20 표
2. 100×50 표의 성능 측정
3. 한글 IME 조합 입력
4. 빠른 Tab 연속 입력
5. 병합 상태에서 행·열 삭제
6. 병합 후 저장 및 재열기
7. Excel에서 다중 셀 붙여넣기
8. 빈 셀과 여러 줄 텍스트 붙여넣기
9. 표를 포함한 문서에서 이미지 삽입
10. 여러 표를 한 문서에 삽입
11. Undo/Redo 100회 반복
12. 창 크기 및 DPI 배율 변경
13. 오래된 메모 파일 열기
14. 비정상 종료 후 데이터 복구
15. 큰 표를 빠르게 스크롤할 때 입력 지연 측정

성능 최적화는 정확한 동작이 완성된 뒤 진행한다.

셀 렌더링 범위 최적화, 레이아웃 캐시, 변경된 셀만 재계산하는 방식 등을 검토한다.

## 완료 조건

다음 사용자 시나리오가 모두 성공해야 한다.

1. 메모를 작성한다.
2. 문장 중간에 3×3 표를 삽입한다.
3. 각 셀을 클릭하여 내용을 입력한다.
4. Tab으로 셀을 이동한다.
5. Excel에서 5×4 범위를 복사해 붙여넣는다.
6. 두 셀을 병합한다.
7. 열 너비를 마우스로 변경한다.
8. 표 아래에 일반 문장을 작성한다.
9. 저장하고 프로그램을 종료한다.
10. 재실행 후 동일한 문서를 확인한다.
11. 표를 다시 Excel에 복사한다.
12. Ctrl+Z로 이전 편집을 취소한다.

위 조건을 충족하지 못한 기능은 완료로 보고하지 않는다.

## Codex 작업 방식

먼저 Phase 0만 수행하고 조사 결과를 보고한다.

이후 실제 코드 구조에 맞게 설계를 확정하고 Phase 1부터 순차 구현한다.

각 Phase가 끝날 때마다 다음 내용을 보고한다.

- 변경한 파일
- 핵심 구현 내용
- 테스트 명령과 결과
- 기존 기능에 대한 영향
- 남은 문제
- 다음 단계에서 수정할 사항

기존 메모장 기능을 손상시키는 대규모 일괄 리팩터링은 피한다.

## 특히 주의해야 할 버그 5가지

**한글 입력 중 커서가 이동하는 문제**

egui에서 셀 위젯의 ID나 포커스가 바뀌면 한글 조합이 끊길 수 있습니다. 셀 ID를 안정적으로 유지하고 IME 조합 중 구조 변경을 피해야 합니다.

**병합 후 셀이 겹치는 문제**

rowspan과 colspan을 화면 좌표에만 반영하면 행·열 삭제 시 데이터 구조가 깨질 수 있습니다. 논리 셀 점유 맵을 별도로 계산해야 합니다.

**Excel 붙여넣기 시 열이 밀리는 문제**

HTML의 병합 셀, TSV의 빈 셀, 셀 안 줄바꿈을 잘못 처리하면 데이터가 다른 열로 이동합니다. 붙여넣기 파서를 독립적으로 테스트해야 합니다.

**표 편집 중 메모가 자동 저장되지 않는 문제**

셀의 내용 변경도 문서 전체의 변경 감지 시스템에 연결해야 합니다. 표 위젯 내부 상태만 바뀌면 저장되지 않을 수 있습니다.

**기존 메모 데이터 손상**

TableV2에서 새로운 문서 구조로 옮길 때 표 위치, 이미지 위치, 문단 내용이 바뀔 수 있습니다. 실제 기존 파일을 이용한 마이그레이션 테스트가 필수입니다.

## 개발 순서에 대한 최종 권장

가장 중요한 것은 표 기능을 한 번에 모두 구현하지 않는 것입니다.

우선 Phase 0에서 현재 구조를 분석하고, Phase 1~3에서 본문 내 표 삽입과 셀 직접 편집을 완성하세요. 그다음 Excel 붙여넣기와 셀 선택, 병합, Undo 기능을 단계적으로 확장하는 것이 안전합니다.

특히 현재의 table_widget과 TableV2가 잘 구현되어 있다면 상당 부분을 재사용할 수 있습니다. 반대로 메모 본문이 하나의 TextEdit와 그림 위치 정보에 강하게 의존한다면 문서 블록 모델 전환이 가장 큰 작업이 될 것입니다.

첫 번째 작업은 위 지시서의 Phase 0 코드 조사만 수행하는 것을 권장합니다. 조사 결과를 가져오면 현재 메모장 코드에 정확히 맞춰서 수정할 파일, 함수, 자료구조까지 구체화할 수 있습니다.
