# 작업 기록 — 2026-11-12 (2): 트레이 상주·스티커 복원·대용량 성능

## 요청

- Windows 시작 시 자동 실행을 켜고 재부팅하면 스티커는 바탕화면에 그대로, 메인 프로그램은 트레이에 있어야 한다.
- 메인 창 X는 종료가 아니라 트레이로 내린다.
- 메모 저장 용량이 10GB를 넘어도 느려지지 않게 한다: 보이는 행만 그리기, 목록 계산 캐시, 바뀐 것만 저장(SQLite), 이미지는 보일 때만 읽고 목록은 썸네일. 그러면 이미지 삭제 기능은 필요 없다.

## 원인

- 재부팅 후 스티커가 사라진 이유: 열린 메모 창을 저장하지 않았다(`restore`가 창 목록을 비웠다).
- 메인 창만 뜬 이유: X를 누르면 프로그램이 끝났고, 자동 실행이 메인 창을 띄웠다.
- 메모가 많을 때 느린 이유: 100ms마다 모든 행을 그리고 전체 메모를 거르고 정렬했다. 또 2초마다 전체 스냅샷을 만들고 모든 그림의 픽셀을 해시했으며, 시작할 때 모든 그림을 메모리로 풀었다.

## 변경

| 영역 | 내용 | 파일 |
|---|---|---|
| 저장 | `data.json` 대신 SQLite `data.db`를 쓴다(메모 한 개가 한 행). 입력이 있었을 때만 2초 뒤 저장하고, 없으면 1분마다 확인한다. 바뀐 메모 행만 쓰고, 0.3의 `data.json`은 자동으로 옮긴다. 옮긴 뒤 이전 버전이 쓴 더 새 `data.json`은 DB를 백업한 다음 가져온다. 백업은 `VACUUM INTO`로 하고, 그림은 공유하므로 복사하지 않는다 | `storage.rs`, `desktop.rs` |

| 트레이 | 트레이 아이콘(열기 / 새 스티커 메모 / 종료, 아이콘 클릭 = 열기)을 단다. 메인 창 X는 트레이로 내린다. 자동 실행 값은 `"exe" --tray`이다. 단일 실행: 두 번째 실행은 실행 중인 메인 창만 띄운다 | `tray.rs`(신규), `main.rs`, `system.rs`, `Cargo.toml` |
| 목록 | `lists::lazy_row`로 보이는 행만 그린다(내 작업실·오늘/다음·상세 표·전체메모 표). `lists::Cache`로 목록·캘린더 띠·날짜별 목록·오늘 개수를 입력이 있을 때만 다시 계산한다 | `lists.rs`(신규), `views.rs`, `catalog.rs`, `main.rs` |

## 검증

- `cargo test`: Windows 111개 모두 통과. Linux에서는 Windows 글꼴이 필요한 기존 표 이미지 테스트 1개만 실패하며, 이번 변경과 관계없다. `cargo fmt --check`, `cargo clippy --all-targets` 경고 0.
- 새 테스트:
  - 입력이 없으면 저장하지 않고, 입력 뒤에는 바뀐 메모만 쓴다. 스티커 창이 같은 모드로 복원된다.
  - `data.json`을 DB로 옮기고, DB를 백업·복원하며, 더 새 `data.json`을 가져온다.
  - 목록 캐시 재사용, 1만 행 중 보이는 행만 그리기, 트레이 아이콘 픽셀.
- PC 실측:
  - 메인 창 X를 누르면 창만 사라지고 프로세스와 스티커는 남는다.
  - 다시 실행하면 같은 프로세스의 메인 창이 뜬다.
  - 프로세스를 강제로 끝낸 뒤(전원 끄기와 같음) `--tray`로 시작하면 메인 창 없이 스티커가 같은 자리(540,246 · 360×360)에 다시 뜬다. 트레이 아이콘을 클릭하면 메인 창이 열린다.
- 성능(메모 2만 개, 3000×2000 그림 40장, 같은 데이터):

  | | 0.3.0 | 이번 빌드 |
  |---|---|---|
  | 창이 뜰 때까지 | 2.1초 | 1.3초 |
  | 가만히 있을 때 CPU | 99.8%(코어 1개 전부) | 7.8% |
  | 메모리 | 1,489 MB | 438 MB(그림 수와 무관) |

  이미지 모아보기에서는 보이는 카드 12장만 썸네일을 만들었다. 스티커 안 그림은 열 때 읽힌다.

## 사용자 데이터

- 실제 데이터 폴더에 `data.db`보다 오래된 `data.json`(12:37, 메모 11개, ‘바탕화면 메모 테스트’ 포함)이 남아 있었다. DB에는 그 메모가 없었다.
- 그래서 시각을 갱신해 새 규칙으로 가져왔다. 가져오기 전 DB는 `backups\20261112-011801\data.db`에 있고, 원본은 `data.json.1237-original`로 남겼다.
- ‘바탕화면 메모 테스트’를 스티커로 열어 두었다.

## 남은 것 / 알릴 것

- 0.3 이하 버전은 `data.db`를 읽지 못한다. 설치된 0.3을 다시 실행하면 빈 작업 공간이나 예전 `data.json`으로 시작한다. 새 설치 파일 배포가 필요하다.
- 제거할 때 자동 실행 레지스트리 값을 지우지 않는 문제는 기존 그대로다(보고만 함).
- 위키 미분류 목록과 캘린더 분리창은 이번에 보이는 행만 그리기·캐시를 적용하지 않았다. 메모가 아주 많을 때 다음 후보다.
- 이미 보고한 죽은 코드: `views.rs`의 `collections()`(지우지 않음).
