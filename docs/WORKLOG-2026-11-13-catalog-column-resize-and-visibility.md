# 2026-11-13 메모 리스트 컬럼 너비조정/표시선택 (#54)

## 요청
"메모 리스트 컬럼 너비조정/표시선택 기능" — 상세 목록(메모 리스트) 표의 각 컬럼 너비를 조절하고,
필요 없는 컬럼은 숨길 수 있게 해달라는 요청. 원본 요청에 세부 범위(어떤 컬럼을 대상으로 하는지)가
명시되어 있지 않아 아래와 같이 가정하고 진행했다.

## 가정 (명시)
- 상세 목록 표의 8개 컬럼 중 `표시`(눈 아이콘)·`제목`·`내용`·`삭제`는 핵심 동작/핵심 정보 컬럼이라
  너비조정·숨기기 대상에서 제외했다. `제목`/`내용`은 기존처럼 남는 공간을 나눠 갖는 가변(flex) 폭을
  유지한다.
- 너비조정·표시선택 대상은 `완료`·`알람`·`생성일`·`일정` 4개 컬럼으로 한정했다. 이 네 컬럼을 숨기면
  확보된 공간은 `내용` 컬럼으로 넘어간다.
- 너비조정 범위는 24~220px로 제한했다(과도하게 좁히거나 넓히는 것을 방지).

## 구현
- `src/catalog.rs`
  - `Catalog`에 `column_widths: [f32; 4]`(0이면 "커스텀 없음, 기본값 사용"), `column_hidden: [bool; 4]`
    (기본값 `false` = 전부 보임) 추가. 기존 `#[derive(Default)]`가 그대로 올바른 기본값을 내도록
    "숨김" 쪽으로 불리언을 뒤집어서 저장했다(표시 여부 대신 숨김 여부를 저장).
  - `table_cells()`가 `&Catalog`를 받아 커스텀 너비/숨김 상태를 반영하도록 수정. 기존 고정폭 배열
    `COLUMN_WIDTHS`는 "변경 전 기본값"으로 남아 있다.
  - 표 헤더에 각 조정 대상 컬럼 경계마다 드래그 핸들을 추가(기존 미리보기 폭 조절 핸들과 동일한
    상호작용 패턴: 호버 시 강조선, 드래그로 너비 변경, 더블클릭으로 기본값 복귀).
  - 목록 상단 도구줄(`catalog_controls`)에 "열 표시" 콤보박스를 추가해 4개 컬럼의 표시/숨김을
    체크박스로 전환할 수 있게 했다.
- 새 테스트 `hidden_columns_collapse_to_zero_and_custom_widths_are_honored` — 숨김 컬럼이 폭 0으로
  접히고 그 공간이 `내용` 컬럼으로 넘어가는지, 커스텀 너비가 반영되는지, 0 센티널이 "숨김"이 아니라
  "기본값"으로 해석되는지 확인.

## 시험
- Linux: `cargo test` 123개 중 122 통과(윈도우 전용 글꼴 경로 의존 테스트 1개는 기존부터 실패하던
  것, 회귀 아님), `cargo clippy --all-targets` 경고 없음, `cargo fmt --check` 통과.
- Windows 실기 UI 확인은 보류(이번 라운드는 구현을 먼저 몰아서 진행하고, 마지막에 한 번에 비주얼
  검증을 요청하기로 함).

## 범위 밖
- 컬럼 순서 변경(드래그로 재배치)은 포함하지 않았다.
- 컬럼 표시/숨김·너비 설정은 세션 내에서만 유지되며 디스크에 저장되지 않는다(`storage.rs`
  미변경). 영속화가 필요하면 별도로 요청해달라.

## 후속 수정 — "열 표시" 버튼이 안 보이는 문제 (비주얼 검증에서 발견)

실제 PC에서 확인했을 때 너비조정은 되지만 "열 표시" 버튼이 보이지 않는다는 보고를 받았다.
원인은 조정 가능한 컬럼을 쓰는 표(`catalog_table`)가 두 개의 서로 다른 진입점에서 호출되는데,
"열 표시" 콤보박스는 그중 `catalog_controls()`(카탈로그 화면의 "전체 메모 보기" 탭)에만 추가했고,
할일/일정 목록 화면(`views::filters()` → `detail_workspace`/`agenda`)에는 추가하지 않았기 때문이다.
사용자가 테스트한 "메모 리스트" 화면은 후자였다.

- `catalog_controls()`에서 콤보박스 부분을 `pub(crate) fn column_picker()`로 분리하고,
  `src/views.rs`의 `filters()`에도 같은 메서드를 호출하도록 추가해 두 화면 모두 "열 표시"가
  나오게 했다. `ADJUSTABLE_COLUMNS`도 `pub(crate)`로 바꿔 `views.rs`에서 접근 가능하게 했다.
- 새 테스트 `views::column_picker_tests::filters_offers_the_same_column_picker_as_catalog_controls`
  — `filters()`를 렌더링해 "열 표시" 텍스트가 실제로 그려지는지 확인(수정 전에는 실패, 수정 후
  통과함을 직접 되돌려서 확인).
- `cargo build`/`cargo clippy --all-targets`/`cargo fmt --check`/`cargo test` 모두 통과(기존
  Windows 폰트 경로 테스트 1건 제외).
