# 0.2.0 디자인 디테일·창 조작·시험 배포 검증

2026-11-10 · Windows x64 · 화면과 조작 미리보기. 원본 요구사항 PPT 15장과 추가 디자인 PPT 3장을 기준으로 검토했다. 원본 문서와 추출 이미지는 저장소/배포판에 포함하지 않는다.

## 변경과 코드 검토

- 작업실 상세 보기를 표시/완료/제목/내용/알람/생성일/일정/삭제의 가로 8열로 교체했다. 우측 편집 미리보기는 약 300 논리 픽셀을 사용하며 표만 가로 스크롤한다. 헤더/본문 열 위치, 좁은 창의 마지막 열 접근, 복수 행 표시를 렌더링 시험으로 확인했다.
- 메모는 상단 헤더·제목/속성·본문·하단 탭/아이콘으로 구분했다. 시작/종료 날짜와 시간은 달력에서 선택하고 프로젝트만 분류 옵션으로 남겼다. 폴더 정리는 별도 전용 화면에 유지한다.
- 본문과 하단 도구를 분리해 본문만 스크롤한다. 탭 아래 구분선과 아이콘 줄, 우측 연결 메모 화살표를 둔다. 자동숨김 스티커는 탭만 최하단에 표시한다. 최대화/복원과 더보기 도움말을 제공한다.
- 실시간 관측 크기를 매 프레임 다시 요청하던 코드와 수동 이동/크기 계산 경로를 제거했다. 초기/모드 전환의 크기 요청과 Windows 네이티브 BeginResize/StartDrag를 사용한다. Shift 상자는 조작 종료 후 안정된 위치에 한 번만 정사각형을 적용한다.
- 추가 검토에서 닫은 창 재생성 시 저장 크기 누락, 상태 메시지가 있을 때 하단 도구 잘림, 완료시각 선택 중 다른 완료 발생으로 이동하면 잘못 적용될 수 있는 경로를 발견해 각각 수정하고 회귀시험을 추가했다.
- 명시적 종료 날짜를 통해 5일을 넘는 기간도 표현한다. 단일 완료 메모의 종료 시각만 수정했을 때 완료 상태를 보존하고, 단일/기간 전환과 일정 이동에서도 완료 시각의 의미를 유지한다.

## 자동검사

- `cargo fmt --all --check`, `cargo clippy --locked --all-targets -- -D warnings`, `cargo test --locked`를 실행한다. 최종 시험 개수와 빌드 결과는 아래 최종 결과에 기록한다.
- 400일 일정, 역순 시작/종료 정규화, 기간 이동/축소/확장, 완료 해제 후 기록 부활 방지, 독립 창/탭·댓글·프로젝트·드래그·복사/내보내기 회귀를 포함한다.
- 네이티브 크기 변경 중 수동 geometry 명령이 발생하지 않고 종료 보정은 한 번만 수행되는지 확인한다. 이 시험은 실제 화면의 떨림 관찰을 대신하지 않는다.

## 실제 창 검증 상태

기존 사용 중인 debug 실행본을 보존하고 별도 release 실행본에서 확인했다. Windows 잠금이 풀린 뒤 검증을 재개했다.

- 작업실의 8열 목록과 한 장의 우측 미리보기를 확인했다. 기본 창 폭에서 마지막 삭제 열이 가려지지 않도록 미리보기를 250~300 범위에서 조절하고, 좁은 폭의 표는 자체 가로 스크롤을 유지했다.
- 우측 미리보기의 두 줄 아이콘이 아래에서 잘리던 문제를 발견해 하단에서 위로 배치하는 컨테이너 안의 줄바꿈 도구 영역에 실제 높이를 확보했다. 다시 실행한 창에서 마지막 투명도·배율 아이콘까지 모두 표시되는 것을 확인했다.
- 분리 편집창의 제목/색상/완료/중요, 시작·종료/정기·위키, 프로젝트/생성시각, 넓은 본문, 맨 아래 탭·서식 아이콘·연결 화살표를 확인했다. 폴더 선택은 없다. 스티커의 상단은 아이콘으로만 표시하고 도움말은 더보기 메뉴 안에 있다.
- 스티커를 360×360에서 336×300으로 모서리 드래그한 뒤 변경이 유지되는 것을 확인했다. 최대화 후 복원하면 336×300으로 돌아오고 본문과 하단 도구가 다시 배치됐다.
- 빠른 드래그가 Windows 크기/이동 루프 시작 전에 끝나거나 실제 창이 움직이지 않은 채 종료되는 경우를 재현했다. 이미 끝난 입력에만 최종 크기/위치를 한 번 적용하는 보완 후 스티커 위치가 논리 픽셀 30×30 이동하고, 작은 상자도 16×16 이동했다. 연속 관측 크기를 되돌려 보내는 경로는 없다.
- 스티커→제목 한 줄(편집·압정·접기, 닫기 없음)→48×48 색상 상자로 접기, 상자를 36×36으로 조절, 더블클릭하여 360×360 스티커로 복원을 확인했다. 작은 상자를 가리던 긴 툴팁은 제거했다.
- 작은 상자에서 큰 편집창을 다시 열 때 하단이 화면 밖으로 나갈 수 있는 경우를 발견해 현재 모니터의 작업 영역 안으로 위치를 맞추도록 보완했다. 음수 좌표 모니터의 위치 계산도 회귀시험에 포함했다.

실제 Shift 키를 누른 연속 드래그, 모든 방향의 장시간 마우스 조작, 다중 모니터/DPI 변경은 별도 수동 인수 대상이다. 빠른 입력·단발 종료 보정·원본 크기 보존의 자동시험과 위 직접 확인 범위를 구별한다.

## 배포 검증 상태

설치형/포터블/체크섬을 만드는 Windows 워크플로를 준비했다. 정적 CRT 의존성, 파일 허용 목록, 현재 사용자 설치·바로가기·제거, 최종 해시 확인을 통과한 뒤 사전 배포한다. 첫 실행에서 정적 CRT 빌드·테스트·런타임 검사·포터블 스테이징을 통과했으나 설치 도구 탐색에서 중단됐다. 설치 도구의 버전 확인/탐색을 보완했다. 다음 실행의 도움말 식별 검사가 설치된 도구를 잘못 거부해, 도움말 형식에 의존하지 않고 실제 무출력 컴파일 결과의 엔진 버전으로 확인하도록 단순화했다. CI 실행과 공개 첨부파일 확인 전에는 설치파일 배포 완료로 기록하지 않는다.

## 최종 결과

- 로컬 형식 검사와 Clippy 경고 0개 검사를 통과했다.
- `cargo test --locked`: **86개 통과, 실패 0개**.
- 정적 CRT x64 release 빌드와 dumpbin 직접 의존성 검사를 통과했다. 별도 Visual C++ 런타임 DLL이 나타나지 않았다.
- 위 실제 창 검증을 완료했다. 작업 영역 안으로 복원하는 보완도 최종 창에서 확인했다. 360 높이 스티커를 아래로 200 논리 픽셀 이동한 뒤 620×720 편집창으로 열면, y=132에 재배치되어 하단이 852 작업 영역 안에 모두 보였다. 달력/시간 팝업과 완료 후에만 `완료 시간 :` 표시도 확인했다. GitHub 설치/제거·공개 릴리스 결과는 추가 확인 후 갱신한다.

## 범위와 추가 인수

프로그램 종료 시 데이터와 설정은 초기화된다. 저장/백업·암호화·실제 Windows 알림/트레이/자동시작, 완전한 한국 공휴일과 반복 발생 엔진은 후속이다. 잠금은 UI 시뮬레이션이다. 서로 다른 DPI/모니터, 원격 세션, 대량 창·탭, 모든 IME와 접근성 조합은 추가 인수 대상이다. 사내 PC 동작은 해당 환경에서 별도로 확인해야 한다.
