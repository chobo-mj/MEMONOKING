# 작업 기록 — 2026-11-12 (3): 전체 점검 (메모리·데이터 관리·편의성·버그)

## 요청

근무자 보기 버튼을 빼고, 지금까지 작성된 코드를 점검해 메모리 비효율·데이터 관리 비효율·UI 편의성 부족·버그를 모두 고친다.

## 찾은 것과 고친 것

### 메모리

| 문제 | 조치 | 파일 |
|---|---|---|
| 글꼴 파일 6개(약 100MB)를 통째로 읽고, 같은 파일을 두 번씩 읽었다 | 메모리 맵으로 열고 파일당 한 번만 연다 | `main.rs`, `Cargo.toml`(memmap2) |
| 자동 저장이 모든 메모의 사본을 하나 더 들고 있었다 | 메모별 64비트 지문만 둔다 | `storage.rs` |
| 한 번 본 그림의 텍스처를 프로그램이 끝날 때까지 들고 있었다 | 화면에서 사라지고 60초 뒤 해제한다 | `lists.rs`, `composer.rs`, `content_collections.rs`, `main.rs` |

### 데이터 관리

| 문제 | 조치 | 파일 |
|---|---|---|
| 저장 확인 때마다 모든 메모를 레코드로 만들어 비교했다(2만 개에서 35~65ms) | 수정용으로 꺼낸 메모만 본다(`model::Notes`) | `model.rs`, `storage.rs` |
| 시작할 때마다 모든 메모를 DB에 다시 썼다 | 읽은 내용을 저장된 것으로 표시한다 | `storage.rs` |
| WAL 파일이 줄지 않았다(테스트 데이터에서 65MB) | 열 때 체크포인트(TRUNCATE), 크기 제한 4MB | `storage.rs` |
| 휴지통 보관 기간 정리가 시작할 때만 돌았다(트레이 상주라 거의 안 돎) | 실행 중 1시간마다 | `main.rs` |
| 더 새 `data.json`이 깨져 있으면 멀쩡한 DB를 ‘깨진 파일’로 옮겼다 | 그 json만 `data.unreadable.json`으로 옮기고 DB를 쓴다 | `storage.rs` |
| 데이터 폴더를 이미 데이터가 있는 폴더로 바꾸면 그 데이터를 덮어썼다 | 덮어쓰기 전에 그 폴더에 백업한다 | `storage.rs` |
| 저장 실패가 설정 화면에만 보였다 | 화면 아래 알림으로 한 번 알린다 | `storage.rs` |
| 제거해도 자동 실행 등록이 남았고, 트레이에 떠 있으면 파일을 못 지웠다 | 제거 때 프로그램을 끝내고 등록을 지운다 | `packaging/OmniMemoJang.iss` |

### 속도 (메모 2만 개 기준 한 프레임)

| 화면 | 전 | 후 |
|---|---|---|
| 전체메모 · 폴더 보기 | 55ms | 1.3ms |
| 전체메모 · 관계 보드 | 415ms | 1.0ms |
| 편의기능 · 업무일지(완료 2,800개) | 37ms | 0.2ms |
| 나만의 위키 | 0.7ms | 0.3ms |

폴더 보기·위키 트리·업무일지·관계 트리에 ‘보이는 행만 그리기’와 계산 캐시를 적용했다. 관계 보드는 화면 밖 카드를 그리지 않고, O(N²)이던 연결 계산을 한 번 훑기로 바꿨다. 입력이 10초 없으면 다시 그리기 주기를 100ms에서 250ms로 늦춘다.

### 편의성

- 빠른 메모·새 스티커를 열면 커서가 본문에 있어 바로 입력된다(전에는 한 번 클릭해야 했다).
- 새 메모 창이 이미 열린 창 위에 정확히 겹치지 않고 28px씩 비켜 열린다.
- 메인 창을 처음 X로 닫으면 화면 오른쪽 아래에 ‘트레이에서 계속 실행됩니다’ 안내가 한 번 뜬다.
- 없어진 모니터에 있던 스티커는 지금 모니터 안으로 들어와 열린다.
- Windows가 `--tray`로 다시 시작해도 이미 실행 중이면 메인 창을 띄우지 않는다.
- 문구: 휴지통 설명(‘현재 실행 중에만 보관’은 사실이 아니었다), 자동 실행 설명, 백업 안내(다른 PC로 옮길 때는 폴더 전체), 사용법의 트레이 설명.

## 검증

- Windows: `cargo test` 113개 통과, `cargo fmt --check`, `cargo clippy --all-targets` 경고 0. Linux에서는 Windows 글꼴이 필요한 기존 테스트 1개만 실패한다.
- 새 테스트: 수정된 메모 번호 추적, 시작 뒤 바뀐 메모 하나만 저장, 깨진 새 json이 DB를 대신하지 않음, 텍스처 해제.
- PC 실측(같은 빌드 조건, 10초 평균):

  | | 점검 전 | 점검 후 |
  |---|---|---|
  | 빈 작업 공간 · 메인 창 | 386 MB · CPU 5.4% | 197 MB · CPU 2.2% |
  | 빈 작업 공간 · 트레이 | 319 MB · CPU 2.0% | 130 MB · CPU 0.1% 미만 |
  | 메모 2만 개 · 메인 창 | 485 MB · CPU 9.5% | 290 MB · CPU 0.2% |

- 빠른 메모에 바로 입력 → 3초 뒤 강제 종료 → `--tray`로 시작: 메인 창 없이 그 메모가 스티커로 다시 떴다. WAL은 65MB에서 32바이트가 됐다.

## 남은 것

- 관계 보드에서 새 메모 카드가 같은 자리에 겹쳐 놓인다(‘자동 정렬’을 눌러야 펼쳐진다). 기존 동작이고 이번에 바꾸지 않았다.
- 쓰지 않는 코드: `views.rs`의 `collections()`(지우지 않고 보고만 한다).
- 설치 파일(.iss) 변경은 설치 프로그램을 새로 만들어 돌려 보지는 않았다. 릴리즈 빌드 때 확인이 필요하다.
- 버전 표기는 아직 0.3.0이다. 데이터 형식이 바뀌었으므로 다음 릴리즈는 0.4.0으로 올리는 것이 맞다.
