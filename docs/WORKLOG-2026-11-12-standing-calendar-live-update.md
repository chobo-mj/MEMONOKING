# 작업 기록 — 스탠딩 캘린더 실시간 반영 확인 (2026-11-12)

## 배경

사용자 요청 (원문):
> 스탠딩 캘린더로 고정된 캘린더 화면이 메인 프로그램에서 업데이트한 내용이 반영되었으면 좋겠어. 메모나 일정이 추가/삭제/완료 처리되면 스탠딩캘린더에도 실시간 반영이 되게해줘.

## 코드 분석

먼저 구조를 살펴봤다.

- `main.rs`의 `App::update()`는 ROOT 뷰포트가 매 프레임마다 `self.calendar_dock(ctx)`를 **무조건** 호출한다. 스탠딩 상태 여부와 관계없이, 캘린더 뷰포트는 메인 창과 같은 틱으로 매번 다시 그려진다.
- 반복 주기는 `ctx.request_repaint_after(...)`로 제어되며, 최근 10초 이내 입력이 있었으면 100ms, 아니면 250ms다.
- `views.rs`의 `calendar()` 함수는 `self.data.notes`를 매 호출마다 직접 읽는다. 캐시(`self.lists`)는 있지만 캐시 키가 `(self.day, self.data.notes.len())`라서, 날짜가 바뀌거나 메모 개수가 바뀌면(추가/삭제) 바로 무효화된다. 완료 처리처럼 개수가 그대로인 변경도 캐시 키 설계상 특별한 문제가 되지 않는 것으로 보였다(실측으로 확인 필요).

즉, 설계상으로는 이미 실시간 반영이 되어야 할 구조였다. 다만 Win11 24H2+ 데스크톱 재부모(SetParent) 환경에서 실제로도 그렇게 동작하는지는 코드만으로 단정할 수 없어서, 실제 PC에서 직접 검증했다.

## 실측 검증 (Windows 11, 빌드 26200)

1. 캘린더를 분리 → "캘린더 분리" 버튼으로 바탕화면에 고정(스탠딩) 상태로 전환.
2. 메인 창을 최소화해 바탕화면 아이콘 뒤의 스탠딩 캘린더만 보이는 상태로 확인.
3. **추가**: 메인 창을 복원 → "캘린더" 사이드바에서 11월 12일의 "+ 이 날짜에 스티커"로 "실시간테스트"라는 제목의 새 메모 생성 → 메인 창 다시 최소화 → 스탠딩 캘린더의 12일 칸에 "실시간테스트"가 **즉시** 표시됨을 확인.
4. **완료 처리**: 메인 창 복원 → 날짜 상세 패널에서 해당 메모의 체크박스 클릭(완료 처리) → 다시 최소화 → 스탠딩 캘린더에서 해당 항목이 취소선 처리된 상태로 **즉시** 반영됨을 확인.
5. **삭제**: 메인 창 복원 → 해당 메모 우클릭 → "휴지통으로 이동" → 다시 최소화 → 스탠딩 캘린더의 12일 칸에서 해당 항목이 **즉시 사라짐**을 확인.

세 가지 트리거(추가/완료/삭제) 모두 별도의 재시작이나 수동 새로고침 없이, 메인 창을 가렸다가 다시 보이는 사이(최대 250ms 주기)에 바로 반영되는 것을 확인했다.

## 결론

**이 기능은 이미 정상 동작하고 있었다.** 코드 변경은 하지 않았다. `calendar_dock(ctx)`가 매 프레임 무조건 호출되는 기존 구조 덕분에, 스탠딩 캘린더는 메인 프로그램의 메모/일정 변경(추가·삭제·완료)을 자동으로, 실시간에 가깝게(최대 0.25초 지연) 반영하고 있다.

혹시 사용자가 실제로 반영이 안 되는 상황을 겪었다면, 다음 중 하나였을 가능성을 염두에 둘 필요가 있다:
- 스탠딩 캘린더가 꺼져 있는 달(month)과 메모를 추가한 달이 달라서 화면에 안 보였던 경우
- #45에서 고친 "SetParent 실패를 성공으로 오인하는 버그"로 인해 애초에 고정이 제대로 안 된 상태였던 경우 (이 경우라면 #45 수정으로 함께 해결됨)
- 메모에 날짜가 아예 안 붙어 있던 경우 (예: 일반 "+ 새 메모"는 날짜 없는 메모를 생성하므로 캘린더에 표시되지 않음 — 이는 날짜가 없다는 점에서 의도된 동작)

만약 위 테스트 이후에도 실시간 반영이 안 되는 재현 가능한 케이스가 있다면, 구체적인 재현 절차(어떤 뷰에서 추가했는지, 날짜 지정 여부, 스탠딩 캘린더가 보고 있던 달)를 알려주시면 추가로 조사하겠습니다.
