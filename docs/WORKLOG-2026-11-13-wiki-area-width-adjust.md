# 2026-11-13 나만의 위키 영역 너비 조절 (#59)

## 요청
"나만의 위키 영역 너비 조절" — 나만의 위키 화면의 영역 너비를 조절할 수 있게 해달라는 요청.

## 조사
- `src/refinements.rs`의 `wiki()`가 나만의 위키 화면을 3개 영역으로 나눈다: 왼쪽 트리/미분류
  목록 컬럼(전체 너비의 22%, 210~280px로 고정 클램프)과 오른쪽 두 콘텐츠 창(항상 50:50 균등
  분할). 세 영역 모두 사용자가 조절할 수 있는 수단이 없었다.

## 가정 (명시)
- "영역 너비 조절"을 좌측 목록 컬럼 너비와 두 콘텐츠 창의 분할 비율, 양쪽 모두를 조절할 수 있게
  하는 것으로 해석했다(어느 한쪽만 가리킨 것이었다면 알려주시면 범위를 좁히겠다).

## 구현
- `src/extras.rs`: `Extra`에 `wiki_left_width: f32`(0이면 기존 비례 기본값 사용)와
  `wiki_pane_frac: f32`(기본 0.5, 균등 분할) 추가.
- `src/refinements.rs`
  - 레이아웃 계산을 순수 함수로 분리: `wiki_left_col_width`/`wiki_left_col_bounds`(좌측 컬럼
    너비와 유효 범위), `wiki_pane_widths`(두 콘텐츠 창의 분할, 각각 최소 160px 보장). 테스트에서
    직접 검증할 수 있도록 UI 코드와 분리했다.
  - 기존 미리보기 폭 조절 핸들(catalog.rs)·캘린더 가로 분할 핸들과 동일한 패턴으로 드래그 핸들
    2개 추가: 좌측 컬럼과 콘텐츠 영역 사이, 두 콘텐츠 창 사이. 호버/드래그 중 강조선, 더블클릭으로
    기본값 복귀.
  - 새 테스트 `wiki_left_width_falls_back_to_the_proportional_default_at_zero`,
    `wiki_pane_widths_split_by_fraction_and_keep_a_minimum` — 기본값 폴백, 커스텀 값 클램프,
    최소 폭 보장을 확인.

## 시험
- Linux: `cargo test` 130개 중 129 통과(윈도우 전용 글꼴 경로 테스트 1개는 기존 실패, 회귀 아님),
  `cargo clippy --all-targets` 경고 없음, `cargo fmt --check` 통과.
- 너비 설정은 이번 세션 동안만 유지되며 디스크에 저장되지 않는다(다른 UI 설정 조절 기능들과
  동일한 범위). 비주얼 확인은 이번 라운드를 모두 마친 뒤 한 번에 요청할 예정.
