# 2026-11-13 '+ 새 메모' → '+ 새 일정' 버튼 변경 (#55)

## 요청
"+ 새 메모' → '+ 새 일정' 버튼 변경 + 메모편집창 열기" — 오늘의 할일/다음에 할일 목록 상단의
"+ 새 메모" 버튼을 "+ 새 일정"으로 바꾸고, 눌렀을 때 메모편집창이 열리게 해달라는 요청.

## 조사
- 해당 버튼은 `src/views.rs`의 `filters()` 안에 `ui::primary(ui, "+ 새 메모")`로 하나만 존재한다
  (오늘의 할일/다음에 할일 페이지 상단). `catalog.rs`·`studio.rs`·`desktop.rs`·`schedule.rs`에 있는
  다른 "새 메모" 문구는 "+" 표시가 없는 별도 메뉴 항목(더보기 메뉴, 달력 메뉴 등)이라 이번 요청과
  무관하다고 보고 그대로 두었다.
- 버튼이 호출하는 `add_note(Some(date))`는 날짜가 지정된 새 메모를 만들고 곧바로 `open_note(i)`를
  불러, `self.editor = true`를 설정하고(메모편집창을 여는 상태) 스티커 창을 연다. `설정 ›
  항상 스티커로 열기`가 꺼져 있으면 편집창 형태로 열리고 켜져 있으면 스티커로 접힌다 — 이 동작은
  사용자의 기존 설정을 그대로 따르도록 바꾸지 않았다(이번 요청은 버튼 자체의 동작을 바꾸는 게
  아니라 이름을 바꾸는 것으로 해석).

## 가정 (명시)
- "메모편집창 열기"는 버튼을 눌렀을 때 이미 일어나고 있는 기존 동작(편집 상태로 전환)을 그대로
  유지하면 충족된다고 보고, 별도의 강제 "항상 편집창으로 열기" 로직은 추가하지 않았다. 사용자의
  "항상 스티커로 열기" 설정을 무시하고 이 버튼만 예외로 만드는 것이 의도라면 알려주시면 추가
  수정하겠다.
- 새로 생성되는 메모의 기본 제목("새 할 일")은 바꾸지 않았다. 버튼 이름만 바뀌는 것이고, 제목은
  즉시 편집 가능한 자리표시자이기 때문이다.

## 구현
- `src/views.rs`: `"+ 새 메모"` → `"+ 새 일정"` 문구만 변경.
- 새 테스트 `schedule_button_tests::new_schedule_button_creates_a_dated_note_and_opens_its_editor`
  — 버튼이 호출하는 `add_note`가 날짜 있는 메모를 만들고 편집기 상태(`self.editor`,
  `self.studio.windows`)를 실제로 여는지 회귀 확인.

  `cargo fmt --check` 통과.
