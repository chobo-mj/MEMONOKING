# 2026-11-13 스티커 더보기>정렬 메뉴 구조 재정비 (#58)

## 요청
"스티커 더보기>정렬 메뉴 구조 재정비" — 스티커의 "더보기 › 스티커 정렬" 서브메뉴 구조를
정리해달라는 요청.

## 조사
- `src/studio.rs`의 `sticker_menu(ui, i, w, own)`가 우클릭 메뉴(Context, `own = true`)와
  더보기의 스티커 정렬 서브메뉴(`SubMenu::Arrange`, `own = false`) 양쪽에 재사용되고 있었다.
- `own`은 맨 위의 "잠금 해제…"/"스티커로 펼치기" 행만 가렸고, 맨 아래의 "이 스티커 닫기"/
  "모든 스티커 닫기 Ctrl+Shift+H"는 `own` 값과 무관하게 항상 표시됐다. 그 결과 "더보기 › 스티커
  정렬" 서브메뉴를 열면 정렬 옵션 6개 아래에 **정렬과 무관한 닫기 명령 2개**가 또 붙어 있었다 —
  우클릭 메뉴에 이미 있는 항목이 엉뚱한 곳에 중복되는 구조였다.

## 구현
- `src/studio.rs`: 닫기 2개 버튼(과 그 앞 구분선)을 `if own { ... }`로 감싸, 서브메뉴
  (`own = false`)에서는 정렬 옵션만 남고 우클릭 메뉴(`own = true`)에서는 기존처럼 닫기 명령이
  그대로 보이게 했다.
- 새 테스트 `arrange_submenu_omits_the_close_actions_the_context_menu_still_has` — 실제 egui
  프레임을 렌더링해 우클릭 메뉴에는 "이 스티커 닫기"가 보이고, 더보기의 정렬 서브메뉴에는 보이지
  않으면서 정렬 옵션은 그대로 남아 있는지 확인.

## 가정 (명시)
- "구조 재정비"를 "정렬과 무관한 항목 제거"로 해석했다. 정렬 옵션 자체의 순서나 문구 변경, 추가
  정렬 옵션 신설은 요청에 없다고 보고 진행하지 않았다. 다른 재구성을 의도한 것이라면 알려주시면
  추가로 조정하겠다.

## 시험
- Linux: `cargo test` 128개 중 127 통과(윈도우 전용 글꼴 경로 테스트 1개는 기존 실패, 회귀 아님),
  `cargo clippy --all-targets` 경고 없음, `cargo fmt --check` 통과.
