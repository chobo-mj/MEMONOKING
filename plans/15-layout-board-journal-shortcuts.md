# 15. 일정 중심 레이아웃·메모 관계 보드·완료 업무일지·단축키

> 최신 범위: [23 프로젝트 단일 분류·아이콘 도구](23-projects-icon-toolbar.md)에 따라 라벨과 `LABEL-*` 계약은 폐기되었다. 이 문서의 라벨 모델·필터·시험은 과거 설계 참조이며 구현하지 않는다. 프로젝트와 메모 자체 색상, 위키/정리 폴더는 유지한다.

> v1.5 변경: 이 문서의 단일 부모 제한 및 parent_id 기반 종속 계약은 [17 복수 부모 DAG·위키](17-dag-board-wiki.md)로 교체한다. 기존 필드를 DAG 간선으로 이전하는 절차를 적용한다. 관리함의 최신 역할과 화면은 17/19를 따른다.

상태: 제품 계획 v1.4 추가 계약. 사용자 피드백(2026-11-08)에 따라 04·13·14의 화면 및 조회 계약을 확장한다. 기존 코드·폐쇄망 정책 조사를 먼저 수행한다는 원칙과 메모별 변경 이력 화면 제외는 유지한다. Rust 프로토타입은 실행 중 반응 검토용이며 영속 저장 구현을 뜻하지 않는다.

## 화면 역할과 이동

- 내 작업실: 날짜 제목 아래 시간순 메모·일정 목록. 오른쪽 캘린더를 열거나 닫는다. 캘린더를 닫아도 목록과 편집은 유지한다. 메모 상세는 제목을 눌러 열고 분리할 수 있다.
- 관리함: 할 일과 일정을 가까운 날짜·시간순으로 정렬한다. 일정 없는 항목은 별도 마지막 그룹. 연체는 날짜순으로 앞에 남기며 숨기지 않는다. 완료 체크·제목/본문/날짜/시간 편집·신규 추가를 제공한다.
- 오늘: 로컬 오늘 날짜의 항목. 다음: 내일부터 이후 항목. 날짜 경계가 바뀌면 갱신하며 연체는 관리함에서 확인할 수 있음을 안내한다.
- 수집함: 기존 빠른 메모 임시 수집 목적을 유지하면서 전체 메모 관계 정리 보드로 확장한다. 미정리 상태와 전체 메모 보기를 구분하고, 보드에서 숨겨도 원본은 삭제하지 않는다.
- 업무일지: 완료 메모 내용·수정 가능한 유효 완료 시각을 날짜별/월별로 조회한다. 기존 사용자 선택형 하루 초안 생성 기능과 함께 제공하되 자동 조회와 문서로 저장한 초안을 혼동하지 않는다.

## 아키텍처와 모델

공유 저장소 → 명령 처리 → 목록/보드/캘린더/업무일지 투영. 보드 편집 화면에 별도 메모 복사본을 저장하지 않는다.

- `BoardLayout(board_id, note_id, x, y, collapsed)`는 개인 보기 상태. 가상화·확대/축소·팬을 지원하는 제품 구현을 계획한다. 프로토타입은 스크롤 캔버스다.
- `RelatedNote(min_id,max_id)` 고유 제약; `Note.parent_id`는 순환 방지. 프로젝트는 `Project(id,name,archived_at)`와 `Note.project_id`로 시작하며 다중 프로젝트 필요 여부는 별도 확인한다. 프로젝트 이름 중복 정책/해체 시 메모 보존을 명시한다.
- `Note.is_important`와 사용자 라벨은 독립. 필터는 결과 ID만 바꾸며 선택 집합은 원본 ID로 유지한다.
- `Completion(effective_completed_at, checked_at, note_id / occurrence_id)`에서 체크 당시 시각과 사용자가 보정한 유효 완료 시각을 분리한다. 일지는 유효 완료 시각으로 조회한다. 수정 행위의 사용자용 버전 이력 화면은 만들지 않는다. 과거 완료 당시 본문 스냅샷이 필요한지는 현행 정책 조사 때 확정한다. 기본 조회는 현재 메모 내용이다.
- 반복 메모 완료는 발생 건 단위이며 템플릿 전체를 완료시키지 않는다. 반복 날짜 이동은 09의 원래 발생 ID·예외·시리즈 분할 계약을 따른다.
- `ShortcutBinding(action,chord,scope,enabled)` 및 등록 상태. Windows 메시지 루프와 등록 관리자의 스레드 수명 일치. 등록 성공 뒤 설정 확정, 실패 시 이전 바인딩 복구. 복구도 실패하면 성공으로 표시하지 않는다. 앱 종료 시 등록 해제.

## 상태기계와 명령

- 드래그: idle → dragging(note_id,origin) → valid_target(date) → commit / cancel. Escape·창 밖·잘못된 대상은 무변경. 일반 날짜 이동은 원자적 단일 명령. 반복 이동은 scope_pending → this_only / this_and_future → commit. 선택 취소 시 무변경.
- 종속: 선택/드래그 → 부모 후보 검사 → 순환/자기참조/보안 권한 검사 → 부모 변경. 실패는 기존 부모 유지. 관련 연결은 이 상태와 별도다.
- 완료: open → completed(checked_at=now,effective=now). completed → correction_pending → valid_correction / validation_error. 체크 해제는 open으로 복귀하며 자동 완료 조회에서 제외한다. 명시적으로 저장한 일지 문서는 자동 삭제하지 않는다.
- 단축키: editing → validating → registering → active / failed → rollback_active / rollback_failed. 충돌 실패 시 빈 상태를 성공으로 알리지 않는다.

## 단계·마이그레이션·보안

1. 기존 코드/보안/스키마/현재 단축키 조사. 작업 공간·관계·프로젝트·완료 의미를 확정.
2. 실행 중 UI 반응 프로토타입으로 이번 화면 구성·일반 날짜 드래그·카드 조작 검토.
3. 승인된 저장 구조에 프로젝트·보드 좌표·중요·완료 시각·키 바인딩 스키마 추가. 기본값으로 기존 메모 유지, 날짜/완료 시각을 추측해 채우지 않는다. 프로젝트 없는 기존 메모는 미분류, 보드 위치는 결정적 초기 배치.
4. 반복 예외·원자적 완료·일지 조회·undo/복구를 제품 명령에 연결. 체크된 기존 메모의 시각이 없으면 `완료 시각 미상`으로 두고 사용자가 보정하도록 한다.
5. 실제 폐쇄망 Windows에서 단축키 충돌·포커스 제한·배율·대용량·반입/복원 리허설 후 출시 판단.

전역 단축키는 키 입력을 기록하는 훅이 아닌 지정 조합 등록 방식을 사용한다. 사내 정책이 등록을 막으면 앱 내부 버튼으로 동일 기능에 접근한다. PDF/PPT/Excel 보안 락 우회, 화면/키 입력 수집, 외부 네트워크 호출은 추가하지 않는다. 인터넷 없이 실행하되 빌드 의존성은 승인된 반입·잠금 파일로 고정한다.
