# 24. 디자인 디테일·창 조작 안정화·0.2.0 시험 배포

2026-11-10 · 대상: **0.2.0 UI Preview** · 문서 성격: 최신 화면·조작 계약

최신 추가 디자인 자료와 사용자 지시를 반영한다. 원본 PPT·추출 이미지는 저장소나 설치파일에 포함하지 않는다. 이 문서는 레이아웃·상태·수용기준을 정의하며 최종 실행 결과는 `docs`의 QA 기록에서 관리한다. 설치파일이 빌드되었다는 사실과 UI/입력/다중 창 시험 통과를 구별한다.

## 1. 적용 순서와 보존 범위

최신 사용자 지시 → 이 문서 → [23 프로젝트·아이콘 도구](23-projects-icon-toolbar.md) → [22 PPT 15장 계약](22-ppt-requirements.md) → 21 및 이전 문서 순서로 적용한다. 이번 변경은 프로젝트 단일 분류, 복수 본문 탭, 메모 관계, 위키/전체메모 정리 폴더, 캘린더 드래그, 기간 발생별 완료, 댓글, 모아보기, 휴지통을 제거하는 요구가 아니다.

- 메모 분류는 프로젝트/프로젝트 없음이다. 폐기된 라벨·고정 분류는 다시 추가하지 않는다.
- **메모 편집폼에 폴더 선택 옵션을 두지 않는다.** 폴더 정리는 전체메모/위키의 기존 전용 화면에서 수행한다. 폴더 데이터와 분류 기능 자체는 유지한다.
- 완료 시각은 현재 선택된 메모/일정 발생이 완료된 때만 `완료 시간 :`와 함께 나타난다. 새 레이아웃 때문에 완료·중요·위키·알람 기능을 없애지 않는다.
- 앱 데이터는 실행 세션의 메모리 상태다. 저장·백업/복원·암호화·Windows 알림/트레이/자동실행은 실제 제품 단계의 후속 구현이다. 잠금은 화면 가림 시뮬레이션이며 보안 통제가 아니다.

## 3. 작업실 상세 목록

표를 한 행 안에 가로로 정렬한다. 행마다 카드 내부에서 텍스트가 다시 세로로 쌓이는 배치를 사용하지 않는다. 기본 열 구성은 다음과 같다. 수치는 현재 UI의 기준치이며 배율에 따라 물리 픽셀로 환산한다.

| 순서 | 열 | 기준 폭 | 동작 |
|---|---|---:|---|
| 1 | 표시 | 32 | 스티커 표시/숨기기. 휴지통에서는 복원 |
| 2 | 완료 | 32 | 해당 메모/날짜 발생 완료. 휴지통에서는 편집 비활성 |
| 3 | 제목 | 180 | 선택·편집 진입, 완료 취소선, 긴 제목 말줄임/툴팁 |
| 4 | 내용 | 240 | 본문 한 줄 요약·선택/편집, 잠금이면 내용 가림 |
| 5 | 알람 | 140 | 알람 아이콘과 날짜·시각, 클릭하여 달력/시간 선택 |
| 6 | 생성일 | 85 | yyMMdd, 생성시각 자체는 원본에 보존 |
| 7 | 일정 | 140 | MM/dd HH:mm, 클릭하여 일정 편집 |
| 8 | 삭제 | 32 | 휴지통 이동, 휴지통에서는 영구삭제 확인 |

열 폭 합계는 881 논리 픽셀이다. 부족한 가로폭은 **목록 영역 안의 가로 스크롤**로 처리하고 우측 미리보기까지 밀어내지 않는다. 표 헤더의 가로 이동량은 본문과 동기화한다. 행 선택 배경·행 구분선·날짜 구분은 열 정렬을 깨지 않으며, 생성일·알람·일정이 서로 다른 의미임을 헤더로 구별한다.

우측 미리보기는 넓은 창에서 약 300 논리 픽셀을 확보한다. 좁은 화면에서는 약 250까지 조정할 수 있으나 제목·본문·탭·도구에 계속 접근해야 한다. 방향키는 목록에 있을 때 행을 선택하고, 본문에 초점이 있으면 커서를 이동한다. 선택 변경·필터·삭제 후 사라진 인덱스가 다른 메모를 뜻하지 않게 안정 ID를 사용한다.

전체메모 상세 보기와 휴지통의 동일한 표 표현은 공통 행/열 계약을 사용한다. 휴지통의 삭제 본문 탭은 메모와 구별하고 소유 메모·탭 제목·복원 대상을 유지한다. 관계 보드와 위키 폴더는 이 표로 강제 대체하지 않는다.

## 4. 메모 편집창과 스티커

전체 편집창의 본문 위에는 제목, 시작/종료 날짜·시간, 프로젝트 선택을 중심으로 배치한다. 정기 여부·중요·완료·위키·알람 등 기존 업무 동작은 해당 아이콘/더보기/조건부 조작으로 유지한다. 생성일을 새 할 일 입력폼에서 직접 수정하는 칸과 폴더 선택 칸은 만들지 않는다. 완료 시각은 완료된 항목에서만 표시한다.

메모 창을 상단 헤더·제목/속성·스크롤 본문·고정 하단으로 구분한다. 탭과 서식 아이콘은 본문 스크롤 영역 밖에 둔다. 탭은 본문 바로 아래, 도구는 창 맨 아래이며 작은 창에서는 도구만 필요한 만큼 줄을 바꾼다. 탭 추가·이름 변경·숨김·복원·삭제 기능을 유지하고 툴바가 숨겨져도 탭/+는 사라지지 않는다. 비편집 스티커는 도구 영역을 줄이고 탭이 창 최하단에 놓이게 한다.

스티커의 상단 +, 압정·완료·접기·닫기·더보기는 동일 원본의 조작이다. 최대화/복원 버튼을 제공하고 닫기는 창만 닫는다. 도움말은 더보기 안에 두며 사용하지 않는 별도 상단 도움말 아이콘은 추가하지 않는다. 본문 글꼴·배율·서식·이미지/표·탭을 편집하는 동안 상단/하단 조작 위치가 내용 길이에 따라 떠다니지 않는다.

기본 접기 순서는 스티커→제목 한 줄→색상 상자, 설정으로 제목 단계를 건너뛸 수 있다. 색상 상자는 더블클릭으로 스티커를 복원한다. 제목 한 줄/상자의 이동·모서리 조작과 클릭 복원을 구별하고 마지막 정상 스티커 크기를 보존한다. 잠긴 상자는 크기 변경을 금지하고 내용/미리보기/댓글을 가린다. 모든 창에 개별 비밀번호 입력이 있다는 사실을 실제 암호화 보호로 표현하지 않는다.

## 5. 창 떨림 방지 계약

Windows 창의 관측 크기와 요청 크기를 분리한다. `ViewportInfo.inner_rect`는 복원용 기록이며 매 프레임 `ViewportBuilder.with_inner_size`로 되돌려 보내지 않는다. Windows의 비동기 크기 변경에 이전 관측 크기를 계속 재요청하면 드래그와 경쟁할 수 있기 때문이다.

- 생성할 때만 초기 크기를 제공한다. 모드·잠금 상태가 바뀔 때 최소/최대/조절 가능 여부와 목적 크기를 한 번 적용한다. 같은 모드의 일반 프레임에는 크기 요청을 보내지 않는다.
- 모서리/변에서 크기 변경을 시작하면 `ViewportCommand::BeginResize(ResizeDirection)`를 한 번 보낸다. 헤더 이동은 `StartDrag`를 한 번 보내고 이후 움직임은 Windows에 맡긴다.
- 실시간 PointerMoved마다 OuterPosition·InnerSize를 함께 계산하는 경로를 사용하지 않는다. 현재 outer 위치와 이전 로컬 포인터 이벤트를 더해 누적 이동량을 만드는 피드백을 제거한다.
- 최대화 중에는 관측 크기로 일반 모드의 마지막 크기를 덮어쓰지 않는다. 접기·잠금·모드 변경 시 대기 중인 이동/정사각형 상태를 취소한다.
- Shift 정사각형은 네이티브 크기 변경 중에는 개입하지 않는다. 종료·해제 후 관측 bounds가 안정된 다음 24~360 범위의 정사각형으로 **한 번만** 보정하고 대기 상태를 지운다. 반대 모서리는 고정한다. 이어지는 프레임마다 같은 보정을 반복하지 않는다.

단위시험의 ‘지속 크기 명령 없음’만으로 실제 떨림이 사라졌다고 판정하지 않는다. 실제 Windows에서 모서리·변·좌상단·보조 모니터·배율 변경을 시험하고 결과를 QA 기록에 남긴다. OS 네이티브 조작을 사용한다는 것은 저장/알림/보안 기능을 OS와 연동했다는 의미가 아니다.

예상 결함은 표 헤더/본문 스크롤 오프셋 불일치, 우측 300폭 때문에 좁은 창 전체가 밀림, 고정 푸터가 본문 높이를 중복 차감, 비편집 도구 빈 공간 잔존, 첫 탭 삭제 후 legacy 본문 부활, 최대화 크기 덮어쓰기, 지속 builder 크기 피드백, 정사각형 대기 상태 잔존, 네이티브 조작 종료 뒤 이전 클릭이 복원으로 처리되는 경우다. 공통 레이아웃 계산·안정 ID·본문/푸터 경계·전환 명령 단발성·실제 포인터 회귀로 검증한다.

## 7. 사전 배포와 제품 단계 경계

예정 버전은 0.2.0, 태그는 `v0.2.0-ui-preview`다. [패키징 안내](../packaging/README.md)의 Windows x64 설치형·포터블·SHA256 자동 산출 절차를 따른다. 설치형은 관리자 권한 없이 현재 사용자 `%LOCALAPPDATA%\Programs\MEMONOKING`에 설치하고 시작 메뉴 바로가기, 선택적 바탕화면 바로가기, 제거 기능을 제공한다. 포터블에는 실행파일·사용 안내·체크섬만 배치한다.

GitHub CI에서 테스트·정적 CRT 의존성·설치/제거 검사를 통과한 뒤 사전 배포한다. 산출물 링크와 CI/QA 결과가 확인되기 전에는 배포 완료로 기록하지 않는다. 실행 PC에 빌드 도구를 요구하지 않고 런타임 다운로드·자동실행 등록·네트워크/보안 설정 변경을 설치 과정에 넣지 않는다.

앱 종료 시 메모/탭/설정/창 위치가 초기화되는 UI 시험 범위는 그대로다. 명시적 이미지 내보내기는 실제 파일을 만들지만 앱 데이터 저장과는 구별한다. 실사용 제품의 영속 저장·복구·백업·암호화·알림·정기 발생 계산·완전한 한국 공휴일 자료와 사내 승인 검증은 기존 제품 계획에서 후속으로 유지한다.
