# 05. 검색·본문 이미지·하이퍼링크·표 모아보기

> 최신 범위: [23 프로젝트 단일 분류·아이콘 도구](23-projects-icon-toolbar.md)에 따라 라벨과 `LABEL-*` 계약은 폐기되었다. 이 문서의 라벨 모델·필터·시험은 과거 설계 참조이며 구현하지 않는다. 프로젝트와 메모 자체 색상, 위키/정리 폴더는 유지한다.

> 문서 상태: 기존 코드 분석 전의 상세 설계안. 특정 언어, UI 프레임워크, 데이터베이스 또는 검색엔진 도입을 확정하지 않는다. 우선 기존 편집기·저장소·파일 권한·보안 프로그램의 허용 범위를 조사하고 본 계획을 조정한다.

상위 계획: [plan.md](../plan.md). 공통 필드·상태의 기준은 [02 데이터 모델](02-data-states.md), 성능·통합 시험의 기준은 [08 수용기준](08-tests-acceptance.md)이다.

## 1. 목표와 범위

- 메모 제목·본문·링크 표시문구·링크 주소를 앱 안에서 검색한다.
- 본문의 표 셀 텍스트·캡션도 검색하고 이미지/링크/표 모아보기에서 사용 위치를 확인하여 해당 메모의 원래 위치로 이동한다.
- 네트워크 없이 작동하며, 검색 결과와 미리보기가 사내 보안 정책을 벗어난 내용을 추출하거나 복제하지 않는다.
- PDF/PPT/Excel 파일 자체의 내용 검색·썸네일·변환·OCR·외부 앱 실행은 기본 범위에서 제외한다. 허용된 클립보드에서 붙여넣은 표의 셀 검색과 파일 내용 추출은 구별한다. 별도의 파일 연동은 승인된 가능성을 확인한 뒤 독립 요구사항으로 다룬다.
- 이미지 OCR, URL 대상 페이지 크롤링, 웹 제목/파비콘/미리보기 가져오기, AI 검색은 기본 기능에 포함하지 않는다.

### 2.1 검색 UI의 구체적인 흐름

1. 검색창에 입력하면 입력 조합이 끝난 뒤 짧은 지연으로 검색한다. 한글 IME 조합 중 Enter를 결과 열기로 해석하지 않는다.
2. 결과에는 제목, 경로, 일정, 완료 표시, 짧은 일치 문맥을 표시한다. 날짜 필터는 생성일·수정일·일정 중 무엇을 기준으로 하는지 명확히 구분한다.
3. 결과 클릭은 현재 선택한 앱의 편집 영역으로 이동한다. 별도 창으로 열기는 별도 명령으로 제공한다.
4. 접힌 상위 메모가 있으면 원본 이동에 필요한 가지를 일시적으로 펼친다. 검색을 끝냈을 때 기존 접힘 상태를 복구할지는 사용성 검증 후 결정한다.
5. 이미 열린 메모가 다른 창에서 수정되면 결과는 최신 revision으로 갱신한다. 이동 대상 블록이 삭제되었으면 메모 상단을 열고 “해당 위치가 변경됨”을 표시한다.
6. 검색 실패를 “검색 결과 없음”으로 보여주지 않는다. 색인 준비/오류 상태와 0건 결과를 구분한다.

### 2.2 필터·정렬의 의미

- 기본 정렬: 제목 일치 우선 → 수정시각 내림차순 → 안정적인 ID 순서. 임의의 검색 점수 도입은 한국어 품질 검증 이후에 한다.
- 입력은 기본적으로 문자 그대로 처리한다. `%`, `_`, 따옴표, 대괄호, `*`가 의도치 않게 와일드카드나 검색 연산자가 되지 않게 한다.
- 공백으로 나눈 검색어를 모두 포함하는 단순 AND 검색을 기본안으로 한다. 정확한 문구 검색 등 고급 문법은 실제 필요가 확인된 뒤 추가한다.
- 제목·본문·URL 중 검색 대상을 선택할 수 있도록 한다. 이미지 파일명은 별도 필터이며 이미지 속 글자를 검색하는 기능이 아니다.
- “선택한 메모 아래 검색”은 그 메모를 포함한 모든 후손에 적용한다. 무제한 논리 깊이에서 재귀 호출로 검색 범위를 계산하지 않는다.
- 일정 기간 검색은 일정을 가진 메모에만 적용한다. 종일 일정은 날짜 구간, 시간 일정은 선택한 시간대의 일 범위와 교차하는지를 검사한다.
- 완료 필터는 메모 자체 상태를 기준으로 한다. 상위 메모의 완료 상태를 자식에게 추정 적용하지 않는다.
- 라벨 여러 개 선택은 기본 ‘하나라도(any)’, 선택 옵션 ‘모두(all)’로 제공한다. 라벨 없음은 별도 필터다. 검색·트리·목록·캘린더에 같은 필터를 적용하고 현재 조건을 표시한다. 숨겨진 결과의 부모는 경로 안내용으로만 노출하고 일치 개수에 넣지 않는다.
- 반복 일정 기간 필터는 규칙 anchor만 비교하지 않고 예외가 반영된 실제 회차 중 범위와 겹치는 것이 있는지 확인한다. 월 밖에서 임시 이동해 들어온 건을 포함하고 이동해 나간 원래 슬롯은 제외한다. 검색 결과는 메모당 1행이며 일치 회차 목록은 세부로 제공한다.
- 메모 검색의 완료 필터는 Note 전체 상태, 캘린더 완료 필터는 회차 상태라는 차이를 문구로 표시한다. 반복 미완료 회차가 남아 있으면 하나 완료했다는 이유로 원본 메모를 완료 필터로 보내지 않는다.
- 라벨·본문 링크·가져온 즐겨찾기는 다른 데이터다. 즐겨찾기 검색은 별도 탭/영역에서 제목·URL·폴더를 대상으로 수행하며, 가져오기만으로 본문 링크 모아보기 항목을 생성하지 않는다. 상세는 [09](09-recurring-schedules.md)·[10](10-bookmarks-labels.md)을 따른다.
- 표 셀은 원점 셀을 행·열 순으로 한 번씩 추출하고 셀 경계·문단 경계와 원문 매핑을 유지한다. 병합으로 덮인 좌표에 같은 텍스트를 복제하거나 이웃 셀을 붙여 거짓 문자열 일치를 만들지 않는다. 검색 결과는 table_id/cell_id/paragraph_id로 이동한다.
- 구조화 기호·들여쓰기의 가상 공백은 본문 텍스트와 분리한다. 기본 검색 대상은 실제 셀/문단 텍스트이며 자동 표시 번호만 변경해도 없는 단어가 추가되거나 원문 강조 오프셋이 밀리지 않아야 한다. 일반 텍스트로 저장된 기존 번호·공백은 그대로 검색한다.

### 2.3 저장 보기·수집·체크·업무일지 연결

[13](13-capture-views-checklists.md)의 저장 보기는 현재 조건의 결과 ID가 아니라 허용 AST·정렬·상대 날짜 정의다. 명시 저장/업데이트 없이 화면 필터를 저장 정의에 덮지 않는다. 같은 조회의 기준일·시간대·조건 revision을 목록/개수/캘린더에 공유하고 무효 참조는 수정 필요 상태로 표시한다. 10의 일시적 라벨 필터 복구 동작과 이름 있는 SavedView의 무효 조건 처리를 구별한다.

수집함·네 가지 진행 상태·체크 유무/미체크 조건을 라벨/완료/기간과 결합한다. 기본 메모 검색은 Note의 현재 상태·본문 체크 템플릿 텍스트를 검색한다. 반복 체크/상태 조회는 선택 기간의 유한 정규 회차와 해당 snapshot/state를 사용하며 원본 전체 메모 상태와 혼동하지 않는다. 항목 원문은 check_item_id/paragraph_id로 연결하고 체크 상태만 바뀌었다고 본문 텍스트를 새 문자열로 덧붙이지 않는다.

업무일지는 현재 화면 필터와 별도 날짜/범위 선택을 사용한다. [14](14-status-overlap-journal.md)의 후보 갱신은 사용자 편집 초안을 덮지 않는다. 저장된 일지는 source_kind=journal인 일반 Note로 검색할 수 있으나 일지 후보 원천에서는 제외한다. 메모별 변경 이력 조회·과거 본문 검색 화면은 이번 범위에 없다.

## 3. 데이터와 모듈 경계

### 3.1 원본과 파생 데이터 구분

| 데이터 | 역할 | 복구 방법 |
|---|---|---|
| `Note.body_doc` | 본문 원본; 안정적인 블록/인라인 참조 ID 포함 | 주 저장소·백업에서 복구 |
| `Note.revision` | 낙관적 동시성 제어·색인 버전 | 원본 저장 트랜잭션에서 증가 |
| `Asset` + 실제 승인된 이미지 파일 | 이미지 원본 및 보안 메타데이터 | 일관된 백업에서 복구 |
| `BodyPlainText` | 본문에서 안전하게 추출한 검색용 텍스트 | body_doc에서 재생성 |
| `ImageUsageIndex` | note_id/block_id/reference_id/asset_id 참조 목록 | body_doc에서 재생성 |
| `LinkUsageIndex` | 주소·표시문구·메모/블록 위치 목록 | body_doc에서 재생성 |
| `TableUsageIndex` | note_id/table_id/안정 anchor·캡션·행열·발췌·indexed_note_revision | body_doc 표에서 재생성 |
| `SearchIndex` | 검색 가속용 구조 | 원본에서 재생성 |
| `ThumbnailCache` | 허용된 이미지의 축소본 | 원본 이미지에서 재생성 |

본문이 권위 있는 이미지·링크·표 사용 위치다. 모아보기 목록에서 항목을 지우는 동작은 그 항목이 사용된 본문 위치를 보여주고 삭제 명령을 실행해야 한다. 색인 레코드만 지워서 본문과 다른 상태를 만들지 않는다. 셀 내부 이미지·링크도 같은 추출기를 거쳐 기존 모아보기에 포함한다.

### 3.2 제안 레코드

```text
Asset
  id: stable opaque identifier
  mime_type, byte_length, pixel_width, pixel_height
  storage_relative_path: application storage 아래의 상대 경로
  content_hash: 무결성/중복 검사용; 접근 권한이나 전자서명이 아님
  created_at_utc
  policy_metadata: 정책 판단·근거·버전·확인시각
  state: staged | ready | quarantined | pending_delete

Asset 확장 메타데이터 후보
  original_name
  import_source_kind: file | clipboard | migration
  policy_metadata.decision: allowed | blocked | unknown
  policy_metadata.policy_version, policy_metadata.checked_at_utc
  integrity_status: valid | missing | corrupted | unchecked

IndexState
  index_schema_version, normalization_version
  note_id, indexed_note_revision, dirty_since_utc, last_error_code

ImageUsageIndex / LinkUsageIndex
  note_id, note_revision, block_id, reference_id
  asset_id 또는 address_raw/display_text/address_kind
```

- 저장 경로는 사용자가 입력한 원래 파일명이나 메모 제목으로 직접 만들지 않는다. 원래 이름은 표시 메타데이터로만 보존한다.
- `Asset` 필드명과 `state`는 02의 계약을 따른다. 확장 메타데이터는 기존 저장소와 정책을 확인한 뒤 추가하며, 파일 누락(`integrity_status=missing`)은 자산 수명주기와 분리한 검사 결과다.
- 관리 경로를 해석할 때 저장소 밖으로의 이탈, 심볼릭 링크/재분석 지점, 절대 경로, UNC 경로를 차단하거나 정책으로 별도 승인한다.
- 링크 원문은 보존한다. 검색용 정규화 값과 실제 열기 주소를 분리하여 쿼리 문자열·대소문자 등을 무리하게 변환하지 않는다.
- 내부 메모 링크는 앱의 note_id 참조로 관리한다. 표시용 제목 변경이 관계를 끊지 않게 한다.
- 파생 데이터도 원문 내용을 포함할 수 있으므로 원본과 같은 접근 권한·보관 정책을 적용한다.

### 3.3 검색 모듈 계약

```text
Search(query, filters, sort, page_cursor, cancellation_token)
  -> results(note_id, revision, match_locations, excerpt),
     index_status, next_cursor, query_generation

ExtractReferences(note_id, body_doc, revision)
  -> plaintext_with_source_mapping, image_refs, link_refs, table_refs

RebuildDerivedData(scope, expected_source_version)
  -> progress, errors, completed_source_version
```

UI는 검색 결과 generation이 현재 요청과 같은지 검사한다. 느린 이전 검색 결과가 최신 입력 결과를 덮어쓰지 못하게 한다. 페이지 커서는 정렬키·필터 지문·색인 generation을 포함하고, 무효화되면 첫 페이지를 다시 읽도록 안내한다.

## 4. 한국어 검색 구현 계획

1. 기존 검색 구현을 분석한다. 한국어 지원, HTML 원문 검색 여부, 개인정보가 로그에 남는지, 대용량 메모 성능을 측정한다.
2. 1차 구현은 제목과 정제된 본문에 대한 부분문자열 검색으로 기준 결과를 만든다. 한글 초성 검색은 별도 선택 기능이며 기본 정확성 조건과 혼합하지 않는다.
3. 비교용 텍스트는 Unicode NFC, 줄바꿈 통일, 정책으로 정의한 공백 처리, 영문 대소문자 비교 규칙을 사용한다. 원본 body_doc는 변경하지 않는다.
4. 정규화 문자열과 원문 위치의 매핑을 보존하여 강조 범위가 틀어지지 않게 한다. 이모지·결합문자에서 UTF-16 코드 단위와 사용자 인식 문자를 혼동하지 않는다.
5. 데이터 크기와 실측 결과가 필요할 때만 FTS·trigram 등의 후보를 비교한다. 검색엔진이 한국어를 지원한다는 설명만으로 도입하지 않는다.
6. 채택한 가속 검색 결과는 기준 부분문자열 검색과 비교한다. 한글 띄어쓰기·조사·복합어·URL·숫자·영문 혼합의 누락을 기록한다.
7. 대용량에서 모든 본문을 매 입력마다 메모리로 복사하지 않도록 배치·페이지 처리를 한다. 취소와 창 닫기에 즉시 반응해야 한다.

## 5. 본문 이미지 삽입과 수명주기

### 5.1 입력 처리

1. 파일 또는 클립보드 입력의 형식·크기·권한·정책을 먼저 확인한다. 클립보드 HTML에 원격 이미지 URL이 있으면 다운로드하지 않는다.
2. 초기 허용 후보는 승인된 정적 PNG/JPEG 등으로 제한한다. SVG/HTML은 활성 콘텐츠와 외부 참조 위험이 있어 기본 제외한다. 실제 형식은 파일 확장자만 믿지 않고 확인한다.
3. 압축된 파일 바이트 한도와 디코딩 후 픽셀 수·메모리 한도를 각각 둔다. 초기 제안값은 파일당 20 MiB, 4천만 픽셀이며 보안/실기기 검증에서 확정한다.
4. `staged` 영역에 스트리밍 복사하고 디코딩·해시·정책 검사를 수행한다. 검사 실패 시 원본 파일을 변경하지 않고 staging만 안전하게 정리한다.
5. 검증된 파일을 관리 저장소에 확정한 뒤 본문 참조를 커밋한다. 파일과 DB가 하나의 트랜잭션이 아닐 때는 복구 저널로 중단 지점을 기록한다.
6. 본문 저장 실패 시 orphan 후보가 남을 수 있으므로 유예 기간 후 정리한다. 실패한 삽입을 성공으로 표시하지 않는다.
7. 썸네일 생성은 백그라운드에서 수행한다. 썸네일 실패가 메모 전체 저장 실패가 되지 않도록 한다.

### 5.2 상태기계

```text
입력 → staged → 검증 성공 → ready
              ├─ 정책 차단 → quarantined 또는 staging 폐기
              └─ 형식/용량 실패 → staging 폐기 + 이유 표시

ready → 파일 검증 실패 → integrity_status=missing/corrupted 또는 quarantined
ready → 마지막 본문 참조 제거 → pending_delete
pending_delete → 복구/참조 재생성 + 파일 검증 성공 → ready
pending_delete → 휴지통·실행취소·백업 보관 정책 충족 → 파일 제거
```

- `integrity_status=missing`은 “파일을 찾을 수 없음”, `state=quarantined`는 “정책상 표시할 수 없음”으로 구분한다. 누락을 발견하면 해당 자산의 신규 영속 참조 저장을 중단하고, 기존 본문은 원본을 유지한 채 깨진 참조를 대체 표시한다.
- 해시가 같아도 권한 범위가 다른 이미지는 무조건 병합하지 않는다. 중복 제거 도입은 권한·백업·참조 계산 검증 후 결정한다.
- 삭제 여부 판단에는 활성 메모, 휴지통, 실행취소·초안·백업 및 회차 체크 운영 snapshot의 자산 참조 보존 정책을 포함한다. 본문 편집 한 번으로 실제 파일을 즉시 지우지 않는다. 메모별 본문 버전 이력 기능을 추가한다는 의미는 아니다.
- 사용자가 “본문에서 제거”와 “모든 사용 위치에서 제거”를 혼동하지 않도록 현재 사용 위치와 영향 개수를 표시한다.
- 회전(EXIF orientation), 투명 배경, 색공간, 고해상도 확대를 검증한다. 메타데이터 제거/재인코딩도 새로운 복제물 생성이므로 조직 정책 허용 범위를 확인한다.

## 6. 하이퍼링크 모아보기와 열기 정책

- 목록 항목은 표시문구, 실제 주소, 내부/외부 구분, 사용 메모, 열기 허용 상태로 구성한다.
- 동일 URL을 묶어 보여줄 수 있지만 원래 모든 사용 위치와 표시문구는 보존한다. “사용 메모 3개 / 사용 위치 5개”를 구분한다.
- 외부 URL은 저장만 가능하게 하고 실행은 정책상 허용된 프로토콜·대상에 한정한다. 폐쇄망이라도 내부 주소에 임의 요청을 보내지 않는다.
- `javascript:`, `data:`, 임의 실행 프로토콜, 인증정보 포함 URL 등은 실행을 거부하고 안전한 문자열로 보여준다.
- `file:`/UNC/네트워크 드라이브는 사내 보안 정책 확인 전 비활성화한다. 파일 존재 확인 자체가 네트워크 접근이 될 수 있으므로 목록 로딩 때 검사하지 않는다.
- 링크 제목·파비콘·OG 이미지·리다이렉트 확인을 위해 백그라운드 통신하지 않는다. 실제 열기 작업은 사용자 행동과 정책 검사를 모두 거친다.
- PDF/PPT/Excel을 가리키는 링크는 제목·주소 기록만 가능하다. 외부 프로그램 실행 차단을 다른 뷰어, 변환, 캡처로 우회하지 않는다.
- 내부 메모가 휴지통으로 이동하면 삭제된 대상임을 표시하고 복구 또는 관계 제거를 제공한다. 동일 제목의 다른 메모로 자동 재연결하지 않는다.

## 7. 색인 상태기계와 오류 복구

### 7.1 표 모아보기 연결

표 모아보기는 [11](11-tables-collection.md)의 TABLE-04~06을 구현한다. 표 제목·원본 메모·라벨·행/열 수·일부 셀 발췌·원본 열기를 제공하고 표 없는 메모는 제외한다. 기본 휴지통 제외, 라벨/본문검색/기간 필터는 기존 의미를 유지한다. 표 1개가 반복 일정의 20회차에 사용되어도 표 목록은 원본 Note+table_id당 1개이며 이미지로 붙인 표는 이미지 목록에만 보인다.

미리보기는 최신 본문에서 안전하게 읽는 작은 투영이며 편집 원본이 아니다. 행/열 삽입·이동·표 삭제/복원·실행취소·다중 창 저장 뒤 indexed_note_revision을 대조한다. 원래 표가 없으면 변경/삭제 안내를 보이고 배열 위치가 같은 다른 표를 열지 않는다. 색인 재생성은 표·셀의 안정 ID를 원본에서 읽고 새로운 표 ID를 발급하지 않는다.

```text
clean(revision=N)
  → 원본 저장 N+1 → dirty
  → worker claim → rebuilding(N+1)
  → 원본 revision 재확인 + 색인 원자 교체 → clean(N+1)
  → 그 사이 N+2 저장 → dirty(N+2), 더 오래된 결과로 덮어쓰기 금지

rebuilding → 실패 → retry_wait → 재시도
반복 실패 → degraded: 원본은 보존, 제목/안전한 직접검색 또는 복구 메뉴 제공
```

- 원본 저장과 dirty 표시를 같은 트랜잭션으로 처리하거나, 동등한 내구성 있는 변경 큐를 사용한다.
- 전체 색인 재구축은 새 generation에 작성하고 성공한 뒤 전환한다. 실패 중인 미완성 색인을 정상 상태로 공개하지 않는다.
- 앱 재시작 시 색인 버전·원본 revision·중단 작업을 검사한다. 단순히 마지막 종료 시간이 정상이라는 이유로 색인을 신뢰하지 않는다.
- 삭제된 메모와 이미지 참조는 색인에서도 제거한다. 휴지통 노출 여부는 필터에 따라 달라야 한다.
- 파생 데이터의 손상이 원본 복구나 파일 삭제의 근거가 되어서는 안 된다.

## 9. 예상 버그와 예방책

| 예상 버그 | 원인 | 예방·탐지 |
|---|---|---|
| 본문에 없는 검색 결과가 계속 남음 | 수정 시 dirty 기록 누락 | 원본 저장과 변경 큐 내구성 결합, revision 대조 |
| 한글 강조가 한 글자씩 밀림 | 정규화 전후 오프셋 혼동 | 원문 매핑과 IME/결합문자 픽스처 |
| 갤러리를 열자 이미지 원본이 전부 메모리에 올라감 | 가상화·지연 읽기 누락 | 작은 썸네일·페이지 읽기·메모리 계측 |
| 한 이미지를 삭제했는데 다른 메모도 깨짐 | 참조 수만 단순 차감 | 실제 참조 재검증, GC 유예, 공유참조 테스트 |
| 검색 로그로 업무 내용 노출 | 디버그 기록에 원문 포함 | ID·지연·오류코드만 기록, 로그 점검 |
| 링크 목록 보기에서 사내 서버 접속 | 파비콘/존재 검사 | 자동 fetch 경로 제거·네트워크 관측 시험 |
| 본문 링크 클릭과 편집 커서 충돌 | 선택/열기 제스처 불명확 | 편집 중 명시적 열기 동작, 키보드 접근 제공 |
| 잘못된 파일명이 저장소 밖을 덮어씀 | 원래 이름을 경로로 사용 | 불투명 asset_id 경로, 경로 정규화·이탈 검사 |

## 10. 개발 순서와 완료 증거

1. 기존 코드 조사: 검색·편집기 직렬화·이미지 저장·링크 실행·보안 차단 동작을 표로 남긴다.
2. 참조 추출과 기준 검색을 읽기 전용으로 구현하고 기존 데이터와 비교한다.
3. 원본 revision·dirty 큐·재구축을 구현한다. 오류 주입 시험 후 UI에 연결한다.
4. 이미지 staged 가져오기·본문 참조·GC 복구를 구현한 뒤 모아보기를 추가한다.
5. 링크 목록과 정책 검사·명시적 열기를 구현한다.
6. 성능·네트워크 무접속·다중 창·접근성 시험 결과와 남은 제한을 릴리스 기록에 첨부한다.

완료 산출물: 기준 검색 픽스처, 원본/파생 데이터 스키마 문서, 색인 재구축 절차, 이미지 중단 복구 보고서, 링크 정책표, 기준 PC 성능 결과, 차단된 동작 설명문.
