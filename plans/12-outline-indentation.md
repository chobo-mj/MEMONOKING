# 12. 문단 기호·자동 번호·2칸 들여쓰기 개발 계획

> 최신 범위: [23 프로젝트 단일 분류·아이콘 도구](23-projects-icon-toolbar.md)에 따라 라벨과 `LABEL-*` 계약은 폐기되었다. 이 문서의 라벨 모델·필터·시험은 과거 설계 참조이며 구현하지 않는다. 프로젝트와 메모 자체 색상, 위키/정리 폴더는 유지한다.

상위 계획: [plan.md](../plan.md) · 공통 모델: [02](02-data-states.md) · 메모 편집: [03](03-notes-tree-relations.md) · 표: [11](11-tables-collection.md) · 통합 시험: [08](08-tests-acceptance.md)

문서 상태: 사용자 추가 요구와 확인 답변을 반영한 핵심 범위(P1) 설계안. **Enter는 같은 들여쓰기 단계에서 다음 번호·기호를 이어 쓴다.** 매번 하위 단계로 들어가는 동작이 아니다. 기존 편집기·본문 형식·한글 입력·키 이벤트를 먼저 조사하고 실제 구현 방식과 라이브러리는 이후 선택한다.

v1.3 체크리스트 확장은 [13](13-capture-views-checklists.md)의 CheckItem이 체크 표시를 소유하고 내부 Paragraph.outline은 level만 재사용한다. marker_family=none으로 숫자/불릿과 체크박스를 동시에 만들지 않는다. 체크 항목 Enter는 같은 단계의 새 미체크 항목, 일반 번호 문단 Enter는 같은 단계의 다음 번호다. 명시 종류 변환 없이 타이핑 하나가 두 종류를 동시에 생성하지 않게 한다. 표 셀 Tab/Shift+Tab 우선·IME·본문 Space 보존 규칙은 그대로 적용한다.

## 1. 사용자가 기대하는 동작

- 문단 시작에서 `1.`, `i)`, `(i)`, `A)`, `a)`, `ㄱ)`, `가)`, `(1)`, `(I)`, `-`, `*` 같은 기호와 구분 공백을 입력하면 목록 문단으로 인식한다.
- 새 기호를 수동 입력할 때 기본 들여쓰기는 직전 관련 문단보다 2칸 깊다. 다만 활성 상위 목록의 다음 번호를 명시한 경우 그 목록의 수준에 맞춘다.
- 내용이 있는 목록 문단에서 Enter를 누르면 같은 수준의 다음 기호가 생성된다. 예: `1. → 2.`, `a) → b)`, `i) → ii)`, `ㄱ) → ㄴ)`, `가) → 나)`. `-`, `*`는 같은 기호를 이어 쓴다.
- Shift+Tab은 2칸 내어쓰기, Tab은 2칸 들여쓰기다. 내어쓰기는 0칸 아래로 내려가지 않는다.
- `1.` 아래에 `a)`가 있고 그다음 줄에서 `2.`를 명시하면 `1.`과 같은 수준으로 맞춘다. 자동 생성된 `b)` 뒤에 `2.`를 붙여 `b)2.`로 만들지 않는다.
- 문단 들여쓰기는 본문 서식이다. 메모의 부모·자식 트리, 관련 메모, 라벨, 일정은 바뀌지 않는다.

## 3. 2칸과 수준의 정의

`level`은 0 이상의 정수이며 시각적 들여쓰기는 `level × 2칸`이다. 1칸은 문단의 유효 글꼴에서 공백 U+0020 한 개에 해당하는 기준 폭으로 정의한다. 글꼴·배율을 바꾸어도 논리 수준은 바뀌지 않는다. 구현 방식은 편집기 paragraph margin/indent 등 조사 후 정하되 숫자와 공백을 여러 번 본문에 추가해서 위치를 맞추지 않는다.

표시는 기호 시작 위치와 본문 시작 위치를 구별한다. 두 줄 이상으로 줄바꿈된 항목은 본문 시작에 맞추는 내어쓰기(hanging indent)를 적용하여 두 번째 줄이 기호 밑으로 돌아가지 않게 한다. 기호 폭이 `9.`에서 `10.`으로 커져도 level을 바꾸지 않는다. 마커·본문 간 최소 간격과 긴 기호의 처리 폭은 공통 렌더링 규칙으로 정한다.

기본 일반 문단 level=0 다음에 첫 `1. `를 입력하면 level=1, 즉 2칸이다. 직전 문단이 없으면 기준 수준은 0이다. 이전 일반 문단이 사용자의 수동 들여쓰기 level=2라면 새 목록의 기본은 level=3이다. 상위 계열 복귀 규칙이 유효하면 그 규칙이 기본 증가보다 우선한다.

본문의 논리 level과 원래 입력된 리터럴 공백은 다르다. 기존 텍스트·코드·붙여넣기에 들어 있는 선행 공백을 자동 제거하거나 구조 수준으로 추정하지 않는다. 일반 텍스트로 복사할 때만 구조 수준을 2개의 U+0020씩 직렬화하고 원래 본문 공백은 따로 보존한다. 재붙여넣기에서 이를 또 들여써 두 배로 만들지 않도록 구조 클립보드와 순수 텍스트를 구분한다.

## 4. 지원 기호와 계열 구분

### 4.1 기호 표

| 입력 예 | 계열의 일부 | 다음 기호 | 유의점 |
|---|---|---|---|
| `1.` | decimal + dot | `2.` | `(1)`과 다른 계열 |
| `(1)` | decimal + enclosing parentheses | `(2)` | 괄호 양쪽 모두 있어야 함 |
| `a)` | lower alphabet + right parenthesis | `b)` | 대문자와 별도 계열 |
| `A)` | upper alphabet + right parenthesis | `B)` | 번호로서의 대소문자 보존 |
| `i)` | lower Roman + right parenthesis | `ii)` | 초기 모호성 기본은 Roman |
| `(i)` | lower Roman + enclosing parentheses | `(ii)` | `i)`와 별도 계열 |
| `(I)` | upper Roman + enclosing parentheses | `(II)` | Unicode 로마숫자 글자와 혼동하지 않음 |
| `ㄱ)` | Hangul consonant + right parenthesis | `ㄴ)` | 지정 순서와 마지막 값 처리 필요 |
| `가)` | Hangul syllable + right parenthesis | `나)` | 단순 유니코드 코드포인트 증가 금지 |
| `-` | dash bullet | `-` | 하이픈 뒤 구분 공백 필요 |
| `*` | star bullet | `*` | 별표 뒤 구분 공백 필요 |

기호 계열은 숫자/영문/로마자/한글 종류, 대소문자, 괄호·마침표 형태까지 포함한다. 숫자가 같다고 `2.`를 `(2)` 계열의 다음 항목으로 자동 합치지 않는다. 기호는 구조에서 렌더링하되 사용자가 선택한 형식과 표시 문자를 보존한다.

### 4.2 모호성 해소 순서

1. 사용자가 도구모음에서 명시한 계열이 있으면 그 계열을 사용한다.
2. 같은 문맥의 활성 계열에서 입력이 정확한 다음 기호라면 그 계열로 해석한다. `h) → i)`는 영문 소문자 계열, `i) → ii)`는 로마 소문자 계열이다.
3. 둘 다 없으면 단독 `i)`, `I)`, `(i)`, `(I)`는 로마 숫자로 시작하는 기본안을 사용하고 계열을 변경할 수 있게 한다. `a)`, `A)`는 영문 계열이다.
4. 애매한 해석으로 원문이 달라지는 경우 자동 변환을 되돌려 문자 그대로 유지할 수 있다. 확정하지 않은 기호를 조용히 다른 번호로 바꾸지 않는다.

로마 숫자는 정해진 표기 규칙으로 검증한다. `iv`, `ix` 같은 표기는 지원하지만 임의의 i/v/x 문자열을 모두 번호로 인정하지 않는다. 초기 범위는 1~3999로 제안하며 경계에 도달하면 자동 증가를 멈추고 다른 계열/직접 입력을 안내한다. 영문 계열은 `a..z, aa..az, ba...`와 같은 명시된 순서로 증가하며 입력 길이·숫자 오버플로 한도를 검증한다. 실제 상한은 직렬화·편집기 검증에서 확정한다.

한글 자음 순서는 `ㄱ, ㄴ, ㄷ, ㄹ, ㅁ, ㅂ, ㅅ, ㅇ, ㅈ, ㅊ, ㅋ, ㅌ, ㅍ, ㅎ`, 한글 음절 순서는 `가, 나, 다, 라, 마, 바, 사, 아, 자, 차, 카, 타, 파, 하`로 고정한다. 마지막 이후를 임의로 `가가` 또는 처음 기호로 순환시키지 않는다. 같은 수준의 일반 빈 항목을 만들고 자동 증가 범위를 벗어났다는 상태와 계열 선택을 제공한다. 이미 입력한 마지막 항목과 본문은 유지한다.

## 5. 트리거·문맥·우선순위

### 5.1 언제 인식하는가

자동 인식은 입력 조합이 끝난 상태에서 문단의 본문 시작 위치에 기호와 구분 공백을 **직접 입력**했을 때 수행한다. 예를 들어 `1.`만 입력한 중간 상태에서는 확정하지 않고 `1. `가 되었을 때 판정한다. 기호 뒤 최초 구분 공백은 구조화 변환의 일부로 소비하고, 실제 본문에 필요한 뒤쪽 공백은 보존한다.

날짜 `2026.11.08`, 소수 `1.2`, URL, 본문 중간의 `1.`, 코드 블록·인라인 코드, 비밀번호 등 특수 입력은 변환하지 않는다. 줄 시작의 `-1`을 하이픈 목록으로 변환하지 않는다. 한글 조합 중의 `ㄱ`·`가`를 미완성 상태에서 판정하지 않으며 IME 확정 Enter와 문단 분리 Enter를 구분한다.

직접 입력과 붙여넣기는 별도 이벤트로 처리한다. 다중 행 텍스트·기존 문서 전체·표 셀 데이터를 붙여넣었다는 이유로 모든 줄의 숫자를 스캔해 자동 재구조화하지 않는다. 사용자가 `목록으로 변환`을 명시한 경우만 미리보기 후 변환한다.

### 5.2 관련 문단과 활성 계열 스택

‘윗 문단’은 같은 편집 컨테이너 안에서 바로 앞에 있는 관련 문단이다. 메모 트리의 부모 Note나 문서 어디든 과거에 있던 `1.`을 뜻하지 않는다. 본문과 각 표 셀은 서로 다른 컨테이너다.

연속 목록 구간에는 `list_context_id`를 부여한다. 현재 위치보다 앞쪽의 목록 문단과 level로 활성 계열 스택을 만든다. 같은 level의 다음 항목은 그 level의 마지막 항목을 갱신하고, 더 얕은 수준으로 돌아오면 그 아래의 활성 가지를 닫는다. 아직 본문을 입력하지 않은 자동 생성 다음 항목은 이전 번호 판정의 확정 선행 항목으로 중복 포함하지 않는다.

일반 문단으로 목록을 끝냈거나 표·이미지 같은 독립 블록 경계를 넘어 새 목록을 시작하면 과거 목록의 자동 복귀 문맥을 종료한다. 다른 셀·다른 메모·다른 독립 목록의 기호를 찾기 위해 문서 전체를 거꾸로 검색하지 않는다. 필요하면 사용자가 `이전 목록에 연결`을 명시하는 후속 기능으로 확장한다.

### 5.3 자동 수준 결정 순서

1. 자동 인식이 꺼졌거나 코드·조합·붙여넣기 금지 문맥이면 원문을 유지한다.
2. 명시 Tab/Shift+Tab으로 현재 문단을 수동 보정한 상태라면 현재 수준을 유지한다. 기호를 명시적으로 다시 편집하거나 `자동 수준 맞춤`을 실행할 때까지 같은 입력 이벤트로 재적용하지 않는다.
3. 입력 기호가 활성 스택의 어떤 계열에서든 **정확한 다음 ordinal**이면 가장 가까운 유효 계열의 level로 맞춘다. 여기에는 바로 앞의 같은 수준 항목도 포함한다.
4. 위 조건이 없으면 직전 관련 문단의 유효 level+1을 기본으로 한다. 부모 항목을 찾지 못했다고 임의의 전체 문서 번호에 맞추지 않는다.
5. 결과를 하나의 편집 명령으로 확정한다. 렌더링·저장·다른 창의 수신 이벤트가 같은 변환을 다시 실행하면 안 된다.

예를 들어 `1.` 다음 줄에 `2.`를 직접 입력하면 정확한 후속 번호이므로 `1.`과 같은 수준이다. `1.` 아래에서 `a)`를 직접 입력하면 다른 계열이므로 2칸 더 깊어진다. `a)` 다음에 `3.`을 입력했지만 활성 상위 숫자는 `1.`이면 후속 번호가 아니므로 상위로 자동 복귀하지 않고 기본 +2칸을 적용한다. 사용자는 Shift+Tab으로 보정하거나 명시 수준 맞춤 명령을 사용한다.

## 6. Enter·수동 보정·커서 동작

### 6.1 Enter와 자동 기호 교체

내용이 있는 목록 문단에서 Enter를 누르면 현재 항목 뒤에 새 문단을 만든다. 새 항목은 같은 level·계열·문맥을 사용하고 ordinal은 다음 값이다. 커서는 기호가 아니라 본문 시작에 둔다. 순서 없는 목록은 같은 기호를 이어 쓴다. Enter로 생성한 항목은 `inherited_pending` 상태로, 추가 들여쓰기 트리거를 다시 실행하지 않는다.

새 항목의 본문이 아직 비어 있을 때 사용자가 다른 지원 기호+공백을 입력하면 pending 기호를 **교체**한다. 예: `a)`에서 Enter로 생긴 `b)` 항목에 `2. `를 입력하면 `b)2.`라는 본문을 만들지 않고 숫자 계열로 변경하여 활성 상위 계열 규칙을 적용한다. 본문을 이미 입력한 뒤 나타나는 `2.`는 일반 본문이며 자동 교체하지 않는다.

기호 자체를 문자로 입력하고 싶은 경우 즉시 자동 변환 undo 또는 자동 목록 끄기로 원문을 유지한다. 일반 본문으로 들어간 후 기호를 바꾸는 작업은 전용 기호 편집/계열 메뉴로 제공한다. 자동 교체가 타이핑 원문을 되돌릴 수 없는 형태로 소비하지 않게 한다.

문단 중간에서 Enter를 누르면 커서 뒤 텍스트를 같은 수준의 새 다음 항목으로 옮기며 앞뒤 내용·서식·참조를 보존한다. Shift+Enter는 같은 문단 안의 줄바꿈으로 취급하고 새 번호·level을 만들지 않는다. 내용 없는 목록 항목에서 Enter를 누르면 목록 기호를 제거하고 같은 들여쓰기 수준의 일반 문단으로 전환한다. 이때 새 번호를 무한 생성하지 않는다.

일반 문단의 Enter는 현재 일반 들여쓰기 수준을 유지한 새 일반 문단이다. 자동 인식이 꺼진 상태에서도 명시적인 Tab/Shift+Tab·도구모음 들여쓰기는 사용할 수 있다. 목차 구조의 기호 문자열을 단순 텍스트 검색으로 판정하지 않는다.

### 6.2 Tab과 Shift+Tab

본문 편집 컨테이너에서 Tab은 선택한 문단의 level+1, Shift+Tab은 level-1이다. 한 번당 2칸이며 최솟값은 0이다. 0에서 Shift+Tab을 눌렀다고 음수 margin을 저장하지 않는다. 기호 종류·본문·번호는 그대로 두고 해당 문단의 수준만 바꾼다.

명시 보정 뒤에는 `manual_override=true`를 기록하여 저장 이벤트나 같은 키 입력 후 자동 판정이 다시 +2칸을 넣지 못하게 한다. 이 잠금은 현재 문단에만 적용한다. 다음 Enter 항목은 사용자가 선택한 현재 수준을 이어받되 새 문단의 자동 판정 상태는 새로 시작한다. 사용자가 새 기호를 명시 입력하면 잠금을 해제하고 문맥 규칙을 다시 적용할 수 있다.

여러 문단을 선택했으면 각 대상 문단을 같은 1단계만 이동한다. 이미 0인 문단은 그대로 두고 상대 깊이를 음수로 만들지 않는다. 부분 텍스트 선택은 선택에 걸친 문단 단위로 적용하고 선택 범위를 유지한다. 다른 Note의 트리 노드를 이동하거나, 자동으로 하위 메모 전체를 들여쓰지 않는다.

## 7. 사용자 예시의 정확한 처리 순서

아래 코드 블록의 선행 공백은 설명용이며 각 2개가 1단계다. 실제 원본에는 level 메타데이터로 저장한다.

### 예시 A. 기본 입력과 같은 단계 이어쓰기

```text
직전 일반 문단: level=0
사용자: 1. + Space + 본문
결과: level=1
  1. 첫 항목

Enter
결과: level=1, 다음 기호 자동 생성
  1. 첫 항목
  2. |
```

Enter의 `2.`가 또 자동 인식되어 4칸이 되는 것은 결함이다.

### 예시 B. 4칸이 되었지만 2칸을 원한 경우

```text
직전 관련 문단: level=1, 사용자 입력한 새 계열/후속 판정 안 되는 2.
자동 기본값: level=2
    2. 새 항목

Shift+Tab
보정 결과: level=1
  2. 새 항목
```

이미 활성 숫자 `1.`의 정확한 후속 `2.`로 판정되는 경우는 처음부터 2칸에 맞춘다. 위 예시는 새 목록·다른 문맥·번호 불연속 등으로 후속 계열을 찾지 못한 경우의 수동 보정이다. 기호만 같다는 이유로 사용자 보정 예시를 항상 4칸으로 만들지 않는다.

### 예시 C. `1.` 아래 `a)` 후 `2.`로 상위 복귀

```text
  1. 상위 항목             # level=1, decimal-dot ordinal=1
    a) 하위 항목           # 수동 a) 입력: level=2

Enter
  1. 상위 항목
    a) 하위 항목
    b) |                  # 자동 이어쓰기: level=2

새 빈 항목에서 사용자 2. + Space 입력
  1. 상위 항목
    a) 하위 항목
  2. |                    # b) 교체, 상위 숫자 후속이므로 level=1
```

`2.` 입력 전후 level과 기호 교체를 한 명령으로 처리한다. `b)`가 본문에 남거나 새 Note가 생기면 실패다.

## 8. 본문 모델과 저장 계약

```text
Paragraph
  paragraph_id: stable block anchor
  runs[]: 텍스트·안전한 링크·허용 인라인 노드
  outline?:
    level: integer >= 0
    marker_family: kind + case + delimiter, 또는 none(일반 문단)
    ordinal?: integer (bullet은 없음)
    marker_text?: 원래 표시형 보존용 검증된 기호 문자열
    manual_override: boolean
    list_context_id?: stable context identifier
    list_item_id?: stable item identifier
```

기호는 runs 앞에 리터럴 문자열로 매번 추가하지 않는다. 구조에서 가상 기호로 표시하고 일반 텍스트 복사·내보내기에서만 기호와 들여쓰기를 명시적으로 생성한다. paragraph_id는 커서·검색·표 셀·다중 창의 원문 위치 기준이다. 목록 항목의 identity를 렌더링 순서나 현재 번호 문자열로 만들지 않는다.

기호 없는 일반 문단의 수동 들여쓰기도 같은 level을 사용한다. marker_family=none이면 ordinal/marker_text/list_context_id/list_item_id는 null이며 기호를 렌더링하지 않는다. outline이 없으면 일반 문단 level=0이다. 일반 문단 Enter와 빈 목록 종료가 가짜 목록 컨텍스트를 계속 유지하지 않게 한다.

`marker_text`가 있더라도 임의 HTML·스타일·실행 코드를 허용하는 필드는 아니다. 지원 계열에서는 ordinal·계열과 일치하도록 검증하고, 자동 인식하지 않는 사용자 기호를 보존할 때는 문자 그대로 안전하게 표시한다. 컨테이너·Note 범위를 넘는 목록 ID를 자동 재사용하지 않는다.

`inherited_pending`, 입력 중 기호 버퍼, IME 조합 상태는 편집 상태다. 영속 원본에는 확정된 구조와 내용만 넣고, 초안 복구가 필요하면 기존 초안 정책에 따라 별도 보호한다. 비어 있는 구조 항목을 저장했다면 재열기 시 동일한 빈 항목으로 표시하되 원래 번호·수준을 새로 추정하지 않는다.

자동 변환·Enter 분리·수준 변경·기호 교체는 문서 편집 명령 한 번으로 적용하고 하나의 undo 단위로 묶는다. 자동 변환 undo는 변환 직전의 사용자가 입력한 기호+공백·본문·커서를 복구한다. undo 직후 같은 원문을 동일 이벤트로 재변환하지 않도록 입력 토큰을 소진 처리한다. redo는 동일 결과를 재생하며 같은 command_id 재전송이 문단을 또 추가하지 않는다.

기존 후속 항목이 이미 `2.`인데 앞에 새 항목을 삽입했더라도 사용자가 명시 입력한 번호를 조용히 일괄 재번호화하지 않는다. 자동 생성 중복 번호를 감지해 안내할 수는 있으나 `번호 다시 매기기`는 범위·전후 결과를 보여 주는 별도 명령으로 둔다. 단순 저장·검색·앱 재시작은 문서 번호를 변경하지 않는다.

## 9. 편집 상태기계와 키 처리 순서

```text
plain → prefix_buffering → recognized_prefix → transform_committing → list_item
prefix_buffering → literal_text  (불일치·본문 입력·자동 기능 꺼짐)
list_item --Enter(본문 있음)--> inherited_pending(같은 level, 다음 기호)
inherited_pending --본문 입력--> list_item
inherited_pending --다른 기호+Space--> recognized_prefix(기호 교체·수준 재판정)
list_item/inherited_pending --Tab/Shift+Tab--> manual_level
manual_level --기호 명시 재편집/자동 수준 맞춤--> recognized_prefix
inherited_pending --Enter(본문 없음)--> plain(현재 level 유지)
transform_committing --revision 충돌/실패--> draft_preserved
```

키 이벤트 우선순위는 IME 조합 처리 → 편집기 선택/대화상자 → 표 셀 이동 → 코드 등 특수 컨테이너 → 현재 본문 목록/문단 처리 → 일반 앱 단축키다. 같은 이벤트가 둘 이상의 계층에서 처리되지 않도록 소비 여부를 명시한다. 단축키 전달 여부는 편집기·Windows 입력기 실험으로 확인한다.

저장 충돌은 전체 메모 revision 계약을 따른다. 다른 창이 문단·표를 바꾼 뒤 늦게 온 자동 들여쓰기 결과가 최신 문서를 덮어쓰면 안 된다. 내 초안의 문단 ID·이전 구조·변경 제안을 보존하고 최신 원본에서 비교·재적용한다. 현재 caret 위치만 저장해 외부 변경 뒤 다른 문단을 들여쓰지 않는다.

## 10. 표 셀·설정·접근성

표 셀 안에서는 Tab/Shift+Tab을 다음/이전 셀 이동에 먼저 사용한다. 목록 수준 변경에는 `Alt+Shift+Right/Left` 또는 명시 들여쓰기/내어쓰기 버튼을 제공하며 사내 단축키 충돌에 따라 재지정할 수 있다. 셀 이동과 수준 변경을 같은 키 한 번으로 동시에 수행하지 않는다. 표 안 Enter는 같은 셀의 새 문단·같은 목록 수준 이어쓰기이며 다음 셀로 이동하지 않는다. 표의 행 추가·셀 나눔 명령과 구별한다.

각 셀의 list_context_id는 독립적이다. 왼쪽 셀의 `1.`이나 표 밖의 `1.`을 현재 셀 `2.`의 활성 상위로 사용하지 않는다. 표 셀 복사·병합·분할은 [11](11-tables-collection.md)의 원문 보존 규칙과 함께 paragraph_id·목록 구조를 처리한다.

자동 기호 인식과 자동 상위 수준 맞춤을 설정에서 제어할 수 있게 하되, 기본은 이 문서의 사용자 요구 동작이다. 끄기는 향후 입력에 적용하며 이미 구조화한 본문 전체를 평문으로 바꾸지 않는다. 계열 선택·수준 변경·기호 제거는 메뉴로도 제공한다. 설정 변경으로 기존 문서가 재번호화되지 않아야 한다.

화면읽기에는 목록 종류·현재 ordinal·수준·항목 내용을 전달한다. 들여쓰기만으로 계층을 알게 하지 않는다. 고대비·확대·줄바꿈·긴 번호에서도 기호와 본문을 식별하고, 마우스 없이 같은 작업을 수행할 수 있어야 한다.

## 12. 예상 버그와 예방책

| 예상 버그 | 원인 | 방지·검증 |
|---|---|---|
| Enter마다 2칸 더 들어감 | 자동 기호를 수동 트리거로 재처리 | inherited_pending·입력 원인 구별·동일 이벤트 소비 |
| Shift+Tab 후 다시 4칸 복귀 | 저장/렌더에서 자동 규칙 재실행 | manual_override·명시 편집만 재평가 |

| `2.`가 엉뚱한 과거 목록에 붙음 | 문서 전체 역검색·문맥 ID 없음 | 컨테이너별 활성 스택·구간 경계 |
| 로마·영문 후속 번호 오류 | `i`를 무조건 한 종류로 처리 | 계열·문맥·명시 선택 우선순위 |

| 기호와 본문이 저장마다 늘어남 | 리터럴 공백·기호와 구조 중복 저장 | 원본 구조·표시·평문 내보내기 분리 |
| 표 셀 이동 대신 목록만 움직임 | 동일 Tab 이벤트 중복 소비 | 셀 키 우선순위·대체 수준 명령 |
| IME Enter가 새 항목도 만듦 | 조합 상태 무시 | composition·keydown 순서 실기기 시험 |
| 기존 문서 번호가 전부 바뀜 | 저장/붙여넣기 때 전역 정규화 | 명시 변환만 수행·원문 대조·버전 이전 |

| 자동 undo 뒤 즉시 재변환 | 동일 입력 이벤트 재사용 | 입력 토큰·undo/redo 명령 구분 |

## 13. 개발·이전·완료 순서

1. 기존 편집기의 문단·목록·선택·IME·클립보드·표 셀·undo·저장 경계를 조사한다.
2. 기호 계열 parser/formatter·한글 순서·상위 스택 결정 규칙을 UI와 독립적으로 구현하고 고정 예시로 검증한다.
3. paragraph_id와 outline 구조를 body_format_version에 추가한다. 기존 본문은 읽기 전용 변환 리허설을 거친다.
4. 수동 기호 인식·Enter pending·기호 교체·상위 복귀·Tab 보정을 하나의 편집 명령 체계에 연결한다.
5. undo/redo·저장 실패·다중 창 revision·표 셀 키 충돌을 먼저 검증한다.
6. 한글 IME·화면읽기·고대비·DPI·다중 문단 선택·긴 본문 성능을 실제 Windows에서 확인한다.
7. 기존 본문은 기호·선행 공백이 있다는 이유만으로 새 목록으로 추정하지 않는다. 기존 구조가 확실하면 매핑하고, 불명확하면 원문을 보존해 사용자가 명시 변환하도록 한다.
8. 백업·복원에서 기호 계열·ordinal·level·문맥·수동 보정과 본문·표 셀 앵커를 대조한다. 신형 구조를 모르는 구버전 편집기는 읽기/쓰기 전에 호환성을 검사한다.

완료 산출물에는 사용자 확정 Enter 의미, 기호 계열 사전, 정확한 입력 trace, 구조 스키마·본문 버전, 키 우선순위 표, IME·undo·다중 창·표 셀 시험 증거, 이전·복원 대조표를 포함한다. 간단한 숫자 문자열 치환만으로 완료했다고 판정하지 않는다.
