## 위키 화면·명령·모델

`FolderSelection`은 새 폴더의 부모 맥락이며 자동으로 새 폴더를 선택해 다음 생성이 의도치 않은 하위 단계가 되지 않도록 한다. 명령은 `CreateFolder(parent?)`, `MoveFolder(folder_id,parent?)`, `ClassifyWikiNote(note_id,folder?)`로 분리한다. 최상위/미분류 드롭 영역을 제공하고 이동 전 순환 검사를 한다. 드롭으로 본문·생성시간·완료·댓글을 변경하지 않는다.

오른쪽 목록은 폴더 선택과 독립적인 분류 작업 재료다. 미분류 필터 상태에서 폴더에 넣으면 해당 항목만 목록에서 빠지고 원본은 유지한다. 왼쪽 배치된 제목 선택은 읽기/댓글 보기, 오른쪽 목록 클릭은 별도 편집창이므로 두 동작을 안내한다. 트리 댓글은 읽기 참조이며 새 댓글/편집은 같은 댓글 ID에 반영한다.

공통 댓글 엔진은 위키/일지뿐 아니라 이후 모든 댓글 입력에 적용한다. 현재 UI 프로토타입의 본문과 댓글은 동일한 다중행 텍스트 입력 위젯을 사용한다. 이는 전체 리치 본문 엔진(이미지/표/문단)의 구현 완료를 뜻하지 않는다. 제품 연결 시 동일 블록/붙여넣기 명령을 재사용하고 자산의 소유자가 Note 또는 Comment가 될 수 있도록 05/11 자산 모델을 확장한다. 댓글 자산 삭제/백업·검색 포함 정책을 명시하고 메모 검색에 댓글을 암묵 합치지 않는다.

## 기간 일정과 완료 상태기계

`PeriodGroup(note_id,start_date,day_count:1..5)`와 `Occurrence(id,period_group_id,offset,scheduled_date)`를 구분한다. 제품에서는 날짜 변경에도 occurrence ID가 변하지 않도록 offset/안정 ID를 사용한다. 기간은 주말 포함 연속 달력 날짜이고 반복 주기 규칙과 다른 개념이다. 정기 일정 엔진과 결합할 때 발생 그룹 중첩/충돌/범위를 09에서 검토한다. 프로토타입의 정기 일정 표시는 여전히 필터 시연이며 실제 반복 발생 계산은 미구현이다.

- 미완료 체크 → ScopePending(note,occurrence,target_state) → ThisDate / FromThisDate / Cancel.
- ThisDate는 선택 발생만, FromThisDate는 선택일부터 그 기간 끝까지. 앞선 날짜는 보존.
- 전체 메모 완료 상태는 기간의 모든 발생이 완료됐을 때 true. 부분 완료는 날짜별 캘린더/목록 취소선으로 표시.
- 일지는 각 완료 발생의 실제 완료 시각으로 집계한다. 일지 댓글·완료 시각 보정도 occurrence별로 분리한다. 같은 제목을 다른 날짜에서 완료해도 댓글을 혼합하지 않는다.
- 중요 섹션은 원본을 복제하지 않은 추가 투영이다. 체크/편집/드래그 결과가 일반 날짜 그룹에도 즉시 반영된다.
- 프로토타입에서 기간의 한 날짜를 드래그하면 전체 기간을 같은 거리만큼 이동하고 완료/댓글의 날짜 연결도 옮기되 실제 완료 타임스탬프는 보존한다. 제품에서는 범위 UI와 일지 정체성을 검토한다.

기간 길이 축소/삭제/반복 규칙 변경으로 이미 완료한 발생을 숨겨야 할 때 완료 이력과 댓글을 조용히 삭제하지 않는다. 제품 저장 단계에서는 활성 일정과 과거 완료 기록을 분리한다. 현재 메모리 프로토타입은 기간 외 완료 키를 정리하므로 이 동작은 제품 인수 전에 영속 이력 모델로 교체한다.

## 날짜 범위·프로젝트 필터

제품 질의는 `ProjectFilter=All|Unassigned|Id`로 직렬화한다. UI 프로토타입의 특수 식별값을 DB 프로젝트 ID로 저장하지 않는다. 날짜는 `SelectStart(d) => [d,d]`, `SelectEnd(d) => [min(start,d),max(start,d)]`. 생성일·일정·이미지 필터 공통 적용. 시작일을 다시 선택하면 새로운 하루 범위로 초기화한다. 일정이 여러 날이면 시작 날짜만 비교하지 말고 조회 범위와 발생 날짜의 교집합으로 검색한다. 신규 할 일은 생성시간을 편집하지 않고 일정/기간만 선택한다.

## 썸네일 보관과 복원

원본을 비우기 전에 작은 썸네일을 생성·검증하고 자산 ID·백업 경로·원본 무결성 정보를 유지한다. 갤러리는 썸네일로 같은 항목 위치를 유지하며 원본/썸네일 상태를 구별한다. 썸네일 클릭은 복사가 아니라 ‘용량 관리로 원본이 정리되었으니 백업 파일을 찾아주세요’ 안내로 이어진다. 기억한 백업 파일 또는 백업 폴더에서 사용자가 파일을 선택해 원본을 임시 로딩한다. 없는 파일·변조·권한 실패는 썸네일을 지우지 않는다. 임시 로딩 원본을 클릭하면 원본을 복사하며 썸네일을 원본으로 가장하지 않는다.

현재 프로토타입은 120×75 이하 썸네일과 실행 중 경로를 유지한다. 제품의 썸네일 크기/압축/전체 용량 한계·자동 정리 연령·백업 폴더 정책은 실제 사용 자료와 사내 정책으로 결정한다. 설정되지 않은 연령/용량 기준으로 자동 삭제하지 않는다.

## 개발·이전 순서

기존 코드 조사와 저장 안전성 우선 원칙 유지 → 실행 중 화면/명령 검토 → 단일 일정에 day_count=1로 기본값 부여 → 기간 발생 ID·완료·댓글 이전 → 폴더 이동·썸네일 카탈로그 영속화 → 실제 폐쇄망 보안·배율·IME·대용량 인수. 현재 내보낸 이미지 파일 외의 앱 상태는 종료하면 초기화된다.
