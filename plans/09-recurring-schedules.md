# 09. 캘린더 일정 이동과 정기 일정 개발 계획

> 최신 범위: [23 프로젝트 단일 분류·아이콘 도구](23-projects-icon-toolbar.md)에 따라 라벨과 `LABEL-*` 계약은 폐기되었다. 이 문서의 라벨 모델·필터·시험은 과거 설계 참조이며 구현하지 않는다. 프로젝트와 메모 자체 색상, 위키/정리 폴더는 유지한다.

상위 계획: [plan.md](../plan.md) · 공통 모델: [02](02-data-states.md) · 창·알림: [04](04-desktop-calendar-reminders.md) · 통합 시험: [08](08-tests-acceptance.md)

문서 상태: 사용자 추가 요구를 반영한 설계안. **반복 일정은 핵심 범위(P1)**다. 기존 코드 분석부터 시작하며 특정 캘린더 라이브러리·반복 계산기·저장 기술을 채택한 상태가 아니다. 반복 계산기가 있어도 아래 이동 범위·예외·이력 규칙은 제품이 직접 책임져야 한다.

## 1. 목표와 용어

캘린더에 이미 배치된 단발 메모도 날짜 칸 사이로 끌어 쉽게 옮긴다. 정기 일정은 매일, 매주, 선택한 요일, 평일, 주말로 등록할 수 있다. 정기 일정의 한 항목을 끌어놓으면 `이번 일정만` 또는 `이 날짜 이후 모두`를 선택하고 결과를 확인한 뒤 반영한다.

| 용어 | 의미 |
|---|---|
| 원본 메모 | 제목·본문·라벨·링크를 가진 Note. 반복 횟수만큼 복제하지 않음 |
| 일정 루트 | Note당 최대 1개의 Schedule. 단발 또는 반복이라는 종류를 가짐 |
| 시리즈 세그먼트 | 한 반복 규칙이 적용되는 구간. 이후 변경 때 이전·새 구간으로 나뉨 |
| 명목 발생 건 | 반복 규칙에서 원래 생성되는 한 슬롯. 예외 이동 전의 날짜·시각을 가짐 |
| 실제 발생 건 | 예외를 적용한 뒤 화면에 보이는 한 슬롯 |
| 원래 키 | 해당 세그먼트에서 처음 부여한 명목 날짜·시각 키. 한 건 이동으로 변경하지 않음 |
| 순번 | 반복 규칙상 발생 순서. 실제 이동 날짜나 화면 정렬 순서와 다름 |
| 예외 | 특정 슬롯의 일회성 날짜·시각·취소 변경. 시리즈 규칙과 별도로 보관 |

반복 항목에서 원본을 열면 같은 Note를 편집한다. 일반 본문·제목·라벨은 원본을 공유한다. v1.3 본문 체크리스트는 공유 템플릿과 회차별 체크/분모 snapshot을 구분하며 이미 시작한 회차의 체크 항목 내용은 보존한다. 임의의 전체 본문 회차별 사본·메모 버전 열람 기능은 없다. 날짜·완료·진행 상태·체크·알림은 해당 회차의 범위를 명시한다. 체크 상세는 [13](13-capture-views-checklists.md), 상태·겹침·일지는 [14](14-status-overlap-journal.md)를 따른다.

## 2. 요구사항 등록부

| ID | 요구사항 | 수용 조건 |
|---|---|---|
| REC-01 | 반복 일정 등록 | 매일·매주·선택 요일·평일·주말을 종일 또는 시간 일정으로 저장·재열기 가능 |
| REC-02 | 기존 단발 항목 드래그 | 캘린더에서 다른 날짜로 옮겨도 원본 Note·Schedule을 복제하지 않음 |
| REC-03 | 반복 이동 범위 선택 | 드롭 뒤 `이번 일정만`/`이 날짜 이후 모두`·취소를 제공하고 적용 전 결과 표시 |
| REC-04 | 한 건 이동 예외 | 같은 발생 identity의 실제 날짜만 바뀌고 다른 회차·반복 규칙은 유지 |
| REC-05 | 이후 구간 이동 | 원래 발생 순서의 선택 지점부터 시리즈를 분할하고 날짜 차이를 이후 규칙에 반영 |
| REC-06 | 기존 예외·이력 보존 | 완료·이동 예외·확인·다시 알림을 숨겨 삭제하거나 엉뚱한 회차에 붙이지 않음 |
| REC-07 | 회차 완료와 전체 완료 | 기본 체크는 해당 회차만 완료. 원본 메모 전체 완료·반복 종료는 별도 명령 |
| REC-08 | 회차별 알림 | 원본 회차 키로 중복을 제어하고 이동한 범위의 미확인 알림만 재계산 |
| REC-09 | 범위 생성·정확한 조회 | 무종료 반복을 모두 저장하지 않으며, 화면 범위 밖에서 이동해 들어온 예외도 조회 |
| REC-10 | 충돌·중단·되돌리기 | 버전 검사·원자 저장·명령 멱등성·복구·안전한 되돌리기 검증 |

## 3. 반복 입력과 기본 의미

### 3.1 입력 항목

메모의 일정 편집기와 캘린더의 빠른 입력 확장 화면에 같은 반복 설정을 둔다. 입력은 제목·시작 날짜·종일/시각·종료 또는 길이·반복·종료 조건·알림 순으로 구성한다.

| 사용자 선택 | 내부 규칙의 기본안 | 날짜 선택 의미 |
|---|---|---|
| 반복 없음 | mode=once | 기존 단발 일정 |
| 매일 | rule_kind=daily, interval=1 | 시작 날짜부터 매일 |
| 매주 | rule_kind=weekly, interval=1, 시작일 요일 1개 | 시작일과 같은 요일마다 |
| 요일 선택 | rule_kind=weekly, interval=1, 선택 요일 집합 | 월~일 중 한 개 이상 선택 |
| 평일 | rule_kind=weekly, 월·화·수·목·금 | 공휴일을 자동 제외하지 않음 |
| 주말 | rule_kind=weekly, 토·일 | 회사의 근무일 정의와 무관한 토·일 |

평일은 ‘월~금’이라는 뜻을 UI에 적는다. 공휴일 제외·영업일 이동은 별도 기능이며 공휴일 패키지 갱신이 기존 반복 날짜를 자동 변경하지 않는다. 토요일을 근무일로 운영하는 회사도 이 기본 명칭을 임의로 바꾸지 않는다.

초기 필수 범위는 위 규칙과 간격 1이다. 2주마다·매월·연간·음력·특정 주차는 후속 확장으로 분리한다. 월~일 입력·저장 순서와 주 시작 요일을 고정하고 OS 지역 설정으로 요일 비트가 뒤바뀌지 않게 한다.

종료 조건은 `계속 반복`, `마지막 날짜까지`, `총 N회` 중 하나다. 종료 날짜는 해당 시간대의 명목 시작 날짜를 포함하는 마지막 날짜다. N은 양의 정수이며 취소·한 건 이동도 원래 슬롯 한 회로 센다. 확인된 완료 건을 없던 것으로 처리해 총횟수를 다시 채우지 않는다.

선택 시작일이 요일 집합에 포함되지 않으면 다음으로 일치하는 날짜를 첫 발생으로 제안하고, 확인 전 날짜를 조용히 바꾸지 않는다. 예: 토요일에 평일 반복을 고르면 다음 월요일을 첫 발생으로 보여준다.

### 3.2 시간·기간

- 종일은 날짜와 일수, 시간 일정은 시리즈 시간대의 현지 시각과 명시된 기간으로 반복한다.
- UTC에 매번 24시간을 더해 현지 시각을 계산하지 않는다. 날짜·요일을 먼저 계산한 뒤 각 회차의 UTC를 구한다.
- Asia/Seoul 기본안을 사용하더라도 저장 시간대를 명시한다. 다른 시간대를 지원하면 존재하지 않는/중복 시각의 처리 결과를 표시·검증한다.
- 날짜 드래그는 종일 일수 또는 시간 일정의 벽시계 시작 시각과 기간을 보존한다. 시간을 바꾸는 드래그는 주·일 보기 등 명시적인 시간 영역에서만 수행한다.
- 첫 입력에 종료시각이 없으면 임의 길이를 숨겨 넣지 않는다. 기존 일정 입력 규칙에 따라 사용자에게 기간을 확인한다.

## 4. 논리 모델과 identity

아래는 공통 02 모델의 확장 계약이다. 필드 직렬화·인덱스·ID 형식은 기존 저장소 조사 뒤 확정한다.

```text
Schedule
  id: stable schedule_id
  note_id: UNIQUE Note reference
  mode: once | recurring
  schedule_revision
  once일 때만 기존 kind/날짜/시각/시간대 필드 소유
  recurring seed/시간대/기간은 RecurrenceSeries에서만 소유

RecurrenceSeries
  id, schedule_id, lineage_id, previous_series_id
  kind: all_day | timed
  rule_kind: daily | weekly
  interval: 1 (초기 범위)
  weekday_mask, anchor_local_date, anchor_local_time?
  time_zone, duration (종일은 일수 / 시간 일정은 초 단위를 명시)
  limit_kind: none | count | end_date
  limit_value (횟수 또는 마지막 현지 날짜)
  base_ordinal, cutoff_original_key_exclusive?
  revision, state: active | ended | superseded

RecurrenceException
  series_id, original_key, original_ordinal
  override_start_date/end_date_exclusive 또는 override_start_at_utc/end_at_utc
  cancelled, revision

OccurrenceState
  lineage_id, global_ordinal
  current_series_id, current_original_key
  workflow_status: todo | in_progress | waiting | on_hold
  completed_at_utc?, revision

OccurrenceAlias / SplitMapping
  source_series_id, source_original_key 또는 source_ordinal_range
  target_series_id, target_original_key 또는 target_base_ordinal
  command_id, mapping_version

Reminder (회차별 알림을 선택할 때)
  scope: series_relative
  schedule_id, offset_seconds, generation, enabled
  all_day_anchor_local_time?, anchor_time_zone?
  종일 기준 시각 미지정(null)은 매회 알림 없음
```

명목 키는 종일이면 원래 날짜, 시간 일정이면 원래 현지 날짜·시각과 시간대 의미를 포함한다. 드래그로 실제 날짜를 바꾸어도 한 건 이동에서는 이 키를 바꾸지 않는다. 화면 날짜를 ID로 사용하면 이동 후 확인·다시 알림·완료 상태를 잃으므로 금지한다.

세그먼트 분할은 새 세그먼트의 명목 키가 달라질 수 있다. 따라서 시리즈 전체에서 `lineage_id + global_ordinal`을 회차의 안정 논리 identity로 사용하고, `(series_id, original_key)`는 해당 세그먼트의 주소로 사용한다. 기존 주소를 새 주소로 해석하는 alias를 보존한다. 무한한 미래 슬롯의 alias를 행으로 모두 만들지 않고, 순번 범위 매핑으로 결정적으로 계산한다. 이미 저장된 예외·완료·알림 참조는 같은 트랜잭션에서 정확한 대상으로 이관한다.

02의 공통 계약에서는 순번 매핑을 `SplitMapping(old_series_id, old_boundary_ordinal, new_series_id, new_start_ordinal, mapping_revision)`으로 명명한다. 위 source/target 표기는 같은 논리 역할의 설명이며 별도 중복 저장소를 만들라는 뜻이 아니다. 개별 참조를 위한 `OccurrenceAlias`와 미생성 미래 슬롯을 위한 범위 매핑을 구분한다.

`global_ordinal`은 최초 시리즈의 발생 순서에서 시작해 분할된 세그먼트가 이어받는 순번이다. 단순히 현재 날짜순으로 다시 번호를 매기지 않는다. 계산기에 맡기는 로컬 순번과 lineage의 순번 사이에는 `base_ordinal` 대응을 둔다. 추후 임의 반복 규칙 편집·횟수 삽입을 지원하면 별도 매핑 설계가 필요하며, 이번 드래그 범위에서는 기존 슬롯 수·순서를 유지하는 날짜 이동만 지원한다.

완료나 휴지통 상태인 Note의 반복 계산·알림은 비활성화한다. Note를 영구삭제할 때 관련 시리즈·예외·회차 상태·alias·알림을 참조 정책에 따라 정리한다. 휴지통에서는 복원할 수 있도록 함께 보존한다.

## 5. 기존 단발 일정 드래그

1. 본창 또는 분리 캘린더의 항목을 잡으면 원본 Note ID, Schedule ID, 기대 revision, 시작 구간을 보관한다.
2. 이동할 날짜 칸을 강조하고 변경될 날짜·시각·기간을 보여준다. 월 경계를 넘는 자동 스크롤과 키보드 날짜 변경도 제공한다.
3. 드롭하면 단발 일정은 범위 선택 없이 같은 Schedule을 변경한다. 저장 성공 후 모든 캘린더·메모·트리 일정 정렬을 갱신한다.
4. 취소·금지 영역·저장 실패·revision 충돌은 원래 위치로 되돌리고 원본을 보존한다. 충돌에는 최신 값과 제안 값을 제시한다.

여러 날짜에 걸친 막대는 드래그를 시작한 셀의 오프셋을 계산한다. 이틀 일정의 둘째 날을 잡아 옮겼다고 전체 시작일이 하루 더 밀리지 않게 한다. 막대 끝 조절과 위치 이동을 다른 손잡이·피드백으로 구분한다.

## 6. 정기 일정 드래그의 공통 흐름

```text
idle → dragging → drop_proposed → scope_choice → preview
preview → conflict_resolution → preview
preview → committing → committed
dragging/drop_proposed/scope_choice/preview → cancelled (원본 불변)
committing → conflict 또는 failed (원본·제안 보존)
```

범위 선택에는 다음 정보를 함께 보인다.

- `이번 일정만`: 선택한 회차 한 건만 임시 이동. 원래 반복 요일은 유지.
- `이 날짜 이후 모두`: 선택한 회차의 **원래 발생 순번부터** 연결된 이후 회차 전체 이동. 표시된 실제 날짜 이후를 잘라내는 기능이 아님.
- 변경 전·후 날짜, 반복 요일, 첫 5~10회, 종료 조건, 영향을 받는 완료·예외·알림 건수.
- 저장·취소 버튼. 무한 반복은 개수 대신 `이후 계속`과 표시 범위를 안내한다.

명령 예시:

```text
MoveCalendarOccurrence(
  note_id, schedule_id, source_series_id?, original_key?,
  expected_note_revision, expected_schedule_revision,
  expected_series_revisions, expected_exception_revisions,
  scope: once | this_and_following,
  target_interval, resolution_plan, preview_token, command_id
)
```

preview_token에는 원본 버전·회차 identity·범위·목적지·해결안을 결합한다. 미리보기 후 다른 창에서 같은 시리즈가 바뀌면 확정하지 않고 다시 조회한다. 드롭 이벤트 중복은 같은 command_id로 한 번만 적용한다.

## 7. `이번 일정만` 처리

선택 회차의 `RecurrenceException`을 생성·수정한다. 기존 명목 슬롯을 원래 날짜에 중복 표시하지 않고 실제 이동 날짜에 한 번만 표시한다. 이미 예외인 항목을 다시 옮겨도 새 슬롯을 추가하지 않는다. 원래 날짜로 되돌리면 다른 예외 속성이 없는지 확인한 뒤 날짜 override만 제거할 수 있다.

예: 매주 월요일 09:00 회의의 원래 11월 16일 회차를 11월 18일로 이동한다. 해당 주는 수요일에 보이고 11월 23일 이후는 계속 월요일이다. 완료 상태·알림 확인 상태·원본 본문은 같은 회차에 남는다.

월요일 회차를 다음 월요일로 이동하면 그날 원래 회차와 두 건이 겹칠 수 있다. 서로 다른 순번이면 두 건을 모두 보여주고 겹침을 안내한다. 날짜·제목이 같다는 이유로 병합하거나 자동 삭제하지 않는다. 중복 클릭으로 같은 identity가 두 개 생기는 오류와 실제 서로 다른 회차의 겹침은 구별한다.

지난 미완료 회차를 미래 날짜로 옮기는 것은 허용한다. 기본안에서 완료 이력의 일정 수정은 완료 취소 등 명시적 이력 편집 흐름을 거치게 하며, 기록 시각을 새 이동 시각으로 위조하지 않는다. 과거로 이동해 도래 시간이 이미 지난 알림은 즉시 팝업을 쏟아내지 않고 다시 설정·확인 목록에 둔다.

## 8. `이 날짜 이후 모두` 처리

### 8.1 경계와 규칙 이동

선택 회차의 명목 순번 k를 경계로 이전 세그먼트의 `cutoff_original_key_exclusive`를 정한다. 경계 이전 원래 회차는 움직이지 않는다. 선택 회차가 이미 다른 날짜로 이동된 예외라도 경계는 그 예외의 원래 키다. 실제 표시 날짜를 기준으로 SQL 날짜 조건만 걸어 자르지 않는다.

화면 드래그 delta는 선택 회차의 **현재 실제 시작 날짜 → 목표 시작 날짜** 차이다. 이후 규칙에 적용할 rule_delta는 `목표 날짜 - 선택 회차의 원래 명목 날짜`다. 두 값을 구별해 저장·계산하고 새 세그먼트에서 선택 회차의 시작이 정확히 목표가 되도록 anchor를 정한다. 선택 회차에 기존 이동 예외가 있으면 두 이동량이 다를 수 있으므로 미리보기에서 차이와 새 규칙의 결과를 설명한다. 이후 세그먼트의 요일·종료 날짜 이동에는 rule_delta만 사용한다.

**선택한 회차 자체는 반드시 드롭한 목표 날짜로 이동한다.** 선택 회차의 기존 날짜 예외는 이 명령의 목표로 대체·정리하며, 아래의 ‘기존 예외는 실제 날짜 유지’ 기본값을 선택 회차에 적용해 원래 자리에 남기지 않는다. 미리보기에서 `선택 회차는 목표로 변경 / 다른 기존 예외는 유지`를 구분해 보여준다. 예: 명목 월요일이던 회차가 이미 화요일로 옮겨져 있고 금요일에 드롭되면, 이후 규칙은 월→금(+4일), 선택 회차도 금요일이다. 화면에서 끌어온 거리인 화→금(+3일)를 다른 명목 회차에 적용하지 않는다.

매일은 anchor를 이동하고, 매주는 요일을 이동하며, 선택 요일은 모든 요일을 같은 규칙 이동량 modulo 7로 이동한다. 평일·주말도 날짜 이동을 사용자가 선택한 결과로 그대로 이동한다. 예를 들어 월~금 반복을 하루 뒤로 옮기면 화~토의 `사용자 지정 요일`이 된다. 이름은 평일이라고 남겨두고 토요일을 몰래 제외하지 않는다.

이미 다른 미래 구간으로 나뉜 successor 세그먼트가 있으면 그 이후도 같은 명목 이동량으로 이동한다. 기존에 별도 지정한 요일 차이는 유지하며, 각 구간의 전·후 규칙을 미리보기에 열거한다. 이후 연결 구간을 무시하여 일부 날짜만 남겨두거나 한 규칙으로 덮어쓰지 않는다. 복잡한 구간이 많아 미리보기를 만들 수 없으면 확정하지 않고 범위·충돌을 설명한다.

### 8.2 종료 조건

- 무종료: 새 구간도 계속 반복한다. 미래 회차를 모두 생성하지 않는다.
- 총 N회: 선택 순번을 포함한 남은 **명목 슬롯 수**를 새 구간으로 넘긴다. 이전 완료·취소·한 건 이동 때문에 남은 횟수를 새로 늘리지 않는다.
- 마지막 날짜: 명목 날짜를 같은 일수만큼 옮기므로 종료 날짜도 같은 일수만큼 이동하는 기본안이다. 전·후 마지막 회차를 미리 보여준다.
- 이전 세그먼트는 경계 미만만 생성한다. 새 세그먼트는 경계 순번을 이어받으며 중복 생성하지 않는다.

### 8.3 기존 예외·완료·알림 해결

단순 분할은 새 규칙만 만들면 끝나지 않는다. 영향받는 순번 범위의 예외, 완료 상태, 확인한 알림, 다시 알림, 이미 열린 알림창, 미래 successor를 조사한다. 해결안이 확정되기 전까지 커밋 버튼을 활성화하지 않는다.

| 기존 기록 | 기본 해결 | 허용되는 다른 선택 |
|---|---|---|
| 사용자가 지금 드래그한 선택 회차 | 드롭 목표로 변경, 기존 날짜 예외를 새 목표로 대체 | 적용 취소. 선택 회차를 제자리에 남긴 채 이후만 이동하는 숨은 동작 없음 |
| 미완료 미래의 날짜 예외 | 같은 논리 슬롯으로 이관하고 현재 실제 날짜 유지 | 해당 예외만 초기화하여 새 규칙 따르기, 영향 미리보기 후 명시 선택 |
| 완료·과거 이력 | 실제 날짜·완료시각·확인 기록 유지하는 보존 예외로 이관 | 자동 초기화 금지; 별도 이력 수정 흐름 |
| 확인한 알림 | 같은 슬롯의 확인 이력 보존, 새 알림 자동 부활 안 함 | 사용자가 별도로 재알림 설정 |
| 다시 알림 | 같은 슬롯의 다시 알림 시각 유지 | 명시 재예약. 시각이 과거가 되면 검토 목록 |
| 미확인 미래 상대 알림 | 새 실제 발생 시각 기준으로 재계산·구형 실행 토큰 무효화 | 미리보기에서 해당 회차 알림 해제 |
| 아직 저장된 상태가 없는 미래 슬롯 | 새 세그먼트 규칙으로 생성 | 별도 예외 없음 |

완료·과거 기록을 이동 범위에 포함시켰다는 이유만으로 기록 날짜를 바꾸지 않는다. 그대로 남는 보존 예외가 있다는 점을 사용자에게 보여준다. 이력 보존 때문에 목표 날짜에 중첩이 생기면 겹침을 표시하며 다른 슬롯과 합치지 않는다.

기존 예외의 선택을 바꿀 때는 예외 revision을 검증한다. 미래 무한 슬롯 전체를 훑는 대신 저장된 예외·상태 범위만 조회하고, 미저장 슬롯은 순번 매핑 규칙으로 처리한다. 소스→타깃 alias는 순환 없이 최신 주소로 해석하고 체인이 길어지면 논리 identity를 유지한 채 압축할 수 있다.

### 8.4 원자 저장과 되돌리기

하나의 트랜잭션에서 이전 경계 확정, 새 구간·후속 구간 생성, 예외·상태·alias 이관, 영향을 받는 알림 취소/재예약 기록, revision 증가, 내부 변경 기록을 확정한다. 저장 기술상 즉시 다 처리할 수 없다면 전환 전 staged 묶음을 완성하고 활성 generation을 원자 전환한다. 미완성 묶음을 캘린더에 공개하지 않는다.

되돌리기는 해당 명령의 역변경을 저장한다. 이후 다른 창에서 새 구간을 수정했거나 사용자가 새 알림을 확인했다면 과거 스냅샷으로 덮지 않고 충돌을 안내한다. 동일 command_id 재시도는 시리즈를 추가 분할하지 않는다. 강제 종료 후 이전 상태 또는 완전한 새 상태로만 복구되어야 한다.

## 9. 완료·알림·종료 동작

반복 캘린더의 기본 완료 체크는 현재 회차의 `OccurrenceState`만 완료한다. 다른 날짜는 그대로이고 원본 Note 전체 완료 필드는 변경하지 않는다. 메모 헤더에는 `이 회차 완료`와 `메모 전체 완료`를 구분하며, 스티키를 어느 회차에서 열었는지 표시한다.

`메모 전체 완료`는 명시 명령으로 모든 이후 반복의 활성 표시·알림을 중지한다. 과거 완료 이력은 그대로 남는다. `반복 종료`는 종료 경계를 지정하는 일정 명령이며 본문 메모를 완료로 바꾸지 않는다. 완료 해제·휴지통 복원으로 과거 알림을 일괄 재발화하지 않는다.

알림은 `reminder_id + reminder_generation + lineage_slot_identity`를 기준으로 논리 중복을 제어한다. 단발 알림은 단발 슬롯 키를 사용한다. 한 건 이동은 해당 슬롯의 미확인 알림만 재계산하고 다른 회차의 확인·미루기를 건드리지 않는다. 시리즈 분할은 주소 alias를 따라 참조를 이관하고 구형 실행 요청의 series revision·generation을 표시 직전 재검증한다.

여기서 `reminder_generation`은 알림 설정의 세대다. `이번 일정만` 이동할 때 전체 설정 세대를 올려 다른 회차까지 무효화하지 않는다. 대상 `ReminderOccurrence`의 `delivery_revision` 또는 동등한 실행 토큰을 증가시키고 해당 미확인 건의 예약 시각을 갱신한다. 실행 요청은 알림 설정 세대·회차 전달 버전·현재 유효한 일정/예외 주소를 함께 검사한다. 확인된 발생 건을 새 ID로 다시 만들어 재전달하지 않는다. 무효화된 작업 기록은 보존 정책에 따라 이력으로 남기며 활성 고유성과 구별한다.

무종료 반복 알림도 제한된 예약 범위만 만든다. 앞으로의 예약 horizon을 주기적으로 보충하고, 시작·절전 복귀 시 마지막 처리 지점부터 현재까지의 누락을 배치로 평가한다. 수년치 지난 반복을 수천 개 창으로 열지 않고 기간별 요약과 사용자 선택을 제공한다. 알림 생성 범위와 캘린더 표시 범위를 같다고 가정하지 않는다.

종일 반복도 **매회 알림 설정을 이번 핵심 범위에서 지원**한다. 사용자가 이를 선택하면 `Reminder.scope=series_relative`, `all_day_anchor_local_time`, `anchor_time_zone`을 명시 입력받아 영속 저장한다. 기준 시각과 시간대가 모두 유효해야 활성화하며, 기준 시각 null은 매회 알림 없음이다. 날짜만으로 00:00을 자동 추정하지 않는다. 각 회차의 실제 현지 날짜에 이 기준 시각을 결합하고 `offset_seconds`를 적용해 예약한다. 기준값 수정은 설정 변경으로 generation을 올리고 확인·다시 알림 기록의 보존 규칙을 따른다. note_once의 일회성 절대 알림은 별도 동작이며 반복 전체에 자동 복제하지 않는다.

## 10. 조회·생성·성능

v1.3에서 분할·alias 이관 대상은 기존 완료·알림뿐 아니라 OccurrenceState.workflow_status, OccurrenceChecklistState와 ChecklistOccurrenceSnapshot도 포함한다. 정규 슬롯을 유지해 오늘 체크가 내일 슬롯에 붙지 않도록 한다. 첫 체크/진행 상태 조작 또는 완료 때 필요한 체크 snapshot을 같은 트랜잭션으로 확정한다. 대기/보류·본문 체크가 회차 완료·알림 해제를 자동 실행하지 않는다.

시간 겹침은 예외 적용 실제 회차·숨긴 유효 일정까지 검사하고 검사 범위를 명시하되 저장을 허용한다. 이후 무한 범위 이동은 ActivityEvent.schedule_moved 범위 명령 1건으로 기록하며 매회 무한 이벤트를 만들지 않는다. 일지 후보는 이벤트가 발생한 보고일로 집계하고 원래 회차 예정일·표시 날짜와 혼동하지 않는다. 사용자 편집 일지 문장이나 메모별 변경 이력 화면을 이관 기능으로 추가하지 않는다.

월·주·일 보기 조회 범위와 작은 여유 범위에서만 규칙을 펼친다. 무종료 규칙을 종료 날짜 없이 반복문으로 전부 생성하지 않는다. 원본 규칙·예외·완료 상태는 영속 데이터이고 화면용 발생 목록은 재생성 가능한 projection이다.

조회는 다음을 합쳐 identity로 중복 제거한다.

1. 범위와 교차하는 각 활성 세그먼트의 명목 발생 건.
2. 실제 override 구간이 조회 범위와 교차하는 예외. 원래 날짜가 범위 밖이어도 포함한다.
3. 명목 날짜는 범위 안이지만 실제 날짜가 밖으로 이동한 예외는 명목 항목을 제외한다.
4. 취소·구간 cutoff·완료 필터·메모 휴지통·전체 완료 정책을 적용한다.

순번별 상태·예외를 건별 조회하는 N+1 접근을 피하고 범위 배치로 읽는다. 같은 날짜·제목으로 중복 제거하지 않는다. 캐시 키에는 일정 revision·시리즈 세대·예외 revision·보기 범위를 포함하고, 본창·분리 캘린더 모두 커밋 이후 갱신한다.

## 12. 예상 버그·개발 순서

| 위험 | 원인 | 예방·탐지 |
|---|---|---|
| 이번만 옮겼는데 이후도 변경 | 발생 건과 템플릿 혼동 | 별도 명령·예외 테이블·REC-04 회귀 |
| 이후 변경이 과거 일정까지 이동 | 실제 날짜로 범위 선택 | 원래 키·순번·cutoff 고정 |
| 예외가 두 달에 중복 표시 | 명목+실제 조회 합성 오류 | identity 병합·이동 밖 제외 시험 |
| 평일 이동 후 토요일 누락 | preset 이름만 유지 | 실제 요일 집합 이동·Custom 전환 |
| 완료·미루기 기록이 다른 회차로 붙음 | 새 날짜를 ID로 사용 | 안정 lineage slot·alias·검증 대조 |
| 무종료 반복으로 앱 정지 | 전체 발생 건 선생성 | 범위 전개·horizon·취소 가능한 배치 |
| 시리즈 분할 후 알림 두 번 | 구형 작업 유효·주소 이관 누락 | generation·revision 재검증·논리 슬롯 중복 제어 |
| 선택한 회차만 목적지에 안 맞음 | 이미 이동된 예외의 delta 혼동 | 원래 날짜/실제 날짜/규칙 이동량 동시 미리보기 |
| 반복 완료가 전체 메모 완료 | 기존 단발 체크 재사용 | 회차 완료·전체 완료 명령 분리 |
| 되돌리기가 나중 업무를 삭제 | 스냅샷 무조건 복원 | 역명령·대상 revision 검사·새 이력 보존 |

개발 순서는 기존 일정·알림 분석 → 순수 날짜 규칙 계산·fixture → 안정 occurrence identity·예외 → 단발 드래그 회귀 → 이번만 이동 → 이후 분할·기록 매핑 → 회차 완료·알림 → 범위 조회·다중 창 → 중단 복구·이전 리허설이다. 캘린더 라이브러리가 반복 표시를 지원하더라도 저장 계약·명목 키·예외 매핑을 앱 도메인으로 독립 검증한다.

완료 산출물에는 규칙 스키마·예시 fixture·이동 범위 설명·분할 대조표·알림 재계산 기록·상태 전이 시험·성능 결과·이전/복원 결과를 포함한다. 기존 반복 제외 문구는 상위·관련 모듈에서 제거하고 이번 요구를 초기 핵심 출시의 인수 범위로 추적한다.
