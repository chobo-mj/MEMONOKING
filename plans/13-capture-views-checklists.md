# 13. 빠른 메모·수집함·저장한 보기·본문 체크리스트

> 최신 범위: [23 프로젝트 단일 분류·아이콘 도구](23-projects-icon-toolbar.md)에 따라 라벨과 `LABEL-*` 계약은 폐기되었다. 이 문서의 라벨 모델·필터·시험은 과거 설계 참조이며 구현하지 않는다. 프로젝트와 메모 자체 색상, 위키/정리 폴더는 유지한다.

문서 상태: 사용자 선택을 반영한 v1.3 핵심 범위(P1) 설계안. **빠른 메모 수집·저장한 보기·본문 체크리스트를 추가한다. 메모별 변경 이력 조회·본문 버전 비교 화면은 추가하지 않는다.** 기존 백업, 실행취소, 저장 실패 초안 복구, 이전 안전성은 유지한다. 현재 코드·편집기·저장소·단축키·보안 정책을 조사한 뒤 기술을 결정한다.

## 1. 목표와 업무 흐름

다른 프로그램을 쓰다가 떠오른 업무를 단축키로 짧게 기록한다. 즉시 날짜나 라벨을 정하지 않아도 수집함에 남고, 나중에 내용을 보완한 뒤 정리 완료한다. 자주 확인하는 필터 조합은 이름을 붙여 저장하고 매번 현재 데이터로 다시 조회한다. 메모 안의 작은 준비 항목은 체크리스트로 적고 진행률을 확인한다.

수집함·저장한 보기는 메모 사본이나 별도 업무 저장소가 아니다. 체크 항목도 독립 자식 Note를 자동 생성하지 않는다. 모든 기능은 기존 원본·revision·명령 멱등성·정책·백업 계약에 연결한다.

기존 UI 기술을 바꾸거나 단축키를 임의로 고정하기 전에 이 조사 결과를 남긴다. 단축키 등록이나 백그라운드 상주가 금지된 PC에서는 트레이/본창의 빠른 입력 버튼을 제공하고 지원 범위를 안내한다. 금지된 전역 감시 기능을 대체 경로로 만들지 않는다.

## 4. 빠른 메모와 수집함

### 4.1 창 열기와 입력

앱이 실행 중일 때 사용자 지정 전역 단축키를 누르면 작은 비모달 캡처 창을 열고 제목/짧은 본문 입력에 포커스를 둔다. 이미 창이 있으면 같은 초안을 보여주며 새 창·새 메모를 만들지 않는다. 기본 입력은 텍스트이며 일정·라벨은 펼친 영역에서 선택할 수 있다.

- 기본 단축키의 실제 조합은 지원 Windows·IME·사내 프로그램과의 충돌 검사 후 정한다. 등록 실패를 성공으로 표시하지 않는다.
- 단축키 변경은 기존 등록을 안전하게 해제하고 새 조합 등록 결과를 표시한다. 실패하면 사용 가능한 이전 설정 또는 버튼 동선을 보존한다.
- 창은 유효한 모니터 작업 영역에 표시하고 DPI·글꼴 확대·키보드 조작을 지원한다. 전체 메모 스티키를 한꺼번에 활성화하지 않는다.
- 다른 프로그램의 선택 텍스트·클립보드·창 제목·키 입력을 자동 수집하지 않는다. 사용자가 붙여넣기를 실행할 때만 기존 허용 클립보드 경로를 사용한다.
- IME 확정 Enter와 저장 단축키를 구분한다. 단순 Enter는 본문 줄바꿈이며 저장은 버튼/분리된 명시 단축키를 사용한다.

앱이 완전히 종료되면 전역 단축키는 동작하지 않는다. 별도 상시 서비스·관리자 권한·예약 작업을 기본 의존성으로 넣지 않는다. 일반 앱 바로가기를 통한 시작은 가능하지만 ‘종료 중에도 전역 단축키가 항상 동작’한다고 약속하지 않는다.

### 4.2 저장·닫기·재시도

`CreateCapturedNote(command_id, draft_id, payload)`는 Note와 `collection_state=inbox`를 같은 트랜잭션으로 확정한다. 생성시각은 실제 최초 생성 커밋 때 확정하고 초안 입력 시각은 필요하면 별도 메타데이터로 보존한다. 재전송된 같은 명령은 기존 note_id를 반환한다.

저장 성공을 확인한 뒤 입력창을 비우거나 닫는다. 저장 중 추가 타이핑은 전송 스냅샷과 후속 초안을 구별하며, 앞선 응답 때문에 후속 입력까지 지우지 않는다. 연속 입력 모드는 성공 후 빈 새 초안을 명시적으로 열 수 있지만 실패한 입력을 잃지 않는다.

Escape/창 닫기는 초안 보존 후 숨기기를 기본으로 한다. `입력 버리기`는 별도 동작이며 내용이 있으면 영향과 되돌릴 수 있는 범위를 안내한다. 숨긴 초안이 이미 저장된 메모인지 구별하고 재열기 때 중복 생성하지 않는다. 임시 저장·복구 파일도 승인된 위치·권한·보존 정책을 따른다.

디스크 부족·권한 오류·보안 차단은 미저장 상태로 표시하고 재시도·허용된 복사·복구 동선을 제공한다. 저장 실패를 이유로 원래 업무 앱의 포커스를 반복적으로 빼앗지 않는다.

### 4.3 수집 상태

`Note.collection_state = inbox | filed`를 둔다. 빠른 메모는 inbox, 일반 메모 생성은 filed를 기본으로 제안한다. 기존 메모는 이전 시 filed로 매핑하며 사용자가 원하면 수집함으로 보낼 수 있다.

수집 상태는 루트/자식 관계·일정·라벨·진행 상태·완료·휴지통과 다른 축이다. inbox 메모에 라벨이나 날짜를 붙였다고 자동 filed로 바꾸지 않는다. `정리 완료`를 누르면 filed로 바꾸고, 원본 내용·부모·일정은 유지한다. 수집함 보기는 활성 inbox 메모만 포함하며 완료·휴지통 필터는 명시한다.

수집함에서 여러 메모에 일괄 정리 완료를 적용할 때 대상 수·예상 revision을 확인한다. 필터된 화면에서 보이지 않는 항목까지 조용히 처리하지 않는다. 정리 완료를 취소해 inbox로 돌려도 새 Note를 만들지 않는다.

## 5. 이름 있는 저장 보기

### 5.1 데이터 계약

```text
SavedView
  id, name, revision
  predicate_schema_version
  predicate_ast: allowlisted fields/operators/literals
  sort_spec
  layout_preferences
  time_zone, relative_date_policy
  created_at_utc, updated_at_utc
```

조건은 검증된 자료 구조이며 SQL·스크립트·임의 함수·실행 템플릿을 저장하지 않는다. AND/OR·비교·집합 연산의 허용 종류, 노드 수·깊이·문자 길이를 정한다. 참조 가능한 필드는 라벨·완료/진행 상태·수집 상태·생성/수정/일정 범위·본문 검색·선택 가지·이미지/링크/표/체크리스트 유무 등 앱이 지원하는 항목뿐이다.

현재 필터·정렬·허용 화면 배치를 `보기로 저장`하고 이름을 붙인다. 예: `보고서 라벨 + 미완료 + 이번 주 일정`을 ‘이번 주 보고업무’로 저장한다. 검색 결과 ID 목록을 저장하지 않으므로 새 메모가 조건을 만족하면 자동으로 포함된다. 보기 복제는 설정만 복사하고 메모는 복제하지 않는다.

### 5.2 날짜와 상태 평가

‘오늘’은 지정 시간대의 오늘 날짜 구간, ‘이번 주’는 고정한 주 시작 요일의 현재 주 구간, ‘앞으로 7일’은 오늘 포함 7개 날짜 구간처럼 포함/배타 경계를 고정한다. 기본 시간대는 작업공간의 Asia/Seoul 제안을 따르되 보기 저장 시 의미를 명시한다.

보기를 열거나 새로고침할 때 현재 날짜로 상대 조건을 계산한다. 실행 중 자정을 넘기면 갱신 표시와 함께 날짜 기준을 다시 계산하며, 한 조회의 목록·개수·캘린더가 서로 다른 ‘오늘’을 사용하지 않도록 query evaluation 기준점을 공유한다. 명시한 절대 날짜는 자동 이동하지 않는다.

단발·반복 일정 기간 필터는 [05](05-search-media.md)·[09](09-recurring-schedules.md)의 실제 구간 교차 규칙을 사용한다. 전체 메모 완료와 회차 완료, 메모의 진행 상태와 회차 진행 상태는 UI의 조회 대상에 맞춰 구별하고 어떤 상태를 조건으로 삼는지 표시한다. 아직 지원하지 않는 범위 조합은 오류로 안내하며 잘못된 근사 결과를 만들지 않는다.

### 5.3 임시 변경과 참조 오류

저장 보기를 연 뒤 필터를 바꾸면 현재 화면만 임시 변경하고 ‘저장된 조건과 다름’을 표시한다. 기존 보기를 덮으려면 `보기 업데이트`, 별도 이름은 `새 보기로 저장`을 선택한다. 단순 창 닫기·앱 종료가 저장된 정의를 몰래 변경하지 않는다.

라벨·가지 루트·사용자 정의 참조가 삭제되면 보기를 `참조 확인 필요`로 표시한다. 없는 라벨을 조건에서 제거해 전체 메모로 범위를 넓히지 않는다. 사용자가 조건을 고치거나 삭제 사실을 확인해 새 정의를 저장할 때까지 누락 참조와 영향을 보여준다. 복원하면 같은 ID 참조를 다시 검증한다.

보기 삭제는 설정만 삭제한다. 현재 화면은 명시적인 임시 보기로 유지하거나 다른 보기 선택을 안내하되 메모·일정·체크 상태를 바꾸지 않는다. 같은 이름 정책·표시 순서·고정 기능은 UI 일관성을 위해 S1에서 정하며 ID를 이름으로 대체하지 않는다.

### 5.4 화면 연동과 집계

이름 있는 보기는 기존 공유 작업 보기의 필터 계약에 연결한다. 본창 목록/트리·검색·split 캘린더·본창을 따르는 분리 캘린더가 같은 정의와 평가 기준점을 사용한다. 독립 캘린더 보기나 고정 스티키는 독립 상태를 표시하며 필터 때문에 이미 열린 메모를 강제로 닫지 않는다.

메모 개수는 distinct note_id, 캘린더 개수는 실제 발생 건 수다. 경로 표시만을 위한 비일치 조상은 결과 개수에서 제외한다. 체크 항목 수나 표 수를 메모 수로 더하지 않는다. 저장 보기 적용이 원본 메모 parent_id나 라벨을 변경하는 동작이어서는 안 된다.

## 6. 본문 체크리스트

### 6.1 문서 구조와 기본 상태

```text
CheckItem (body_doc node)
  check_item_id: stable within Note
  paragraph: Paragraph(paragraph_id, runs[], outline?)
  checked_for_note: boolean; non-recurring note state, recurring template default false

ChecklistOccurrenceSnapshot
  snapshot_id, note_id, lineage_id, global_ordinal
  checklist_template_revision
  item_snapshot[]: item_id, text/allowed inline content, order, level
  created_at_utc, revision

OccurrenceChecklistState
  lineage_id, global_ordinal, check_item_id
  is_checked, checked_at_utc?, revision
```

실제 노드 이름의 직렬화는 02·12의 문단 구조에 매핑한다. 단계는 paragraph.outline.level 한 곳만 원본으로 사용하고, 체크박스가 기호를 소유하므로 그 문단의 marker_family는 none이다. 같은 항목의 단계를 두 군데 저장하거나 체크박스와 숫자 기호를 동시 렌더링하지 않는다. 문단과 check_item_id는 번호·텍스트·표 셀 좌표와 독립적인 안정 ID다. 이동은 ID 유지, 복사해 새 항목 만들기는 새 ID다. 체크리스트는 Note.body_doc에 있으며 별도 자식 메모·독립 일정·Reminder를 자동 생성하지 않는다.

도구모음의 `체크리스트`로 생성하거나 선택 문단을 명시 변환한다. 일반 텍스트의 `[ ]`나 `[x]`를 열기·검색·이전 중 자동 체크 노드로 바꾸지 않는다. 직접 입력용 축약 표기를 추가하면 별도 트리거·취소 규칙을 정하고 기본 문단 번호 인식과 충돌을 검증한다.

### 6.2 체크·진행률·완료

각 활성 체크 항목을 1개로 세어 `완료 항목 수 / 전체 활성 항목 수`를 표시한다. 중첩 체크 항목도 독립 항목이며 부모 체크가 자식을 자동 체크하거나 자식 전체 완료가 부모를 체크하지 않는다. 초기 진행률은 leaf-only 집계가 아니라 현재 컨텍스트의 모든 활성 체크 항목 집계다. 항목 0개는 ‘체크리스트 없음’으로 표시하며 0/0을 100% 완료라고 하지 않는다.

체크 항목 완료는 Note 전체 완료·회차 완료와 독립이다. 5/5가 되어도 메모나 반복 회차를 자동 완료하지 않는다. 반대로 전체 Note 또는 회차를 완료해도 모든 체크를 암묵적으로 체크하지 않는다. 필요한 경우 `모든 항목 체크`는 대상·범위를 보여주는 별도 명령이며 사용자 선택 없이 실행하지 않는다.

항목 삭제는 해당 항목을 현재 목록·진행률에서 제외하고 의미 있는 undo 단위로 복구한다. 하위 항목이 있으면 삭제 범위를 안내하고 미리보기에서 내용 보존/함께 삭제를 명확히 선택한다. 기존 실행취소·휴지통·반복 스냅샷 정책을 넘어 전체 메모 변경 이력 조회를 만들지 않는다.

### 6.3 키보드·문단 기호·표 셀

체크 항목에서 내용이 있는 상태로 Enter를 누르면 같은 수준의 새 **미체크** 항목을 만든다. 직전 항목이 체크됐어도 새 항목을 체크하지 않는다. Shift+Enter는 항목 안 줄바꿈이다. 빈 체크 항목의 Enter는 체크 표시를 제거하고 같은 수준의 일반 문단으로 전환하는 기본안을 사용한다.

체크박스와 `1.`·`a)` 등의 번호 기호를 같은 입력 이벤트로 이중 생성하지 않는다. 초기 기본안은 한 문단이 번호 목록 또는 체크 항목 중 한 종류만 갖는다. 체크 항목을 번호 항목으로 바꾸거나 반대로 바꿀 때는 명시 변환 명령을 사용하고 텍스트·단계를 보존한다. 일반 번호 문단의 Enter·상위 `2.` 복귀는 12 계약 그대로다.

본문에서 Tab/Shift+Tab은 단계 변경이고 표 셀에서는 셀 이동이 우선이다. 표 안 체크 항목의 단계 변경은 Alt+Shift+Right/Left 또는 버튼을 사용한다. 체크박스 토글은 클릭·체크박스에 포커스가 있을 때의 Space·명시 체크 명령으로만 수행한다. 본문을 타이핑하는 중의 일반 Space를 체크 토글로 소비하지 않는다. IME 확정 Enter/Space가 체크·새 항목을 동시에 실행하지 않게 한다.

### 6.4 정기 일정의 회차별 체크

반복 Note는 체크리스트 본문을 **템플릿**으로 공유하되 체크 여부는 정규 회차 키 `(lineage_id, global_ordinal)`별로 보관한다. 전날의 5/5가 다음날 5/5로 복제되지 않는다. 세그먼트 분할·임시 이동도 canonical 키를 유지하므로 해당 회차의 체크를 잃지 않는다.

회차 컨텍스트를 열면 미시작 회차는 현재 템플릿을 미체크로 보여준다. 처음 체크·진행 상태 조작을 하거나 해당 회차를 완료할 때 템플릿 항목/순서/내용/단계의 스냅샷을 함께 확정한다. 회차 자체 완료 기록이 먼저 생긴 경우에도 당시 체크리스트의 분모와 내용이 나중에 달라지지 않도록 스냅샷을 만든다. 읽기만 했다는 이유로 무한 미래 회차의 스냅샷을 만들지 않는다.

이미 스냅샷이 있는 회차는 그 항목 집합과 항목 내용을 사용한다. 이후 원본 템플릿을 추가·삭제·수정해도 이미 시작한 회차의 진행률이나 완료된 기록을 조용히 다시 계산하지 않는다. 미래 미시작 회차만 최신 템플릿을 따른다. ‘시작한 미완료 회차에 템플릿 새로 적용’은 선택 확장으로, 추가/제거/내용 변경·유지할 체크를 미리 보여주고 명시 확정해야 한다. 완료 회차 스냅샷은 이 동작의 대상에서 제외한다.

반복 원본 메모를 회차 선택 없이 열면 템플릿 편집 상태와 ‘체크하려면 회차 선택’을 표시한다. 템플릿 화면의 체크 조작을 모든 회차의 체크 상태로 해석하지 않는다. 단발→반복 전환은 기존 체크 상태의 처리 결과를 미리 보여주고 이후 새 회차는 미체크로 시작한다. 반복→단발 전환도 보존할 회차·이력을 확인하고 임의 합산하지 않는다.

스냅샷은 업무 체크 상태의 정확한 분모·내용을 보존하기 위한 자료다. 사용자가 제외한 메모별 과거 본문 버전 조회·시점 비교 기능이 아니다. 별도 노트 변경 이력 화면이나 임의 과거 본문 복원을 구현하지 않는다. 업무일지는 해당 날짜/회차의 체크 요약을 읽을 수 있지만 체크 상태를 바꾸거나 본문을 자동 복사해 기록을 증식시키지 않는다.

## 7. 명령·상태기계·동시성

```text
Capture:
closed/hidden → opened(existing draft) → editing → saving → saved
saving → failed/conflict → editing/retry
editing → hidden_with_draft
same command retry → original saved note_id

Inbox:
inbox --명시 정리 완료--> filed
filed --수집함으로 보내기--> inbox
각 상태 --휴지통--> 일반 수집함 조회 제외 (원래 상태 보존)

SavedView:
valid → applied → locally_modified
locally_modified --명시 업데이트--> saved valid
reference/schema failure → needs_attention
delete → view removed; notes unchanged

Checklist:
unchecked ↔ checked
active item --명시 삭제--> removed from current set
recurring unstarted --첫 조작/회차 완료--> snapshot + sparse states
recurring started → same snapshot/state identity after move/split
```

```text
CreateCapturedNote(draft_id, command_id, payload)
SetCollectionState(note_id, expected_note_revision, inbox|filed, command_id)
SaveView(view_id?, expected_view_revision?, validated_definition, command_id)
ApplyView(view_id, expected_definition_revision, evaluation_context)
EditChecklistTemplate(note_id, expected_note_revision, patch, command_id)
SetChecklistItem(note_id, item_id, context, checked, expected_revisions, command_id)
```

context는 단발 Note 또는 반복 canonical 회차다. 상태가 없는 첫 회차 조작에서는 템플릿 revision·snapshot 생성·상태 쓰기를 원자적으로 수행한다. 템플릿을 읽은 뒤 다른 창에서 바뀌었으면 오래된 분모로 조용히 시작하지 않고 재조회/명시 확인한다.

단발 체크는 본문 원본·Note revision, 반복 체크는 OccurrenceChecklistState와 snapshot/state revision을 검사한다. 반복 체크가 공유 Note 본문을 저장하지 않아 다른 회차·본문 편집을 덮어쓰지 않는다. 화면 갱신은 커밋 후 이벤트·현재 revision 대조를 따른다. 저장 실패 시 체크 표시를 성공으로 확정하지 않고 미저장/재시도 상태와 이전 원본을 보존한다.

체크·항목 이동·변환·복수 항목 변경·저장 보기 정의 수정도 command_id를 사용한다. undo는 의미 있는 역변경을 revision 검사 뒤 적용하고, 이후 다른 창의 체크·상태 변경을 과거 스냅샷으로 덮지 않는다. 반복 체크 undo가 다른 슬롯의 상태를 변경하지 않아야 한다.

## 8. 보안·검색·접근성

모든 기능은 로컬 저장·승인된 경로·동일 사용자 권한을 사용한다. 수집함과 저장 보기 이름·필터·체크 항목 텍스트에도 업무 정보가 있으므로 로그에 원문·URL·클립보드를 기본 기록하지 않는다. 전역 단축키 기능을 키로거·클립보드 감시로 구현하지 않는다.

체크 항목 본문은 기존 한글 부분문자열 검색과 원문 매핑에 포함한다. 체크 상태·진행률 필터는 단발 Note/반복 회차 컨텍스트를 표시한다. 미체크 회차를 찾는 기능은 지정된 기간의 유한 회차만 펼치고 무종료 미래 전체를 검사하지 않는다. 검색 결과 메모 수는 distinct Note, 회차·항목 수는 별도 집계다.

화면읽기에는 체크 항목 이름·체크 여부·수준·현재 진행률·수집 상태·선택 보기와 참조 오류를 전달한다. 상태를 색상·취소선·작은 체크 그림만으로 구분하지 않는다. 단축키 충돌·비활성·앱 종료·저장 실패를 명시하고 마우스 없이 대체 동작을 제공한다.

## 9. 이전·백업·복구

- 기존 메모의 수집 상태는 filed로 매핑하고 원래 부모·일정·라벨·완료를 보존한다. 기존 전체 메모를 ‘미정리’로 바꾸어 수집함을 채우지 않는다.
- 기존 화면 필터는 개인 화면 설정으로 보존하고 사용자가 저장하기 전 임의의 SavedView를 생성하지 않는다. 스키마 버전이 다른 조건은 변환 미리보기 또는 참조 확인 필요 상태로 둔다.
- `[ ]`, `[x]`로 보이는 기존 텍스트를 체크 항목으로 자동 재해석하지 않는다. 확인된 기존 체크 구조만 매핑하고 원문·출처·예외를 보존한다.
- 백업에는 collection_state, SavedView·조건 버전·참조, CheckItem·안정 ID, 회차 snapshot/state·canonical 키·별칭 대응을 포함한다. 검색·개수 캐시는 재생성 가능하다.
- 복원 후 단축키는 새 PC의 등록·정책·충돌을 다시 확인한다. 옛 PC에서 성공한 조합이 새 PC에서도 사용할 수 있다고 가정하지 않는다.
- 빈 시험 프로필에서 캡처 저장·수집 정리·상대 날짜 보기·체크·반복 이동·스냅샷 분모·검색을 실제 확인한다. 메모별 변경 이력 화면이 없어도 이 복구 검증은 필수다.

## 11. 예상 버그·성능·개발 순서

| 위험 | 원인 | 예방·검증 |
|---|---|---|
| 단축키마다 창/메모 증식 | 창 등록·초안과 원본 생성 혼동 | 창 1개·명시 저장·command_id |
| 저장 응답이 새 입력 삭제 | 전송 스냅샷과 후속 초안 혼합 | 입력 버전 구분·느린 저장 시험 |
| 라벨 붙이자 수집함에서 유실처럼 보임 | 정리 상태 자동 추정 | collection_state 독립·명시 정리 완료 |
| 보기 삭제가 메모 삭제 | 쿼리 결과를 소유 데이터로 오해 | SavedView 수명과 Note 분리 |
| 삭제 라벨이 전체 보기로 확장 | 잘못된 참조를 조건에서 자동 제거 | needs_attention·명시 수정 |
| 오늘 보기가 날짜를 고정 저장 | 상대 날짜를 결과 날짜로 직렬화 | 상대 표현 저장·평가 기준점 |
| 다른 회차까지 체크됨 | 원본 checked_for_note를 반복 상태로 재사용 | canonical 슬롯별 상태·템플릿 기본 미체크 |
| 템플릿 수정으로 완료 진행률 변화 | 현재 항목을 과거 분모로 사용 | 첫 조작/완료 시 스냅샷·완료 이력 보존 |
| 체크가 Note 전체 완료로 전파 | 단발 완료 버튼 재사용 | 별도 명령·완료 독립 시험 |
| Space·Enter가 두 동작 실행 | IME/본문/체크/셀 키 중복 소비 | 컨텍스트·포커스·소비 여부 계약 |

성능 수치는 08의 공통 기준에서 대상 PC를 확인한 뒤 정한다. 큰 수집함·저장 보기 여러 개·체크 항목 수천 개·수년치 반복을 각각 시험하되 모든 미래 회차나 모든 보기 결과를 선제 생성하지 않는다. 진행률·필터 결과도 원본 revision·상태 revision 기준으로 캐시하고 오래된 계산이 최신 체크를 덮지 않게 한다.

개발 순서는 기존 입력/필터/본문 조사 → collection_state·명령·초안 복구 → 단축키/단일 창·수집함 → 조건 AST·상대 날짜·저장 보기 → 체크 노드·키 라우팅·진행률 → 반복 스냅샷/상태·분할 → 검색·접근성 → 이전·실제 복원·중단 시험이다. 메모별 변경 이력 화면은 이 단계에 포함하지 않는다.

완료 산출물에는 지원 단축키·실행 수명·초안 정책, 수집 상태 규칙, 저장 보기 스키마·날짜/오류 의미, 체크 항목/회차 스냅샷·진행률·명령 계약, 모듈/통합 시험·보안 PC·이전/복원 결과를 포함한다.
