# 10. 브라우저 즐겨찾기 가져오기와 색상 라벨

문서 상태: v1.1 추가 핵심 요구의 설계안. 기존 코드·저장소·사내 브라우저 실행 정책을 조사한 뒤 구현한다. 특정 HTML 파서, 프로세스 API, UI 프레임워크 또는 DB를 선정한 문서가 아니다.

상위 계획: [plan.md](../plan.md) · 공통 계약: [02 데이터 모델](02-data-states.md) · 통합 시험: [08](08-tests-acceptance.md)

## 1. 목표와 범위

Chrome 또는 Edge에서 내보낸 즐겨찾기 HTML 파일을 프로그램에 가져와 폴더·제목·주소를 탐색하고, 사용자가 즐겨찾기를 실행하면 선택한 Chrome 또는 Edge로 해당 주소를 연다. 가져오기·목록 보기·검색은 완전히 오프라인으로 동작한다. 브라우저가 열린 뒤 주소에 접속할 수 있는지는 폐쇄망 경로·인증·사내 정책에 달려 있으며, 인터넷 접근을 새로 허용하는 기능은 아니다.

메모에는 사용자가 이름과 색을 정한 라벨을 여러 개 붙일 수 있다. 라벨은 메모 상단의 색띠와 이름으로 보이고, 특정 라벨의 메모만 목록·트리·검색·캘린더에서 모아 본다. 라벨은 메모의 복사본·별도 폴더가 아니라 원본 Note에 부여하는 분류다.

즐겨찾기의 로그인 정보·비밀번호·쿠키·브라우저 세션은 가져오지 않는다. 브라우저 프로필 DB를 직접 읽거나 Chrome/Edge에 양방향 동기화하지 않는다. 즐겨찾기 가져오기로 웹 페이지를 다운로드·캐시·OCR·변환하지 않는다. PDF/PPT/Excel 또는 보호 파일을 가리키는 주소 역시 보안 제한을 우회하는 실행 경로로 쓰지 않는다.

## 2. 기존 코드와 사내 환경 확인

| 조사 항목 | 확인 사실 | 구현에 미치는 영향 |
|---|---|---|
| 현행 링크 처리 | 주소 검증·기본 브라우저 실행·외부 셸 사용 여부 | 승인된 공통 URL 실행 어댑터 재사용 또는 교체 |
| 즐겨찾기 표본 | 사내 설치 Chrome/Edge에서 실제 내보낸 HTML, 한글 폴더·중복·긴 주소 | 지원 형식·인코딩 픽스처와 호환 범위 확정 |
| 브라우저 설치 | Chrome/Edge 설치 여부·버전·실행 경로·관리 정책 | 선택 가능한 브라우저 목록·미설치 안내 |
| 앱 실행 정책 | 표준계정 외부 프로세스 실행 허용 여부·허용목록 | 사용자 클릭 실행의 가능 범위 확인 |

| 기존 분류 기능 | 태그·분류·색상·고정·필터 데이터와 화면 | 기존 값을 Label로 안전하게 매핑 |
| 화면 구조 | 본창·스티키·트리·검색·캘린더 렌더러 | 공통 Label 조회·색띠·필터 적용 지점 |
| 운영 | 가져오기 원본·진단·백업 저장 위치 및 보존기간 | 임시 원본·URL·라벨 정보 보호 |

지원 브라우저의 현재 설치 경로를 계획에서 고정하지 않는다. 설치 조사와 실행 확인은 사내 허용된 OS 경로를 사용하며, 브라우저 프로필 내용·레지스트리에 등록된 임의 프로토콜을 무조건 신뢰하지 않는다.

## 4. 공통 논리 모델과 책임

### 4.1 즐겨찾기 원본

| 엔터티 | 필드·규칙 |
|---|---|
| BookmarkFolder | id, parent_id, title, sort_key, revision; 단일 부모·순환 금지, 루트는 null |
| Bookmark | id, folder_id, title, url_raw, sort_key, revision, import_source_id?, created_at_utc, updated_at_utc |
| BookmarkImportJob | id, source_digest, source_browser_hint, parser_version, options_digest, status, counts, error_summary, created_at_utc |
| BookmarkImportMap | job_id, source_node_key, target_kind, target_id, decision; 같은 작업·원본 노드 유일 |
| BookmarkImportStaging | job_id, 원본 노드·부모·순서, 안전하게 추출한 제목·URL, 검증 결과·중복 후보 |
| BrowserPreference | 선택 browser_id(chrome/edge), 승인된 설치 식별 정보, 검증 상태; 실행 명령 문자열 저장 금지 |

Bookmark는 Note와 별개다. 같은 URL을 메모 본문과 즐겨찾기에 보관할 수 있으며 한쪽 삭제가 다른 쪽을 삭제하지 않는다. 사용자가 나중에 즐겨찾기를 메모에 링크로 삽입하는 기능을 추가하더라도 원본 엔터티를 혼합하지 않는다.

`url_raw`는 HTML entity를 해석한 실제 목적지 문자열을 보존한다. 원본 HTML 바이트·속성값은 승인된 가져오기 원문 보관 정책에 따라 별도 보존할 수 있다. 검색용 정규화 값과 실행용 URL을 분리한다. 쿼리 파라미터·경로 대소문자·fragment를 중복 제거 목적으로 임의 제거하지 않는다.

### 4.2 라벨 원본

| 엔터티 | 필드·규칙 |
|---|---|
| Label | id, name, color_hex, sort_key, revision, deleted_at_utc? |
| NoteLabel | note_id, label_id, assigned_at_utc, assignment_order, is_primary; (note_id,label_id) 유일 |
| LabelViewPreference | 선택 label_id 집합, mode(any/all), unlabeled_only, 화면 적용 범위 |

이름은 앞뒤 공백 제거·NFC 정규화 후 비어 있지 않아야 한다. 비교용 키는 일관된 대소문자 비교 규칙을 적용하여 같은 작업공간의 활성 라벨 이름을 중복 생성하지 않도록 제안한다. 이름 길이와 라벨 개수 한도는 기존 데이터·실측 후 정하며, 입력 상한과 오류를 문서화한다.

색상은 대문자 또는 소문자 표현을 내부에서 한 형식으로 정규화한 `#RRGGBB` 불투명 RGB다. 색상 팔레트와 직접 색 지정 수단을 제공한다. 임의 CSS 문자열·URL·투명도·스타일 속성을 입력값으로 실행하지 않는다. Label ID는 이름·색상 변경과 무관하게 유지한다.

한 메모에 대표 라벨은 최대 1개다. 대표를 해제·삭제하면 남은 assignment_order, label_id 순의 첫 라벨을 대표로 정하는 결정적 규칙을 사용한다. 전체 라벨 정렬 순서를 바꾸더라도 메모별 대표·표시 순서가 매번 흔들리지 않게 한다. 기본 부여 순서는 뒤에 추가하며 사용자가 대표를 지정할 수 있다.

### 4.3 수정·조회 경계

즐겨찾기 가져오기와 라벨 수정도 공통 Command 서비스·revision·command_id·커밋 후 이벤트 규칙을 따른다. UI마다 파일을 따로 읽거나 전역 가변 라벨 객체를 직접 수정하지 않는다.

```text
PreviewBookmarkImport(file_handle, source_hint, options)
  -> staged_job_id, source_digest, tree_preview, counts, warnings
CommitBookmarkImport(job_id, expected_source_digest, expected_target_version, command_id)
  -> imported_ids, skipped_ids, job_status, bookmark_generation
LaunchBookmark(bookmark_id, expected_revision, browser_id)
  -> started | browser_missing | policy_denied | invalid_url | launch_failed

CreateLabel(name, color_hex, command_id)
UpdateLabel(label_id, expected_label_revision, patch, command_id)
AssignNoteLabel(note_id, expected_note_revision, label_id, expected_label_revision, command_id)
RemoveNoteLabel(note_id, expected_note_revision, label_id, command_id)
DeleteLabel(label_id, expected_label_revision, expected_assignment_generation, command_id)
SetLabelFilter(label_ids, mode, unlabeled_only)
```

라벨 이름·색 변경은 Label revision과 라벨 변경 이벤트만 갱신하고 각 메모의 본문·updated_at_utc를 변경하지 않는다. 라벨 부여·해제·대표 지정은 NoteLabel과 Note revision을 같은 트랜잭션에서 갱신하며 메모 자체 분류 변경으로 updated_at_utc를 갱신한다. 라벨 삭제로 연결을 일괄 해제할 때도 영향받는 Note revision을 증가시켜 이미 열린 창의 오래된 연결 저장을 막되, 본문·updated_at_utc는 보존하고 변경 종류를 `label_detached_by_delete`로 기록한다.

## 5. 즐겨찾기 가져오기 절차

### 5.1 입력과 인코딩

1. 사용자가 승인된 위치의 `.html` 또는 `.htm` 파일을 선택한다. 일반 웹 페이지를 브라우저처럼 여는 기능과 구분한다. 확장자만으로 즐겨찾기 파일이라고 믿지 않는다.
2. 파일 바이트·노드 수·깊이·속성 길이 상한을 적용하고 BOM·명시 charset·표본 검사로 인코딩을 판정한다. 초기 구현은 UTF-8을 우선 지원하며 실제 사내 내보내기 표본의 인코딩을 조사한다.
3. 인코딩 충돌·잘린 문자·유효하지 않은 바이트는 대체문자만 넣고 성공 처리하지 않는다. 제목 표본과 재선택 옵션을 표시하고, 지원하는 인코딩으로 사용자가 확인한 뒤 진행한다.
4. 파서는 스크립트·네트워크·이미지 디코딩·외부 entity 해석이 없는 데이터 처리 전용 경로를 사용한다. 일반 WebView에 파일을 로딩해 DOM을 얻는 방식을 기본안으로 쓰지 않는다.
5. 내보내기 형식의 폴더·링크 노드와 필요한 값만 추출한다. 관행적 `DL/DT/H3/A` 구조는 실제 Chrome/Edge 표본으로 검증하며 태그 순서·대소문자·속성 추가·빈 폴더 차이를 견딜 수 있게 한다.
6. `ICON`, `ICON_URI`, script, img, style, iframe, event 속성은 실행·다운로드하지 않는다. 필요 없는 항목은 제외 개수로 보고하고 원격 리소스에 접속하지 않는다.

### 5.2 폴더와 순서

원본 폴더의 안정적인 파싱 노드 키를 만들고 반복 순회로 부모·자식·형제 순서를 추출한다. 빈 폴더·동명 형제 폴더·같은 URL이 여러 폴더에 있는 상태를 허용한다. 제목이 같다는 이유로 폴더를 자동 병합하지 않는다.

기본 가져오기는 사용자가 고른 목적지 아래에 별도 `가져온 즐겨찾기 - 파일명` 루트를 만든다. 날짜·파일명은 표시명이며 ID가 아니다. 기존 폴더와 합치기는 선택 옵션으로 두고 명시적인 목적지 대응표를 미리 보여 준다. 폴더를 평면 링크 목록으로 바꾸어 의미를 잃지 않는다.

내보내기 파일의 생성시각 속성이 있더라도 업무 앱이 자동으로 생성한 정확한 시각이라고 표현하지 않는다. 원본 메타데이터와 가져온 시각을 분리하고, 누락·비표준 속성은 임의 추정하지 않는다.

### 5.3 중복과 재가져오기

기본 정책은 같은 폴더 매핑 안의 동일 `title + url_raw`를 중복 후보로 보여 주고 사용자가 건너뛰기·보존을 선택하는 것이다. 다른 폴더의 동일 URL은 서로 다른 사용 맥락일 수 있으므로 기본 보존한다. 쿼리 파라미터가 다른 URL을 같은 링크로 합치지 않는다.

같은 파일을 다시 선택하면 source_digest·가져오기 옵션·기존 provenance로 이전 작업 여부를 알린다. **같은 job 재개는 항상 멱등**이며 같은 노드를 두 번 추가하지 않는다. 사용자가 명시적으로 새 사본으로 가져오기를 선택하면 새 job으로 보존할 수 있다. 파일 해시만 같다고 모든 사용자 작업을 무조건 차단하지 않는다.

기존 데이터와 합치기에서는 미리보기 이후 폴더가 삭제·이동·수정되면 target version 충돌로 다시 미리보기한다. 변경된 원본 파일을 예전 미리보기 결과로 적용하지 않도록 승인한 staged bytes 또는 digest를 고정한다.

### 5.4 미리보기·확정·취소

미리보기에는 파서 버전, 원본 브라우저 힌트, 판정 인코딩, 전체/가져오기/중복/차단/오류 링크 수, 폴더 구조, URL 예시, 목적지·중복 정책을 보여 준다. 원본 브라우저 표시는 사용자가 지정한 힌트일 수 있으므로 검증된 사실과 구분한다.

확정은 작은 기본 데이터셋에서 하나의 트랜잭션으로 처리한다. 큰 파일은 staging 배치를 사용하더라도 완료 전에는 일반 즐겨찾기 조회에 노출하지 않고 최종 활성 전환을 원자적으로 수행한다. 실패·취소 시 기존 즐겨찾기는 그대로 남는다. 사용자가 저장 성공을 보기 전의 부분 데이터가 운영 목록에 섞이지 않아야 한다.

취소 시 준비 파일·원문·진단 요약의 보존·정리를 사내 정책대로 수행한다. 보안 목적 격리가 승인되지 않은 파일 내용을 새 보관 장소에 무조건 복제하는 근거가 되어서는 안 된다.

## 6. 즐겨찾기 실행과 관리

### 6.1 브라우저 선택과 실행

초기 설정 또는 즐겨찾기 상단에서 `Chrome`·`Edge`를 선택한다. 설치·정책이 확인된 브라우저만 사용 가능 상태로 표시한다. 둘 다 있으면 마지막 선택을 저장하며 항목 메뉴에서 이번 실행만 다른 브라우저를 고를 수 있다. 선택한 브라우저가 없으면 다른 앱으로 조용히 대체하지 않고 설치·정책 상태와 선택 변경을 안내한다.

사용자 클릭 또는 키보드 실행 때 다음 순서로 처리한다.

1. 현재 Bookmark revision과 url_raw를 다시 조회한다. 미리보기·검색 결과에 남은 오래된 주소를 실행하지 않는다.
2. URL을 엄격히 파싱하고 허용 scheme·호스트·포트·길이·인증정보 포함 여부를 검사한다. 초기 기본 실행은 승인된 `http`·`https`에 한정한다.
3. `javascript:`, `data:`, `file:`, UNC, 임의 앱 프로토콜, 제어문자·줄바꿈을 포함한 주소는 기본 차단한다. 사내 파일 링크 지원이 필요하면 별도 정책·검증을 추가한다.
4. 고정된 browser_id를 승인된 설치 실행 파일에 매핑한다. 즐겨찾기 HTML·제목·URL·가져오기 파일에 든 실행 경로나 브라우저 옵션은 사용하지 않는다.
5. 셸 문자열을 만들지 않고 선택 스택의 안전한 프로세스 실행 어댑터에 실행 파일과 URL 인자를 분리해 전달한다. 원시 Win32 command line을 직접 구성해야 한다면 실행 경로를 명시하고 브라우저의 인자 해석에 맞는 검증된 quoting을 적용한다. 공백·따옴표·`&` 등을 임의로 이어 붙이지 않는다.
6. `started`는 프로세스 시작 요청 또는 기존 브라우저로의 전달이 성공했다는 뜻이다. 웹 페이지 로딩·로그인·네트워크 성공을 앱에서 확인했다고 표시하지 않는다. 네트워크 무접속과 실행 실패를 구분한다.

브라우저 기본 프로필·SSO는 브라우저가 관리한다. 앱이 profile-directory, 원격 디버깅 포트, 보안 비활성화 옵션, 비밀번호·쿠키를 주입하지 않는다. 브라우저 실행 파일 확인에 실패하면 임의 경로 탐색·관리자 실행·다른 뷰어로 우회하지 않는다.

브라우저 실행은 사용자가 요청한 URL 열기라는 예외적 외부 동작이다. 앱의 목록·검색·미리보기는 자체적으로 통신하지 않는다. 사내 방화벽을 통과하거나 외부 인터넷 접속을 보장하지 않는다. 사용자가 여러 항목을 한꺼번에 여는 기능은 초기 제외하여 대량 창 생성과 의도치 않은 통신을 줄인다.

### 6.2 검색과 수정

즐겨찾기 검색은 제목·URL·폴더명에 대한 한글 부분문자열을 사용하고 NFC·영문 대소문자 처리 등 기존 검색 규칙을 재사용한다. 메모 검색과 즐겨찾기 검색은 결과 유형을 구분한다. 즐겨찾기가 메모 개수나 메모 캘린더에 섞이지 않는다.

폴더 이동은 비순환 검사와 안정 정렬을 적용한다. 항목 이름·URL 수정은 revision을 검사하고, 폴더 삭제는 영향받는 하위 폴더·항목 수를 보여 주며 삭제·되돌리기를 제공한다. 제목·폴더명도 업무 정보를 담으므로 진단 로그에 원문을 기본 기록하지 않는다.

## 7. 라벨 관리와 상단 색띠

### 7.1 관리·부여 흐름

1. 라벨 관리 화면 또는 메모 상단의 `라벨 추가`에서 이름과 색을 입력한다.
2. 새 라벨을 만들기만 할지, 현재 메모에 만들고 붙일지 명확히 구분한다. 후자는 하나의 명령으로 원자 확정한다.
3. 메모마다 여러 라벨을 체크하고 하나를 대표로 지정한다. 이미 붙인 라벨을 다시 부여해도 중복 연결을 만들지 않는다.
4. 본창·분리 스티키·캘린더 원본 열기에서 같은 라벨 목록을 조회한다. 라벨은 부모→자식으로 자동 상속하지 않는다. 자식에도 적용하는 묶음 기능은 별도 확인·범위 미리보기가 필요하다.
5. 라벨 이름·색을 바꾸면 같은 ID에 연결된 모든 메모의 표시가 갱신된다. 메모 사본을 만들거나 각 메모에 색을 일괄 복사하지 않는다.

### 7.2 색띠 표현

라벨이 하나면 메모 상단 전체 폭을 해당 색띠로 표시하고 이름 배지를 함께 제공한다. 여러 개면 대표 라벨이 먼저 오고 assignment_order·label_id로 정한 순서대로 색띠를 분할한다. 폭은 표시되는 라벨 수에 따라 균등 배분하는 기본안으로 정한다.

상단 공간이 좁으면 대표 색과 표시 가능한 조각만 보이되 `외 N개` 버튼·이름 목록으로 전체 라벨을 확인한다. 작은 색 조각만으로 모든 분류를 전달하지 않는다. 무라벨은 중립 띠 또는 띠 없음으로 일관되게 표현한다. 사용자가 고른 색 위의 텍스트 대비가 부족하면 텍스트를 별도 중립 배지에 두거나 대비가 확보된 글자색을 적용한다.

스티키 제목줄, 메모 상단, 목록 행·캘린더 카드의 색띠는 같은 순서를 사용한다. 캘린더에서는 공휴일·오늘·선택일·완료 취소선과 라벨의 의미가 겹치지 않도록 위치·아이콘·텍스트를 구분한다. 완료는 라벨 색을 지우지 않고 취소선·체크 표식으로 표현한다.

고대비 모드에서는 테두리·이름·패턴 등 시스템 접근성 표현을 우선 적용할 수 있다. 색맹·색약 사용자가 색만으로 구분해야 하는 설계를 피하고 모든 라벨 추가·제거·대표 변경·필터 조작을 키보드로 제공한다.

### 7.3 이름·색 수정과 삭제

라벨 삭제 화면에는 이름·색·적용 메모 수와 ‘라벨 연결만 제거되며 메모·본문·일정은 보존됨’을 표시한다. 이름·색 수정과 삭제는 기대 Label revision을 검사한다. 삭제 미리보기 후 다른 창에서 새 부여가 발생하면 연결 generation을 다시 검사해 영향 개수를 갱신하고 진행하도록 한다.

삭제는 Label tombstone과 NoteLabel 연결 해제를 하나의 작업으로 처리한다. 되돌리기에는 라벨 원래 속성·연결·대표 순서를 기록하고, 그 이후 사용자가 수정한 연결을 과거 상태로 덮어쓰지 않는다. 이름이 이미 재사용되었으면 복원 이름을 확인하고 충돌을 해결한다. 라벨 삭제가 메모 휴지통 이동이나 반복 일정 종료 명령으로 해석되어서는 안 된다.

메모에서 라벨 해제는 해당 NoteLabel만 제거한다. 라벨 정의와 다른 메모의 연결은 그대로 남는다. 삭제한 라벨을 참조하는 열린 메뉴는 새 부여를 거부하고 최신 목록으로 갱신한다.

## 8. 라벨 필터와 반복 일정 연동

기본 필터는 선택 라벨 중 하나라도 붙은 메모를 보여 주는 `하나 이상 포함(any)`이다. `모두 포함(all)`은 선택한 모든 라벨이 붙은 메모를 보여 준다. 선택 라벨이 없으면 전체 메모다. `라벨 없음`은 별도 배타 옵션으로 두어 any/all과 동시에 켜서 모순된 조건을 만들지 않는다.

트리 필터는 일치하지 않는 조상도 경로 표시용으로 남길 수 있지만 흐리게 표시하고 결과 개수에 포함하지 않는다. 경로 조상을 일치 메모처럼 집계하지 않는다. 검색 필터와 라벨 필터는 AND로 결합하며 완료·기간·휴지통 필터 의미를 그대로 유지한다.

공유 작업 보기의 선택 라벨·모드는 본창 좌우 split과 연동된 분리 캘린더에 동기화한다. 분리 캘린더가 독립 필터를 지원한다면 `본창 필터 따르기/독립`을 명시하고 독립 상태를 뚜렷하게 보인다. 기존 스티키는 필터 때문에 강제로 닫지 않으며 현재 보기에서 제외된 메모라는 상태만 안내할 수 있다.

라벨·필터가 바뀌면 메모 목록·검색 결과·트리·캘린더를 같은 데이터 generation 기준으로 갱신한다. 변경 중 결과가 일시적으로 뒤처지면 갱신 상태를 표시하고 오래된 조회가 최신 필터를 덮어쓰지 않게 한다. 삭제된 라벨 ID가 저장된 필터에 있으면 제거·안내하고, 빈 선택은 전체로 복귀한다는 규칙을 적용한다.

위 빈 선택 복귀는 임시 라벨 필터 설정의 복구 규칙이다. v1.3의 이름 있는 SavedView에서는 [13](13-capture-views-checklists.md)의 참조 무효 규칙이 우선한다. 삭제 라벨을 조건에서 지워 전체 메모로 확대하지 않고 수정 필요 상태와 영향을 표시한다. 라벨은 업무 분류, workflow_status는 진행 상황이며 체크 완료·Note 완료·수집함 정리와 자동 연동하지 않는다.

반복 일정의 라벨은 메모 원본에서 파생한다. 한 메모의 월간 발생 건 20개에 같은 라벨이 표시되어도 라벨 관리 화면의 적용 개수는 **서로 다른 Note 수 1개**로 센다. 캘린더의 일정 개수는 표시 발생 건 수이므로 별도 이름으로 나타낸다. 발생 건 하나에만 라벨을 다르게 붙이는 기능은 기본 범위 밖이다.

## 9. 상태기계와 실패 처리

```text
즐겨찾기 가져오기:
selected → reading → parsed/staged → previewed → committing → committed
reading/parsing 실패 → rejected (원본·기존 목록 불변)
previewed → cancelled (staging 정책대로 정리)
committing 중단 → 재시작 job 검사 → 완전한 이전 상태 또는 committed

브라우저 실행:
idle → validating → launching → started
validating → invalid_url / browser_missing / policy_denied
launching → launch_failed

라벨:
active → renamed/recolored → active
active → delete_pending_preview → deleted
deleted → restore_validate → active (이름·연결 충돌 해결 후)

부여:
unassigned → assigning → assigned → removing → unassigned
revision 충돌 → 초안 보존·최신 목록 재조회 → 재적용
```

HTML 파싱 오류를 빈 즐겨찾기 정상 가져오기와 구별한다. 원격 리소스 차단 항목, 잘못된 URL, 인코딩 오류는 개수와 위치를 안전한 요약으로 제공한다. 파싱 중 취소·앱 종료·디스크 부족에 대응하고, UI가 멈춘 채로 기다리게 하지 않는다.

라벨 색 변경에 필요한 색상 캐시만 실패했다고 메모 본문을 수정·초기화하지 않는다. 필터 오류를 0건 결과로 위장하지 않는다. 안전한 최신 원본 조회 또는 명시적 오류·재시도 상태를 제공한다.

## 12. 이전·백업·개발 순서

1. 현행 링크 실행·색상 분류·필터 코드를 조사한다. 실제 내보내기 표본·브라우저 설치·정책을 확보한다.
2. 불활성 HTML 파서와 읽기 전용 미리보기를 먼저 구현한다. 원본 대비 개수·구조·URL과 무접속을 검증한다.
3. Bookmark·Folder·import job/staging/mapping, 원자 확정·재개·중복 제어를 구현한다.
4. 선택 브라우저 실행 어댑터를 표준계정 실제 PC에서 검증한다. 설치 없음·차단·인자 주입 시험을 통과시킨다.
5. Label·NoteLabel과 명령·이벤트·revision·백업 스키마를 도입한다. 기존 분류는 이름·색·적용 대상 매핑을 검토하고 불명확 값은 이전 보류 목록에 둔다.
6. 본창·스티키·목록·캘린더에 상단 색띠·이름·대표를 적용하고 필터·검색·개수를 연결한다.
7. 삭제·되돌리기·동시 변경·깊은 폴더·한글·접근성·반복 발생 연동을 시험한다.
8. 빈 시험 프로필 복원으로 BookmarkFolder/Bookmark/Label/NoteLabel·출처·설정이 실제로 복구되는지 확인한다. PC가 바뀌면 실행 파일 경로는 재검증하며 예전 절대 경로를 그대로 신뢰하지 않는다.

백업에는 원본 즐겨찾기·폴더·라벨·연결·정렬·대표·필터와 재개에 필요한 가져오기 이력을 포함한다. 완성 전 staging은 운영 원본과 분리하고 복원 시 재개 또는 폐기를 명확히 정한다. URL에도 토큰·사내 경로가 있을 수 있으므로 로그·진단에는 기본 원문을 남기지 않는다.

완료 산출물은 지원 내보내기 파일 범위, 파서·인코딩·중복 정책, 승인 브라우저 탐지·실행 결과, URL 허용 정책, 라벨 표현·필터·revision 계약, 이전 매핑·복원 결과, 모듈·통합 시험 결과다.

## 13. 공식 참조와 검증 범위

- Chrome은 북마크를 HTML 파일로 내보낸다고 공식 안내한다. 본 모듈은 그 파일을 입력으로 받으며 Google 계정 동기화나 전체 프로필 백업을 요구하지 않는다. [Google Chrome 도움말 — 북마크 가져오기·내보내기](https://support.google.com/chrome/answer/96816?hl=ko)
- Edge의 즐겨찾기 내보내기 기능은 Microsoft 공식 안내를 참고한다. 실제 사내 설치 버전의 파일 표본을 테스트하고, 페이지의 메뉴 위치가 항상 같다고 가정하지 않는다. [Microsoft Edge — 즐겨찾기 백업](https://www.microsoft.com/en-us/edge/learning-center/back-up-passwords-favorites)
- Edge에서 Favorites/bookmarks HTML 파일을 처리하는 공식 지원 안내는 공통 내보내기 파일 호환성을 확인할 참고 자료다. 본 프로그램이 비밀번호 가져오기까지 구현한다는 의미는 아니다. [Microsoft 지원 — 즐겨찾기 가져오기](https://support.microsoft.com/en-gb/edge/import-your-favorites-and-passwords-in-microsoft-edge)
- 실행 파일 경로와 command line의 해석을 구분해야 한다는 근거다. 특정 스택에서 반드시 이 API를 직접 사용하라는 결정은 아니다. [Microsoft Learn — CreateProcessW](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-createprocessw)

참조 확인 기준일: 2026-11-08. 운영 앱은 이 출처에 자동 접속하지 않는다. 브라우저 실행·HTML 파싱·보안 제품 호환성의 실제 적합성은 대상 PC에서 검증한다.
