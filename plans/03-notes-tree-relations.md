# 메모 편집·중첩 트리·관련 메모 개발 계획

> v1.5 변경: 이 문서의 단일 부모 제한 및 parent_id 기반 종속 계약은 [17 복수 부모 DAG·위키](17-dag-board-wiki.md)로 교체한다. 기존 필드를 DAG 간선으로 이전하는 절차를 적용한다. 관리함의 최신 역할과 화면은 17/19를 따른다.

> 상태: 기존 코드 분석 전의 설계 기준안. 특정 편집기·언어·DB·UI 프레임워크의 채택을 뜻하지 않는다. 실제 구조와 보안 정책을 조사한 뒤 대응 설계와 차이를 기록한다.

## 1. 목적과 선행 조사

제목·일정·본문을 가진 메모 한 개를 트리, 본문, 검색 결과, 별도 스티키 창, 캘린더에서 함께 사용한다. 화면마다 내용을 복사해 갖지 않고, 동일한 `note_id`에 대한 명령과 변경 알림을 공유한다.

구현을 시작하기 전에 다음을 코드와 실행 화면으로 확인한다.

- 현재 메모 식별자가 재시작 후에도 유지되는지, 제목·날짜 변경에 따라 ID가 바뀌는지.
- 본문 저장 형식, 이미지 저장 위치, 링크 표현 방식, 기존 데이터 손실 없이 읽을 수 있는지.
- 메모 저장이 즉시 저장·수동 저장 중 어느 방식인지, 한 파일 전체 덮어쓰기인지.
- 트리가 실제 부모 관계를 저장하는지, 화면 폴더만 있는지, 이미 순환·고아 데이터가 있는지.
- 다중 창에서 동일 메모를 여는지, 저장 충돌을 감지할 버전 정보가 있는지.
- 한글 IME 입력 중 저장·포커스 이동·창 닫기가 본문을 훼손하는지.
- 외부 파일·이미지 붙여넣기 허용 범위, 클립보드·스크린 캡처·DRM 관련 사내 정책.

조사 결과로 기존 기능 유지 목록, 재사용 가능 모듈, 교체 필요 부분, 마이그레이션 대응표를 작성한다. 신규 편집기를 먼저 선정하거나 기존 DB를 곧바로 새 형식으로 덮어쓰지 않는다.

## 2. 요구사항 및 범위

| ID | 기능 | 기본 결정 및 수용 조건 |
|---|---|---|
| NOTE-01 | 제목·본문·생성시각 | 제목과 본문을 저장하고 생성시각은 최초 생성 때만 확정한다. 제목을 비워도 메모를 잃지 않으며 목록에서는 `제목 없음`으로 표시한다. |
| NOTE-02 | 텍스트·링크·이미지·표 | 승인된 텍스트, 하이퍼링크, 본문 이미지와 편집 가능한 표를 삽입·수정·삭제한다. 원격 자원을 자동으로 받지 않는다. |
| NOTE-03 | 일정·완료 연결 | 단발/정기 정의와 메모 완료를 같은 원본으로 연결한다. 반복 회차 완료는 그 회차만 바꾸며 전체 메모 완료와 구별한다. |
| NOTE-04 | 저장 상태 | `저장 중`, `저장됨`, `저장 실패`, `충돌 확인 필요`를 구별하고 실패한 내용을 자동 폐기하지 않는다. |
| NOTE-05 | 다중 창 수정 | 예상 revision이 다르면 기존 내용을 조용히 덮어쓰지 않는다. |
| NOTE-06 | 복구 | 휴지통 이동·복원과 작업 취소를 제공하며, 영구 삭제는 별도 동작으로 둔다. |
| TREE-01 | 반복 중첩 | 제품상 고정 깊이 제한을 두지 않는다. 자기 자신이나 자손 밑으로 이동하는 순환 관계는 금지한다. |
| TREE-02 | 접기·펼치기 | 메모별 자식 목록을 접고 펼친다. 접힘 상태는 본문 데이터와 분리해 사용자 화면 설정으로 저장한다. |
| TREE-03 | 정렬 | 수동 순서, 생성시각, 수정시각, 일정, 제목 정렬을 지원한다. 정렬 기준과 오름/내림 방향을 화면에 표시한다. |
| TREE-04 | 트리 이동 | 키보드·메뉴·드래그로 부모와 순서를 바꾼다. 자동 정렬 상태에서 수동 위치를 바꾸면 정렬을 전환할지 명확히 안내한다. |
| REL-01 | 검색으로 관련 메모 연결 | 제목·본문 검색 결과에서 연결 대상을 선택하고 확인 후 연결한다. 자기 연결·중복 연결은 만들지 않는다. |
| REL-02 | 드래그로 관련 메모 연결 | 관련 메모 영역에 떨어뜨린 경우에만 관계를 만든다. 트리 이동·캘린더 일정 변경과 동작을 구별한다. |
| REL-03 | 양방향 탐색 | A와 B의 관련 연결은 양쪽에서 보이며 한쪽에서 해제하면 함께 사라진다. 원본 메모는 삭제되지 않는다. |
| REL-04 | 백링크 구분 | 사용자가 설정한 관련 메모와 본문 속 메모 링크의 역참조를 구분해서 보여 준다. |

기본 범위에 외부 협업, 동시 사용자 편집, 인터넷 동기화, 노션 전체 블록 기능, 수식·롤업·DB 보드는 포함하지 않는다. 단, 편집 본문 형식은 이후 변환이 가능하도록 버전 정보를 갖는다.

## 3. 데이터 계약과 불변조건

### 3.1 메모

`Note(id, parent_id, title, body_doc, revision, created_at_utc, updated_at_utc, completed_at_utc, trashed_at_utc, sort_key)`를 논리 계약으로 사용한다. 실제 테이블·파일 구조는 기존 저장소 분석 후 정한다.

v1.3 추가 필드 collection_state·workflow_status·source_kind와 CheckItem은 [02](02-data-states.md)가 기준이다. 수집·진행·완료·부모·라벨은 별개이며 상태를 다른 메모로 암묵 전파하지 않는다.

- `id`: 내용·제목·위치와 독립적인 불변 ID. 복제하면 새 ID를 발급한다.
- `parent_id`: 루트는 null. 부모는 현재 작업공간에 존재해야 하며 자기 ID와 같을 수 없다.
- `body_doc`: 버전이 붙은 문서 구조. 허용 노드, 링크, 자산 참조만 포함한다. 실행 가능한 스크립트나 임의 파일 경로를 본문에서 실행하지 않는다.
- `revision`: 내용·부모·정렬·완료 등 메모의 영속 상태가 실제 변경될 때 증가하는 정수. UI 이벤트를 보냈다는 이유로 증가시키지 않는다.
- `created_at_utc`: 생성 시 확정하고 일반 편집에서는 변경하지 않는다. 이전 데이터의 시각을 복원하는 마이그레이션은 별도 이력으로 구별한다.
- `updated_at_utc`: 성공한 변경의 저장 시각. 창을 열거나 단순 검색한 때에는 변경하지 않는다.
- `completed_at_utc`: null이면 미완료. 메모 완료는 자식 완료나 일정 삭제를 암묵적으로 의미하지 않는다.
- `trashed_at_utc`: 휴지통 이동 여부. 영구 삭제와 구별한다.
- `sort_key`: 수동 정렬용. 화면 정렬 기준 변경이 실제 부모 관계나 생성시각을 바꾸지 않는다.

시스템 시계는 변경될 수 있으므로 변경 순서와 충돌 판정에 `updated_at_utc`만 사용하지 않는다. `revision` 및 저장소의 트랜잭션 순서를 사용한다.

### 3.2 관계 및 본문 링크

관련 메모는 `Relation(note_a_id, note_b_id, created_at_utc)` 같은 논리 레코드로 둔다. 두 ID를 정규화한 순서로 저장하고 이 쌍에 고유 제약을 둔다. 관련 관계는 방향 없는 하나의 연결이며 부모 관계와 무관하다.

본문 메모 링크는 표시 제목과 별도로 대상 `note_id`를 갖는다. 메모 제목을 바꾸어도 링크가 끊기지 않는다. 역참조는 본문 링크에서 만든 파생 인덱스이며 관련 연결 테이블을 임의로 늘리지 않는다. 대상이 휴지통이면 상태를 보여 주고, 영구 삭제되었으면 `삭제된 메모`로 남겨 원래 본문 구조를 유지한다.

여러 작업공간을 지원한다면 ID만으로 다른 작업공간의 데이터를 열지 않는다. 현재 범위에서는 한 사용자·한 로컬 작업공간을 기본으로 하고 작업공간 간 연결은 보류한다.

### 3.3 이미지·일반 링크

이미지는 본문에 거대한 인라인 문자열을 반복 저장하는 대신 관리 자산 ID를 참조하는 방안을 우선 검토한다. 원본 자산, 썸네일, 메모별 참조를 구별한다. 동일 이미지 재사용 시 다른 메모의 이미지가 함께 삭제되지 않도록 참조 관계로 수명을 판단한다.

- 허용 이미지 형식·최대 바이트·최대 픽셀 수·디코딩 자원 한도를 사내 정책과 실측으로 확정한다.
- 삽입 전 임시 영역에서 형식·크기·디코딩 가능 여부를 검증한다. 파일 확장자만 믿지 않는다.
- 원본 보관 허용 여부와 메타데이터 보존 여부를 확인한다. 파생 썸네일도 민감 데이터로 취급한다.
- 링크는 텍스트와 목적지를 각각 보관한다. `https`, `http` 등 승인된 스킴만 연다. `javascript`, 실행 파일, 임의 명령 실행은 차단한다.
- 사내 경로 링크는 보안 정책에서 허용한 범위에 한해 지원한다. 경로가 저장되어 있다는 이유로 파일을 자동 열지 않는다.
- PDF/PPT/Excel은 보안 락을 우회해 이미지·텍스트로 추출하지 않는다. 허용되지 않은 열람은 설명 가능한 상태로 표시한다.

## 4. 화면·조작 상세

### 4.1 기본 편집

메모 상단에 제목, 생성시각, 수정시각, 완료, 일정, 저장 상태를 배치한다. 본문에는 텍스트, 기본 강조, 번호/기호 문단, 링크, 이미지, 편집 가능한 표를 제공한다. `/` 메뉴와 노션 전체 블록 기능은 기존 편집기의 확장성과 사용성 검증 이후 선택 기능으로 둔다. 표와 문단 metadata를 담는 안전한 문서 구조는 필수다.

제목 위에는 사용자 정의 라벨의 색띠와 이름을 보여준다. 라벨 생성·이름/색상 변경·추가/해제·대표 라벨 선택과 any/all·라벨 없음 필터를 제공한다. 한 개면 전체 띠, 여러 개면 대표 우선 분할 띠로 표시하고 색만으로 식별하지 않는다. 메모·분리 스티키·트리/목록·검색·달력이 같은 Label/NoteLabel을 조회한다. 세부 모델과 수용기준은 [10 즐겨찾기·라벨](10-bookmarks-labels.md)의 LABEL-01~08에 둔다.

본문 이미지에는 대체 텍스트와 캡션을 입력할 수 있게 한다. 링크는 키보드로 수정·제거할 수 있고 링크 주소를 열기 전에 확인할 수 있어야 한다. 자동 미리보기·웹사이트 제목 수집은 제공하지 않아 외부 연결 시도를 만들지 않는다.

일정 미설정과 종일 일정은 서로 다르다. 날짜만 입력한 경우 자정의 시간 일정으로 암묵 변환하지 않는다. 일정·알림의 구체 의미는 [별도 창·캘린더·알림 계획](04-desktop-calendar-reminders.md)에 따른다.

### 4.1.1 본문 표와 표 모아보기

허용된 클립보드 표를 행·열·셀 구조로 붙여넣고 셀 내용·행열·직사각형 병합/분할을 편집한다. 제목/캡션·셀의 여러 문단·줄바꿈·링크·허용 이미지는 [11 표 계획](11-tables-collection.md)의 안전 노드 범위와 격자 검증을 따른다. 이미지로만 붙은 표를 편집 가능한 표로 속여 표시하거나 OCR로 추출하지 않는다. 보호된 파일을 열지 않고 사내에서 허용한 복사 데이터만 처리한다.

표 모아보기는 동일 body_doc의 table_id를 참조한다. 목록에서 열면 해당 메모의 같은 표로 이동한다. 모아보기에서 본문과 분리된 표 사본을 만들지 않는다. 표·셀의 변경은 Note revision·저장 실패·다중 창 충돌·실행취소 규칙을 그대로 적용한다. 표 내부 이미지·링크도 기존 모아보기에 포함한다.

### 4.1.2 기호와 2칸 문단 단계

기호를 문단 시작에서 입력하고 공백으로 확정하면 새 수동 기호는 기본적으로 직전 관련 문단보다 2칸 더 들어간다. 숫자/영문/로마자/한글·괄호·불릿 계열을 구별한다. Enter는 현재 단계에서 다음 번호·기호를 자동 입력하고, Shift+Tab은 2칸 내어쓴다. Enter로 넣은 빈 자동 기호 자리에 다른 기호를 직접 입력하면 하나로 교체하며 중복 번호를 남기지 않는다.

활성 상위 문단의 같은 계열 연속번호가 확인되면 그 상위 단계 정렬이 기본 추가 들여쓰기보다 우선한다. 예를 들어 다음처럼 입력한다. 아래 공백은 보기 위한 표시이며 실제 저장은 paragraph.outline metadata다.

```text
  1. 상위 항목                 ← level 1: 2칸
    a) 하위 항목               ← 수동 a): level 2, 4칸
    b)                         ← Enter: 같은 level 2, 4칸
  2. 다음 상위 항목            ← 자동 b)를 수동 2.로 교체: level 1, 2칸
```

상위 연속번호 근거가 없어 기본 규칙으로 4칸이 되었지만 2칸을 원하면 Shift+Tab으로 한 번 보정한다. 이 수동 보정은 즉시 재자동정렬하지 않고 다음 Enter도 보정된 단계를 유지한다. 문단 들여쓰기로 부모/자식 Note 구조를 바꾸지 않는다. 기호별 다음 값·로마자/영문 모호성·빈 문단·붙여넣기·IME·표 셀 키 우선순위는 [12](12-outline-indentation.md)의 OUTLINE-01~10을 따른다.

### 4.1.3 본문 체크리스트·수집함·진행 상태

본문·표 셀에서 작은 준비 항목을 CheckItem으로 만들고 개별 체크와 `3/5개 완료` 진행률을 표시한다. 항목은 자식 Note가 아니며 숫자 문단과 같은 문단에 이중 기호를 만들지 않는다. Enter는 같은 단계의 새 미체크 항목, 표 셀에서는 Tab/Shift+Tab 셀 이동 우선, Space는 체크박스 포커스에서만 토글한다. 전부 체크해도 메모·회차·자식을 자동 완료하지 않는다.

반복은 회차를 선택해 체크하고 첫 조작/완료 시 체크 항목만 snapshot으로 보존한다. 미시작 미래는 최신 템플릿·미체크, 이미 사용한 회차는 자기 항목·분모·체크 상태다. 회차를 선택하지 않은 원본은 체크리스트 템플릿 편집임을 표시한다. 전체 본문 버전 열람이 아니라 체크 운영 상태이며 메모별 변경 이력 화면을 만들지 않는다.

메모 헤더와 목록에 할 일/진행 중/회신 대기/보류를 표시한다. 완료는 별도 체크이며 마지막 진행 상태를 보존한다. 대기/보류가 일정·알림을 중단하지 않는다. 빠른 입력으로 만든 메모에는 미정리 표시·정리 완료를 제공하고 라벨/일정 입력만으로 수집함에서 제거하지 않는다. 상세 수집·체크 계약은 [13](13-capture-views-checklists.md), 상태는 [14](14-status-overlap-journal.md)를 따른다.

### 4.2 자동 저장과 창 간 동기화

편집기는 조합 중인 한글을 화면 초안에 유지한다. 짧은 입력 대기 후 저장을 시도하되 IME 조합 중인 텍스트의 중간 구조를 확정 본문으로 만들지 않는다. 창 닫기·포커스 이동·앱 종료 시 최종 조합 상태를 확정할 수 있는지 프레임워크별 검증이 필요하다.

명령 계약 예시는 다음과 같다.

```text
UpdateNote(note_id, expected_revision, patch, command_id)
MoveNote(note_id, new_parent_id, placement, expected_revision, command_id)
SetCompleted(note_id, completed, expected_revision, command_id)
AddRelation(note_id, other_note_id, command_id)
RemoveRelation(note_id, other_note_id, command_id)
```

모든 창은 같은 저장 조정자를 거쳐 명령을 보낸다. 저장 조정자는 트랜잭션에서 revision·부모 관계·권한·중복을 검증하고, 성공 후 새 revision 및 변경된 ID를 발행한다. 이벤트만 받고 저장이 완료되었다고 가정하지 않는다. 재전송된 같은 `command_id`는 부작용을 반복하지 않는다.

저장 성공 후 다른 창이 변경을 받으면 다음과 같이 처리한다.

| 해당 창 상태 | 외부 변경 처리 |
|---|---|
| 로컬 미저장 수정 없음 | 새 내용과 revision 적용. 선택·스크롤 위치는 가능한 한 유지한다. |
| 서로 다른 필드만 수정 | 지원 여부를 검증한 필드별 안전 병합만 수행하고 사용자에게 변경을 표시한다. |
| 같은 본문 또는 병합 불가 | 로컬 초안을 보존하고 충돌 화면 제공. `내 초안 보기`, `저장된 내용 보기`, `내용을 비교해 새로 저장`을 선택한다. |
| 메모가 휴지통으로 이동 | 초안이 있으면 복구 가능한 상태로 보존하고 편집을 중지한다. 임의 부활시키지 않는다. |

부모 창 A에서 수정한 뒤 늦게 도착한 창 B의 저장이 A를 덮어쓰는 현상은 반드시 재현 시험한다. 단순 마지막 저장 우선 정책은 기본안으로 채택하지 않는다.

### 4.3 무제한 중첩 트리

‘무제한’은 사용자가 정해진 5단·10단 제한 때문에 막히지 않는다는 의미다. 유한 메모리·화면·저장소의 한계까지 없다는 약속은 아니다. 실제 한도는 성능시험으로 공개한다.

왼쪽 트리뿐 아니라 메모 편집 화면과 분리 스티키에도 `자식 메모 추가`와 접이식 자식 목록을 제공한다. 자식 제목을 펼치면 해당 본문과 그 아래 자식 목록을 확인하고 다시 접을 수 있다. 자식은 독립 Note이며 본문에 내용 사본을 끼워 넣지 않는다. 별도 창으로 열거나 검색해도 같은 ID를 사용한다. 본문 편집기의 노드 안에 무한 문서를 통째로 중첩하지 않고 화면 조회·가상화 계층에서 필요한 자식만 표시한다.

- 트리 탐색·이동 검사·삭제·복원은 재귀 호출 스택에 의존하지 않는 반복 순회로 설계한다.
- 화면은 보이는 행 중심으로 가상화하고 자식을 필요할 때 불러온다. 전체 후손을 매번 렌더링하지 않는다.
- 깊어지면 들여쓰기 폭을 계속 늘리는 대신 깊이 표시·경로·현재 하위 트리 보기로 접근성을 유지한다.
- 이동 명령 시 목적지에서 조상으로 올라가 원본 ID가 나타나는지 검사한다. 도중 기존 순환이 발견되면 중단하고 진단 정보를 남긴다.
- 무결성 검사와 부모 변경은 하나의 저장 단위에서 실행한다. 두 창에서 A를 B 밑으로, B를 A 밑으로 동시에 옮기는 경우도 순환이 생기면 안 된다.
- 접기 상태는 메모 본문 revision을 바꾸지 않는다. 새 창에서 기본 펼침 정책과 기존 창 복원 정책을 구별한다.

### 4.4 부모·자식 완료와 삭제 정책

기본 정책은 메모마다 완료 상태를 독립 관리하는 것이다. 부모를 완료해도 자식은 남고, 자식을 모두 완료해도 부모는 자동 완료하지 않는다. 향후 일괄 완료를 넣는다면 변경 대상 수와 취소 기능을 제공한다.

정기 메모를 달력 회차에서 열면 해당 날짜와 ‘이번 회차 완료’가 보인다. 원본 메모의 ‘전체 완료·반복 중지’는 별도 명시 동작이다. 이번 회차를 완료해도 Note.completed_at_utc·다음 회차·다른 알림은 바꾸지 않는다. 원본 제목·본문·라벨 변경은 모든 회차가 공유하며 회차별 본문 사본이나 라벨 덮어쓰기는 만들지 않는다. [09](09-recurring-schedules.md)의 완료·예외·분할 규칙을 적용한다.

부모 메모를 휴지통으로 옮길 때 기본 동작은 하위 트리 전체 이동이다. 화면에 자식 수와 영향 범위를 보여 주고 작업 취소를 제공한다. 완료와 삭제는 다른 동작이다.

- 삭제 배치에는 이동 당시 원래 부모·순서·자식 구성 기록을 둔다.
- 복원 시 원래 부모가 살아 있으면 복원하고, 없으면 복구 루트로 옮기며 이유를 표시한다.
- 삭제 배치 이후 따로 복원·이동된 자식은 부모 복원 때문에 다시 덮어쓰지 않는다.
- 휴지통 메모의 일정·알림은 비활성 상태로 다루되 원래 설정은 복원용으로 유지한다. 복원 시 지연 알림이 무더기로 뜨지 않도록 확인 목록을 제공한다.
- 영구 삭제는 관련 연결과 자산 참조를 정리하지만 다른 살아 있는 메모가 쓰는 자산은 보존한다.

### 4.5 정렬 규칙

기본은 형제끼리 정렬한다. `전체 메모 평면 목록`은 별도 화면이며 트리를 재배치하지 않는다.

| 기준 | 기본 비교 | 동률·빈 값 |
|---|---|---|
| 수동 | `sort_key` | 마지막에 ID로 고정 |
| 생성시각 | 생성 UTC | 동률은 ID |
| 수정시각 | 수정 UTC | 동률은 생성시각, ID |
| 일정 | 표시 시간대의 시작 날짜·시간 | 미지정은 마지막. 종일과 시간 일정의 같은 날 순서를 명시한다. |
| 제목 | 한국어 정렬 규칙을 검증 후 고정 | 빈 제목은 마지막, 동률은 ID |

완료 메모를 아래로 보내는 옵션은 정렬 기준과 독립된 보조 옵션이다. 선택 중인 행이 저장 직후 이동해 입력을 방해하지 않도록 편집 중 화면 안정 정책을 둔다. 정렬 결과가 재실행마다 뒤집히지 않도록 안정적인 최종 비교키를 항상 둔다.

### 4.6 드래그 의미

| 떨어뜨리는 위치 | 결과 | 사용자에게 보여 줄 피드백 |
|---|---|---|
| 트리 행의 가운데 | 해당 메모의 자식으로 이동 | `하위 메모로 이동` 및 목적지 제목 |
| 트리 행 사이 | 형제 순서 변경 | 삽입선, 수동 정렬 필요 안내 |
| 관련 메모 영역 | 관련 연결 추가 | `관련 메모로 연결` |
| 본문 링크 삽입 영역 | 내부 메모 링크 삽입 | 링크 미리보기 |
| 캘린더 날짜·시간 칸 | 동일 메모의 일정 변경 | 목표 날짜·시간 |
| 허용되지 않은 영역 | 변경 없음 | 금지 표시와 이유 |

드래그 시작 시 원본 ID·작업공간 ID·세션 토큰을 보관한다. 외부에서 흉내 낸 문자열을 내부 메모 명령으로 실행하지 않는다. 드래그 도중 원본이 삭제되거나 목적지가 이동한 경우 드롭 시 다시 검증한다. Escape 취소·창 밖 드롭·중복 이벤트는 원상태를 보장한다.

관련 메모 연결은 드래그 외에 검색 대화상자와 키보드 메뉴를 반드시 제공한다. 검색 결과에는 제목, 경로, 일정, 휴지통 여부를 보여 동명 메모를 구별한다. 관계를 끊는 메뉴는 `연결 해제`로 표시해 메모 삭제와 혼동하지 않게 한다.

## 5. 상태기계

### 5.1 편집 상태

```text
clean --입력--> dirty --저장 요청--> saving --성공--> clean
saving --추가 입력--> saving + 후속 dirty 초안
saving --revision 불일치--> conflict
saving --저장 오류--> failed
failed --재시도--> saving
conflict --내용 확인 후 명령 재생성--> saving
dirty/failed/conflict --창 닫기--> 초안 보존 확인 또는 닫기 대기
```

저장 요청 중 추가 입력이 발생하면 요청 당시 스냅샷과 후속 초안을 구분한다. 이전 요청의 성공 응답이 도착했다는 이유로 새 초안까지 `clean` 처리하지 않는다. 응답에는 처리한 command ID와 revision을 포함한다.

### 5.2 메모 생명주기

```text
active.incomplete <--> active.completed
active.* --휴지통 이동--> trashed
trashed --복원--> active.(기존 완료 상태)
trashed --영구 삭제--> absent
```

휴지통은 편집·새 관계 연결·알림 실행 대상에서 제외한다. 완료는 본문 편집을 막지 않는다. 완료를 해제해도 기존에 확인한 알림을 다시 자동 실행하지 않는다.

| NOTE-A12 | 반복 회차 체크 후 템플릿 항목 추가·스티키 재열기 | 사용한 회차 분모·체크 보존, 다음 미시작 회차 미체크·새 템플릿 |
| TREE-A01 | 10,000단 깊이 시험 데이터 열기·검색·이동 | 스택 오버플로 없음. 가상화와 경로 이동으로 접근 가능 |
| TREE-A02 | A→B→C 구조에서 A를 C 밑으로 이동 | 저장 전 거부, 구조·정렬 그대로 |
| TREE-A03 | 두 창에서 서로 상대 밑으로 동시에 이동 | 한 작업만 유효하거나 둘 다 거부. 순환 없음 |
| TREE-A04 | 생성시각이 같은 100개 메모 정렬 후 재실행 | 순서가 동일하고 형제 범위가 유지됨 |
| TREE-A05 | 부모 삭제 후 일부 자식만 복원·이동하고 부모 복원 | 기존 복원 자식 이동이 덮어써지지 않고 복원 결과 설명 |
| TREE-A06 | 스티키 안에서 자식·손자를 만들고 본문 접기·펼치기 후 트리에서 열기 | 같은 ID·본문·부모 관계 유지, 접어도 삭제되지 않으며 깊은 자식에 접근 가능 |
| REL-A01 | A에서 B 연결 후 B에서 A 중복 드롭 | 단일 관계만 존재하고 양쪽 동일 표시 |
| REL-A02 | 관련 영역에 드롭, 이어 트리 영역에 같은 메모 드롭 | 전자는 연결만, 후자는 구조 이동만 수행 |
| REL-A03 | 대상 삭제 후 관련 목록·본문 링크 열기 | 삭제 상태 설명. 다른 메모를 잘못 열지 않음 |
| REL-A04 | 마우스 없이 관련 메모 검색·연결·해제 | 모든 기능 수행 가능, 포커스가 호출 위치로 복귀 |

10,000단·대량 메모 수치는 개발 스트레스 시험값이며 무제한 성능 보증이 아니다. 실제 배포 기준은 전체 시험 계획의 표준 장비·데이터 규모에서 측정해 확정한다.

## 8. 구현 순서와 완료 산출물

1. 기존 입력·저장·트리의 회귀 표본과 마이그레이션 표본을 확보한다.
2. 불변 ID·revision·명령 저장 경계를 먼저 도입하고 단일 화면에서 검증한다.
3. 본문 편집과 승인 이미지·링크의 안전 저장을 구현한다.
   표 붙여넣기·격자·셀 편집·모아보기는 11, 문단 기호·단계·키 라우팅은 12를 같은 본문 저장 경계에 연결한다. 기존 목록 플러그인과 중복 자동서식이 없는지 확인한다.
4. 순환 방지·가상화·정렬·삭제 복원까지 트리 작업을 완료한다.
5. 관련 검색·연결·내부 링크·백링크를 추가한다.
6. 동일 메모 다중 창과 캘린더 변경 이벤트를 연결한다.
7. IME·중복 이벤트·충돌·디스크 부족·심층 트리 회귀 시험을 통과한다.

완료 시 기능 시연 데이터, 명령 계약, 저장 형식 버전, 삭제·복원 정책, 위 수용기준 결과, 미해결 제한을 개발 기록에 남긴다.
