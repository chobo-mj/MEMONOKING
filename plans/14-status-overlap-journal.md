# 14. 진행 상태·일정 겹침 안내·하루 업무일지 초안

> 최신 범위: [23 프로젝트 단일 분류·아이콘 도구](23-projects-icon-toolbar.md)에 따라 라벨과 `LABEL-*` 계약은 폐기되었다. 이 문서의 라벨 모델·필터·시험은 과거 설계 참조이며 구현하지 않는다. 프로젝트와 메모 자체 색상, 위키/정리 폴더는 유지한다.

상위 계획: [plan.md](../plan.md) · 공통 모델: [02](02-data-states.md) · 캘린더·알림: [04](04-desktop-calendar-reminders.md) · 반복 회차: [09](09-recurring-schedules.md) · 빠른 입력·보기·체크리스트: [13](13-capture-views-checklists.md) · 통합 시험: [08](08-tests-acceptance.md)

문서 상태: v1.3 사용자 채택 기능의 상세 설계안. **진행 상태, 일정 겹침 안내, 사용자가 선택·편집하는 하루 업무일지 초안은 핵심 범위(P1)**다. 기존 코드·본문 형식·저장소·시간 처리·회사 보안 정책을 분석한 뒤 구현한다. 특정 기술 스택·캘린더 라이브러리·이벤트 저장 제품을 선정한 문서가 아니다.

**메모별 변경 이력 화면은 사용자 요청에 따라 제외한다.** 본문 이전 버전 보기·문장별 변경 비교·메모별 수정 타임라인은 만들지 않는다. 아래 최소 업무 이벤트는 하루 일지 후보를 만들기 위한 데이터이며 전체 편집 감시·본문 버전 보관이 아니다. 기존 백업·휴지통·실행취소·저장 실패 복구와 반복 완료/알림의 정상 운영 상태는 유지한다.

## 1. 목표와 선행 조사

진행 상태는 ‘내가 시작할 일’, ‘진행 중인 일’, ‘답변을 기다리는 일’, ‘잠시 보류한 일’을 구분한다. 시간 일정이 다른 일정과 겹치면 저장을 막지 않고 충돌 정보를 알려준다. 하루 일지는 그날의 생성·완료·일정 이동 후보를 모아 사용자가 필요한 항목만 고르고 문장을 다듬어 메모로 저장한다.

| 조사 대상 | 확인할 사실 | 착수 산출물 |
|---|---|---|
| 완료·분류 | 현재 완료 필드·상태 필드·라벨 의미, 완료 취소 동작 | 기존 상태→새 상태 대응표 |
| 반복 회차 | 정규 슬롯 identity·예외·분할·완료·알림 저장 구조 | 상태 범위와 회차 매핑 시제품 |
| 캘린더 | 시간 구간·종일·완료/휴지통 필터·월/주 조회 방식 | 겹침 기준 픽스처·조회 범위 계약 |
| 저장 명령 | 원자 커밋·명령 중복 방지·변경 작업 큐 | 최소 이벤트 기록의 내구성 경계 |
| 날짜·시각 | UTC·업무 시간대·PC 시계 변경·이전 데이터 미상 값 | 일지 날짜 경계·불확실 시각 처리표 |
| 보고 습관 | 일지 항목·표현·완료 회차 집계·보존기간 | 사용자 검토용 일지 예시 |
| 보안·운영 | 보고 메모·이벤트·초안·원본 링크의 보관/접근 정책 | 최소 수집·보존·복원 기준 |

운영 원본으로 실험하지 않는다. 승인된 익명 표본에서 상태 변경→일정 드래그→완료/취소→일지 후보→저장/재시작까지 검증한다. 현행 앱에 비슷한 기능이 있으면 재사용과 의미 보존을 먼저 검토한다.

## 3. 진행 상태의 의미와 모델

### 3.1 상태와 완료는 별개다

| 저장 값 | 사용자 표시 | 의미 |
|---|---|---|
| todo | 할 일 | 아직 시작하지 않았거나 다시 정리한 작업 |
| in_progress | 진행 중 | 현재 처리하고 있는 작업 |
| waiting | 회신 대기 | 다른 사람·부서의 답변이나 자료를 기다리는 작업 |
| on_hold | 보류 | 사용자가 잠시 진행을 멈춘 작업 |

위 값은 `workflow_status`다. 완료 여부는 기존 completed_at_utc가 담당한다. 완료된 작업은 화면에서 완료 표시·취소선과 함께 마지막 진행 상태를 보조 정보로 확인할 수 있다. `workflow_status=done`을 별도로 두어 timestamp와 충돌하게 하지 않는다.

일반 Note의 workflow_status는 기본 todo다. 완료 명령은 completed_at_utc를 설정하고 마지막 workflow_status를 보존한다. 완료 취소는 그 값을 다시 보여주며 과거 알림을 자동 부활시키지 않는다. 완료한 메모의 상태를 바꾸려면 완료 취소와 상태 변경을 명시적으로 수행하도록 한다.

라벨은 ‘보고서·정산·회의’ 같은 분류, 상태는 ‘진행 중·회신 대기’ 같은 진행 상황이다. 라벨 색띠와 상태 표식은 서로 다른 위치·문구로 표시한다. waiting/on_hold를 선택했다고 기한을 지우거나 알림을 자동 해제하지 않는다. 알림을 끄려면 기존 알림 설정에서 명시적으로 변경한다.

### 3.2 반복 일정의 범위

- Note.workflow_status는 원본 메모 전체의 진행 상태다.
- 반복 회차의 OccurrenceState.workflow_status는 해당 정규 슬롯 `(lineage_id, global_ordinal)`의 상태다. 상태 행이 없으면 그 회차의 기본은 todo다.
- 한 회차에서 waiting을 선택해도 다른 회차·Note 전체를 waiting으로 바꾸지 않는다. Note 전체의 값을 바꾸어도 저장되지 않은 미래 회차 상태를 묵시 변경하지 않는다.
- 달력 회차·그 회차에서 연 스티키는 실제 날짜와 ‘이번 회차 상태’를 표시한다. 전체 원본 화면의 상태 변경과 문구를 분리한다.
- 회차 완료는 그 회차의 completed_at_utc와 알림만 처리한다. 전체 Note 완료는 기존 전체 반복 중지 의미를 따른다.
- 이후 일정 분할은 정규 슬롯 identity를 유지하므로 workflow_status도 같은 슬롯에 남는다. 표시 날짜를 키로 삼아 다른 회차에 붙이지 않는다.

부모·자식 메모에 상태를 자동 전파하지 않는다. 일괄 상태 변경을 제공하면 선택한 범위와 영향 개수를 명시하며 각 대상의 revision을 검증한다. 이 기능은 업무 선행 의존 관계·자동 일정 재배치를 추가하지 않는다.

### 3.3 상태 명령·조회

```text
SetNoteWorkflowStatus(note_id, expected_note_revision, status, command_id)
SetOccurrenceWorkflowStatus(note_id, canonical_slot, expected_state_revision,
                            expected_schedule_revision, status, command_id)
```

실제 변경은 공통 명령 트랜잭션에서 확정한다. Note 상태 변경은 Note revision과 업무 수정시각을, 회차 상태 변경은 해당 OccurrenceState revision을 갱신한다. 후자는 Note의 본문 수정으로 위장하지 않되 저장 보기·캘린더 조회 캐시를 무효화한다.

체크 항목이 있는 회차의 첫 진행 상태 조작 또는 완료는 13의 ChecklistOccurrenceSnapshot도 같은 트랜잭션으로 확정한다. 읽기만 했다고 snapshot을 만들지 않으며 전체 본문 버전 저장으로 확장하지 않는다.

필터는 메모 목록의 ‘메모 상태’와 달력의 ‘회차 상태’를 구분한다. 저장 보기의 상태 필드도 이 범위를 포함하며 같은 이름의 상태 조건을 임의로 전환하지 않는다. 회신 대기·보류가 지연 기한과 함께 보일 수 있으며 완료·휴지통·라벨 조건과 AND로 결합한다. 상태 변경만으로 수집함의 정리 완료를 자동 처리하지 않는다.

## 4. 일정 겹침 탐지

### 4.1 판정 대상과 수학적 규칙

두 유효한 시간 일정 A=[startA,endA), B=[startB,endB)가 겹치는 조건은 다음과 같다.

```text
startA < endB AND endA > startB
```

따라서 09:00~10:00과 10:00~11:00은 겹치지 않는다. 09:00~10:00과 09:30~10:30은 겹친다. UTC 실제 시점으로 비교하고 사용자에게는 일정의 시간대 의미를 반영해 표시한다. 잘못된 구간·시간대 미확인 값은 사전 일정 검증에서 처리하며 겹침 없음으로 통과시키지 않는다.

초기 기본 검사 대상은 현재 사용자 저장소의 **활성·미완료·취소되지 않은 시간 일정**이다. 반복은 해당 회차의 완료 상태를 확인한다. 휴지통·취소된 회차·완료된 단발/회차는 기본 제외한다. 이 정책은 설정·안내에 표시하고, 완료 건 포함을 추가한다면 별도 옵션과 시험을 둔다.

종일 일정은 시간을 점유한다고 해석하지 않아 시간 겹침 경고 대상에서 제외한다. 필요하면 ‘이날 종일 일정 N건’ 같은 보조 표시를 할 수 있지만 이것을 시간 충돌이라고 부르지 않는다. 알림 시각, 링크, 생성시각, 표 안의 시간 문자열은 일정이 아니다. waiting/on_hold는 미완료이므로 시간 일정 검사에서 임의 제외하지 않는다.

### 4.2 반복·예외·자기 제외

반복 계산기는 규칙·예외·cutoff·별칭을 적용해 실제 구간을 만든다. 원래 월요일 슬롯을 수요일로 옮겼다면 원래 위치가 아니라 수요일의 구간을 검사한다. 조회 범위 밖에서 안으로 이동한 예외도 포함한다.

드래그하는 자기 항목은 안정 schedule_id 또는 정규 회차 키로 정확히 제외한다. 같은 Note라도 다른 반복 슬롯이면 서로 겹칠 수 있으므로 제외하지 않는다. 예외 적용 결과와 명목 항목이 중복 반환되면 정규 키로 합치되, 서로 다른 슬롯의 날짜·제목이 같다는 이유로 합치지 않는다.

‘이번 일정만’은 선택 건의 제안 구간을 검사한다. ‘이 날짜 이후 모두’는 09의 분할 미리보기 결과를 유한한 범위에서 펼쳐 검사하고 새 구간 사이의 겹침과 다른 일정과의 겹침을 모두 확인한다. 완료·과거 보존 예외와 successor 구간의 실제 날짜도 반영한다.

### 4.3 화면 필터와 검사 범위

현재 라벨·상태·저장 보기·검색 필터로 숨긴 일정도 같은 저장소의 허용된 범위에서 검사한다. 화면에 안 보인다는 이유로 겹침 없음으로 안내하지 않는다. 경고에는 제목/시간·원본 열기와 ‘현재 필터로 숨긴 일정 N건’을 함께 표시한다.

숨긴 일정을 확인할 때는 임시 강조 보기 또는 해당 원본을 열고, 사용자가 저장한 보기의 필터 자체를 덮어쓰지 않는다. 다른 사용자·작업공간의 데이터에 대한 검사·노출 권한을 새로 부여하지 않는다. 표준 단일 사용자 범위를 넘는 기능은 별도 설계다.

검사 horizon은 시작/끝 날짜와 시간대를 결과에 넣는다. 초기 제안은 선택 날짜 주변과 이후 30일을 기본으로 삼되 실제 반복 밀도·성능에 따라 S1에서 확정한다. 무종료 반복을 전부 검사했다고 표현하지 않는다. ‘검사한 기간에는 겹침 없음’, ‘더 먼 일정은 미검사’를 구별한다. 상한 때문에 일부 일정만 검사했으면 truncated/미검사 이유를 보이고 전체 안전을 보증하지 않는다.

### 4.4 비차단 경고와 경쟁 변경

드래그·시간 편집의 미리보기에서 겹침을 보여주고 `그대로 저장`과 `다시 조정`을 제공한다. 사용자가 알고 겹치는 업무를 등록할 수 있으므로 저장 거부·자동 이동·시간 단축을 기본으로 삼지 않는다. 최초 경고와 동일한 내용의 연속 팝업을 반복하지 않고 항목 표시·상세 패널을 이용한다.

```text
CheckScheduleOverlap(proposed_intervals, source_identity,
                     checked_range, source_revisions)
  -> conflicts, hidden_by_filter_count, checked_range,
     data_revision, truncated, status
```

미리보기 뒤 다른 일정이 바뀌면 확정 직전에 최신 범위를 다시 읽어 경고를 갱신한다. 저장 트랜잭션과 다른 일정의 동시 변경 사이에 전역적인 ‘겹침 없음’을 영구 보장할 수는 없다. 따라서 커밋 후 관련 일정 변경 이벤트에서도 겹침 표시를 재계산한다. 마지막 검사 이후 새로 생긴 겹침은 저장된 본문을 되돌리지 않고 새 경고로 알려준다.

조회 실패·취소·색인 지연은 `겹침 없음`이 아니다. `검사 중`, `검사하지 못함`, `범위 일부만 확인`을 구별한다. 경고 확인 기록을 저장한다면 일정 revision·검사 범위에 묶고 일정이 바뀌면 예전 확인으로 새 겹침을 숨기지 않는다. 저장 보기 전환이 경고를 지우는 원인이 되어서는 안 된다.

## 5. 하루 업무일지의 데이터 경계

### 5.1 최소 업무 이벤트

일지 후보는 저장소의 성공한 명령에서 아래 최소 사실만 기록하여 만든다. 원본 변경과 이벤트 기록은 같은 내구성 경계를 사용하고 재전송 command_id가 같은 이벤트를 중복 생성하지 않게 한다.

| event_type | 필요한 사실 | 기록하지 않는 내용 |
|---|---|---|
| created | Note ID, 생성 시각, 출처 종류, source revision | 타이핑 과정·클립보드 원문·화면 |
| completion_changed | Note/정규 회차 ID, 변경 시각, completed true/false | 본문 이전 버전·편집 전후 전문 |
| schedule_moved | Note/정규 회차 또는 범위 명령 ID, 변경 시각, 전/후 날짜·시각·범위 | 본문/표 내용 스냅샷·브라우저 활동 |

진행 상태의 모든 클릭을 새 이벤트 종류로 추가하지 않는다. 상태는 후보를 열었을 때 현재 정보로 보조 표시한다. 업무일지용 최소 사실과 기존 알림·체크리스트 운영 상태를 무제한 편집 감사 로그로 확장하지 않는다.

```text
ActivityEvent
  id, event_type, note_id, canonical_slot?, command_id
  occurred_at_utc, source_revision, occurrence_state_revision?
  safe_payload: completed? / old_interval? / new_interval? / move_scope?
  source_kind: normal | quick_capture | journal | migration

JournalDraft
  id, report_date, report_time_zone, source_watermark
  candidate_generation, selected_candidate_ids, editable_body_doc
  revision, state, saved_note_id?, created_at_utc, updated_at_utc

JournalSourceReference
  journal_note_id, source_note_id, canonical_slot?
  contributing_event_ids, saved_title_excerpt?, candidate_category

ActivityCoverage
  tracking_started_at_utc, retained_from_utc
  last_committed_watermark, known_gaps[]
```

본문 전문이나 과거 버전을 ActivityEvent에 넣지 않는다. 필요한 제목·설명은 후보 생성 시 현재 원본에서 읽고, 사용자가 확정한 보고 문장과 짧은 제목은 최종 일지 메모 자체의 내용으로 저장한다. 이는 보고서의 문장 보존이며 원본 메모의 버전 이력 서비스가 아니다.

이벤트는 확정 뒤 수정하지 않는 최소 사실로 취급한다. 잘못된 업무 상태를 되돌리면 반대 의미의 명령·이벤트로 기록하고 일지 후보에서 대조한다. 승인된 보존기간이 지나 정리할 때는 생성 가능 기간과 누락 범위를 안내한다. 과거 일지 메모는 원본 이벤트가 정리되어도 보고 문장을 유지한다. 이벤트가 없는 과거 기간을 추정해 채우지 않는다.

ActivityCoverage는 수집 시작·보존 시작·확정 watermark·확인된 누락 구간을 구별한다. 후보 응답에는 요청 날짜와 실제 확인 범위·완전성 상태를 담는다. 수집 이전이나 정리된 구간을 현재 Note.created_at/updated_at만으로 복원해 과거 일정 이동·완료 취소를 꾸미지 않는다. 구형 앱이 이벤트를 남기지 않고 수정한 구간 등 완전성을 확인할 수 없는 경우도 gap 또는 미확인 범위로 보고한다.

### 5.2 보고 날짜와 후보 범위

기본 보고 시간대는 Asia/Seoul이며 선택 날짜 D의 현지 00:00 이상 다음 날 00:00 미만에 일어난 이벤트를 조회한다. 실제 저장은 UTC이고 날짜 범위를 변환하여 조회한다. 일지 날짜는 **행동이 일어난 날**이며 원래 일정 날짜가 아니다. 예를 들어 내일 일정을 오늘 다음 주로 옮겼다면 오늘의 일정 이동 후보에 들어간다.

후보 구분은 `완료한 일`, `일정을 옮긴 일`, `새로 기록한 일`이다. 일정 이동을 무조건 ‘지연’이라고 부르지 않고 전/후 날짜를 보여 사용자가 표현을 바꾸게 한다. 빠른 메모 생성은 새로 기록한 일의 후보가 될 수 있지만 수집함의 모든 미정리 항목을 자동으로 보고서에 포함하지 않는다.

현재 화면의 라벨 필터가 일지 전체 범위를 몰래 제한하지 않게 한다. 기본은 해당 보고일의 허용된 활성 자료 전체이며, 사용자가 일지 범위에 라벨·상태를 따로 선택하면 칩과 포함/제외 개수를 보여준다. 휴지통·영구삭제 원본은 기본 후보에서 제외하고 제외 이유·건수만 안전하게 안내한다. 보존된 최종 일지 문장까지 원본 삭제 때문에 자동 지우지 않는다.

업그레이드·이전으로 가져온 옛 메모를 오늘 새로 만든 업무처럼 기록하지 않는다. 실제 신규 사용 명령부터 이벤트를 만들고, 이전자료를 이벤트로 변환하려면 명확한 원시 시각·작업 ID가 있을 때 별도 승인한 매핑을 적용한다. 시각 미상·이벤트가 없는 기간은 `자료 없음/완전성 미확인`으로 구별한다.

## 6. 후보 집계와 사용자 편집

### 6.1 완료 취소·반복·중복 규칙

하나의 논리 작업은 단발 Note ID 또는 반복의 `(lineage_id, global_ordinal)`로 식별한다. 원본 메모가 같다는 이유로 다른 날 회차의 완료를 하나로 합치지 않는다. alias 주소가 바뀌어도 같은 정규 슬롯이면 같은 작업이다.

- 같은 보고일에 완료→완료 취소를 했다면 완료 후보는 취소 상태로 표시하고 기본 완료 성과 집계에서 제외한다. 사용자가 ‘재검토로 미완료 전환’처럼 따로 기록할 수 있다.
- 완료→취소→재완료는 최종 유효 완료 1건으로 모으고 기여 이벤트 ID를 보존한다. 이벤트 개수를 성과 개수로 세지 않는다.
- 보고일 뒤에 원본 완료가 취소됐다면 과거 완료 사실 자체를 삭제하지 않고 후보에 `현재는 미완료`를 붙여 검토를 요구한다. 이미 저장한 일지를 자동 수정하지 않는다.
- 같은 회차의 일정 이동이 여러 번이면 최종 날짜와 이동 횟수를 표시하는 후보 1개로 묶고, 최초→최종 구간을 대조한다. 사용자 선택으로 필요한 중간 이동만 별도 문장으로 남길 수 있다.
- ‘이 날짜 이후 모두’ 이동은 무한 미래 회차 수만큼 후보를 만들지 않고 범위 이동 명령 1건으로 표시한다. 선택 경계·새 규칙·검사 범위를 보여준다.
- 새로 생성한 메모를 같은 날 완료하면 두 범주의 관련 항목을 묶어 보여주고 `작업 1개, 활동 2종`으로 구분한다. 요약 수에 같은 업무를 두 번 더하지 않는다.
- 체크리스트 한 항목 체크는 메모/회차 전체 완료와 다르다. 초기 일지 완료 후보는 전체 완료 명령만 사용하며 체크 개수는 사용자가 선택한 항목의 현재 보조 정보로만 쓴다.

일지 메모와 그 초안은 `source_kind=journal`로 표시하고 후보 수집 대상에서 제외한다. 일지를 생성·수정·완료했다고 다음 일지에 일지 자체가 업무로 계속 들어오는 재귀 증식을 막는다. 일반 메모로 명시 전환하는 기능을 추가하더라도 그 의미·포함 시점을 별도 안내한다.

### 6.2 작성 흐름

1. 사용자가 보고 날짜와 시간대를 확인하고 `업무일지 초안 만들기`를 실행한다.
2. 후보·원본 제목·현재 상태·일정 이동 전후·원본 열기를 표시한다. 아직 일지 Note를 자동 생성하지 않는다.
3. 사용자가 포함할 후보를 체크하고 제외·순서·분류를 조정한다. 기본 선택은 검토하기 쉬운 제안이며 자동 확정하지 않는다.
4. 선택된 후보를 일반 문단·목록으로 작성 가능한 초안에 넣는다. 사용자가 문장을 고치거나 내용을 추가할 수 있다. 생성 문구는 규칙 기반이며 외부 AI 호출은 없다.
5. 원본 메모·회차 링크와 저장 위치·라벨을 확인하고 `메모로 저장`을 실행한다. 실제 Note 생성과 출처 참조·저장 결과를 하나의 작업으로 확정한다.
6. 저장된 보고 메모는 일반 본문 편집·표·체크리스트·라벨 기능을 사용할 수 있다. 원본과의 관계는 링크이며 원본 본문이나 완료 상태를 대신 변경하지 않는다.

초안은 사용자 편집 영역과 새 후보 목록을 구별한다. `후보 새로고침`은 새 후보·변경 표시만 추가하고 사용자가 쓴 문장을 재생성 결과로 덮지 않는다. 이미 포함한 후보의 내용이 바뀌면 비교 가능한 안전한 요약을 보여 사용자가 교체·유지·제외하도록 한다. 이것은 현재 초안 검토이며 원본 메모 전체 이력 화면을 제공하는 기능이 아니다.

### 6.3 저장·재작성·원본 링크

같은 draft_id의 저장 재시도는 같은 saved_note_id를 반환한다. 응답이 끊겼다고 일지 메모를 두 번 만들지 않는다. 같은 날짜의 일지가 이미 있으면 `기존 일지 열기` 또는 `별도 초안 만들기`를 제안하고 조용히 덮어쓰지 않는다. 여러 보고 목적의 같은 날짜 일지는 명시적인 새 초안/사본 선택으로 허용한다.

보고 메모의 제목 예시는 ‘2026-11-08 업무일지’지만 제목은 ID·유일 키가 아니다. draft_id/저장 command_id가 멱등성 기준이며 report_date와 time_zone은 검색 메타데이터다. 보고 날짜 변경은 새로운 후보 범위에 대한 명시 새 초안으로 처리하고 기존 문장을 몰래 재귀속시키지 않는다.

원본 링크는 Note ID와 필요한 정규 회차 키를 쓴다. 제목이 바뀌어도 원본을 열고 분할 뒤 회차 주소는 alias로 해석한다. 원본이 휴지통/영구삭제라면 상태를 알려주고 같은 제목의 다른 메모로 연결하지 않는다. 최종 보고 문장은 저장 당시 사용자가 확정한 기록으로 남고 원본 제목 변경에 따라 보고 문구 전체를 자동 교체하지 않는다.

저장된 일지를 수정할 때도 Note revision 충돌을 검사한다. 오래된 초안을 다시 저장해 최신 수동 편집을 덮어쓰지 않는다. 원본에서 완료를 취소해도 저장된 일지를 자동 삭제·수정하지 않고 사용자가 새로고침/수정할 수 있게 한다.

```text
진행 상태:

  --명시 상태 변경--> 다른 active 상태
active.* --전체/해당 회차 완료--> completed(마지막 상태 보존)
completed --완료 취소--> active.(보존 상태)
휴지통은 위 상태와 독립이며 알림·편집 정책은 기존 규칙 적용

겹침 확인:
idle → checking(scope, revision) → clear / conflicts / partial
checking → failed / cancelled (겹침 없음으로 표시하지 않음)
clear/conflicts → source_changed → checking
conflicts --사용자 선택--> 조정 또는 그대로 저장

업무일지:
requested → collecting → candidates_ready → editing → saving → saved
collecting → partial / failed / cancelled
editing --후보 새로고침--> editing + new_candidates
saving → conflict / failed (편집 초안 보존)
saving 중단 → command 결과 확인 → saved 또는 안전 재시도
```

자료가 없다는 결과와 조회 실패·미수집 기간을 구별한다. 부분 후보이면 범위·이유를 알려주고 사용자가 수동 기록을 추가할 수 있다. 오래된 후보 응답이 새 날짜 선택·새 필터·새 초안을 덮지 않게 candidate_generation을 검사한다.

수집·반복 겹침·일지 저장은 취소 가능한 작업으로 구현한다. 큰 범위에서 UI가 무한 대기하지 않게 진행 상태·조회 상한·더 좁은 날짜 선택을 제공한다. 알림 전달과 일지 생성은 서로 실패를 전파하여 기능 전체를 막지 않는다.

## 8. 보안·이전·백업

메모·상태·이벤트·초안·보고 메모·원본 링크는 승인된 로컬 저장소에서 같은 권한·암호화·보존 정책을 따른다. 업무 이벤트를 외부 서버로 자동 전송하지 않는다. 화면·키 입력·클립보드·브라우저 방문을 감시하지 않으며 보고서 자동 발송·메일 전송 기능도 없다. 일지는 앱 내 메모로 저장하며 PDF/PPT/Excel 외부 프로그램 열람을 요구하지 않는다.

이벤트 safe_payload는 정해진 필드만 받고 본문·표·이미지·URL·인증정보가 임의 확장 필드로 섞이지 않게 검증한다. 업무일지 원본 링크는 내부 ID이며 외부 주소를 접속·해석하지 않는다. 로그에는 작업 종류·익명 ID·개수·오류·시간 정도만 남긴다.

이전 시 기존 미완료 데이터에 확인된 상태가 없으면 todo로 초기화한 사실을 대응표에 기록한다. 기존 ‘보류’ 등이 상태인지 라벨인지 불명확하면 원시값을 보존하고 매핑을 보류한다. 완료시각·생성시각·진행 상태를 임의로 위조하지 않는다. 새로운 최소 이벤트 수집 시작일 이전에는 완전한 일지 초안을 보장하지 않는다.

백업은 Note/OccurrenceState의 진행 상태, 최소 이벤트, JournalDraft의 사용자 편집, saved_note_id, 출처 대응과 저장 command 결과를 포함한다. 겹침 결과는 재생성 가능한 투영이므로 복원 후 다시 계산한다. 이벤트가 보존정책상 제외됐다면 후보 생성 가능한 날짜 범위를 명시한다. 일지 메모를 복원하는 데 과거 원본 메모의 이전 본문 버전은 필요 없다.

PC 교체·시간대 설정 변경 뒤 report_time_zone을 유지한다. 백업 시점의 후보/초안과 원본 revision이 다르면 재검토 상태로 열고 사용자의 편집을 자동 초기화하지 않는다. 실제 빈 시험 프로필에서 진행 상태·회차 상태·일지 문장·원본 링크·중복 방지를 대조한다.

## 10. 예상 버그와 개발 순서

| 위험 | 원인 | 예방·탐지 |
|---|---|---|
| 회신 대기가 완료로 보이거나 알림이 사라짐 | 상태·완료·알림을 한 값으로 처리 | 독립 필드·범위 명령·STATE-02/04 회귀 |
| 한 회차의 보류가 전 회차에 적용 | Note 상태와 회차 상태 혼합 | 정규 슬롯·헤더 범위·독립 기본값 |
| 맞닿은 일정도 충돌 | 종료 포함 비교 | 반열린 구간 fixture·경계 시험 |
| 필터를 켜면 겹침 경고가 사라짐 | 화면 조회를 검사 원본으로 재사용 | 필터 독립 조회·숨긴 일정 표시 |
| 반복 이동 뒤 옛 날짜 충돌 표시 | 명목 슬롯/예외 캐시 혼동 | 실제 구간 합성·정규 identity·revision |
| 일지 완료 건수가 두 배 | 이벤트·Note·회차 단위 혼합 | 논리 작업과 활동 종류 분리·최종 전이 집계 |
| 완료 취소했는데 계속 성과로 집계 | completed=true 이벤트만 보관 | false 전이 대조·당일 최종/현재 상태 표시 |
| 후보 새로고침이 사용자의 문장을 덮음 | 생성 결과와 편집 원본 혼합 | 후보 generation·편집 초안 분리·명시 병합 |
| 매일 일지가 다시 다음 일지에 쌓임 | 일지를 일반 이벤트 원본으로 수집 | source_kind 제외·재귀 회귀 |
| 일지 후보가 편집 감시/이력 화면으로 확대 | 이벤트 스키마 무제한 확장 | 최소 허용 필드·보존정책·제외 기능 인수 검사 |

개발 순서는 기존 상태/완료/시간 조회 분석 → 상태 범위와 저장 계약 → 단발 겹침 픽스처 → 반복 실제 구간·숨긴 일정·경쟁 변경 → 최소 이벤트의 원자 기록 → 날짜/완료 취소/회차 집계 → 사용자 선택·편집·멱등 저장 → 원본 링크·보고 메모 범위 → 실제 폐쇄망·접근성·이전/복원 시험이다.

초기 성능 표본은 상태 필터를 기존 메모 1만 건에 결합, 겹침은 명시 검사 기간의 실제 회차 1,000건, 일지는 하루 최소 이벤트 1,000개로 제안한다. 확정 상한·지연 목표는 [08](08-tests-acceptance.md)의 기준 PC·실제 분포에서 결정한다. 무한 반복 전체 검사나 모든 과거 일지 생성의 즉시 완료를 보장하지 않는다.

완료 산출물에는 진행 상태/완료/범위 사전, 겹침 정책·검사 범위·반열린 구간 픽스처, 최소 이벤트와 일지 후보 집계 규칙, 수동 편집/새로고침/중복 저장 계약, 제외된 메모별 이력 기능의 확인표, 이전·복구·모듈/통합 시험 결과를 포함한다.

## v1.4 후속 계약

완료 체크 순간의 시각과 사용자가 보정한 유효 완료 시각을 분리하고 유효 시각으로 일/월별 완료 내용을 조회한다. 자동 완료 목록과 사용자가 저장한 하루 일지 초안은 별개다. 상세 상태기계와 시각 보정·반복 발생 건 계약은 [15 확장 계획](15-layout-board-journal-shortcuts.md)을 적용한다.
