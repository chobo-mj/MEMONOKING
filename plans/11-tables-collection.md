# 11. 본문 표 붙여넣기·편집과 표 모아보기

> 최신 범위: [23 프로젝트 단일 분류·아이콘 도구](23-projects-icon-toolbar.md)에 따라 라벨과 `LABEL-*` 계약은 폐기되었다. 이 문서의 라벨 모델·필터·시험은 과거 설계 참조이며 구현하지 않는다. 프로젝트와 메모 자체 색상, 위키/정리 폴더는 유지한다.

상위 계획: [plan.md](../plan.md) · 공통 모델: [02](02-data-states.md) · 본문 편집: [03](03-notes-tree-relations.md) · 검색·모아보기: [05](05-search-media.md) · 보안: [06](06-holidays-security.md) · 통합 시험: [08](08-tests-acceptance.md)

문서 상태: 사용자 추가 요구를 반영한 v1.2 설계안. **메모 안의 편집 가능한 표와 표 모아보기는 핵심 범위(P1)**다. 먼저 기존 편집기·본문 직렬화·클립보드·사내 보안 정책을 조사한다. 특정 편집기, HTML 파서, UI 기술 또는 데이터베이스를 이미 채택한 계획이 아니다.

## 1. 목표와 기능 경계

허용된 클립보드의 표를 본문에 붙여넣고, 행·열·셀의 구조를 유지한 채 앱 안에서 수정한다. 표를 이미지로 바꾸어 붙이는 기능만으로 요구를 충족했다고 하지 않는다. 이미지 모아보기·하이퍼링크 모아보기와 나란히 **표 모아보기**를 제공하고, 목록에서 원래 메모의 해당 표로 이동한다.

표는 Note.body_doc 안의 원본 구성요소다. 별도 스프레드시트 파일이나 독립 업무 DB를 자동 생성하지 않는다. 수식 계산, 매크로, 외부 데이터 연결, Office 객체 포함, PDF/PPT/Excel 원본 열람·변환은 이번 범위에 없다. 셀 값이 `=SUM(...)`이나 `=HYPERLINK(...)`처럼 보여도 문자열로 보존하며 실행하지 않는다.

사내 보안 제품이 클립보드 복사를 허용한 자료만 입력한다. 사용자가 이미 복사한 일반 텍스트·표를 붙이는 동작과 보호 문서를 앱이 직접 열어 내용을 추출하는 동작은 다르다. 보호 문서 읽기, Office 자동화, OLE 객체 열기, 임시 파일 변환, OCR·캡처로 표를 얻는 경로를 만들지 않는다.

## 2. 기존 코드·환경의 선행 조사

| 확인 대상 | 조사할 사실 | 완료 증거 |
|---|---|---|
| 본문 편집기 | 표 노드·셀 선택·병합·줄바꿈·IME·실행취소 지원 여부 | 최소 표 저장·재열기 시제품 |
| 본문 형식 | 표·행·셀 ID, 문서 버전, 구형 앱의 미지원 노드 처리 | 구/신 문서 대응표와 호환성 차단 방안 |
| 붙여넣기 경계 | 앱이 읽는 클립보드 형식·HTML 처리·이미지 입력 경로 | 형식별 허용·차단·미지원 표 |
| 사내 정책 | 표 복사 허용, 보안 경고·읽기 거부, 임시 원문 보존 허용 | 실제 사내와 동등한 시험 PC 결과 |
| 데이터 분포 | 일반 행열 수, 큰 셀, 병합, 다문단·한글·링크·이미지 | 승인된 익명 표본과 스트레스 데이터 |
| 검색·색인 | 본문 노드 순회·원문 anchor·revision 갱신 구조 | 표 텍스트 추출·원본 이동 시제품 |
| 화면 | 본창·스티키 크기, 가로 스크롤·확대·접근성 | 좁은 창·고대비·키보드 사용 결과 |

기존 편집기가 표를 지원한다는 사실만으로 보안·무손실 저장을 통과했다고 하지 않는다. 클립보드 입력부터 영속 저장·재시작·원본 위치 이동까지 확인한다.

## 4. 논리 데이터 모델

### 4.1 본문 원본

```text
TableBlock
  table_id: stable opaque ID
  caption, column_width_hints, header_row_count
  rows[]

TableRow
  row_id: stable opaque ID
  cells[]

TableCell
  cell_id: stable opaque ID
  rowspan, colspan
  blocks[]: paragraph/text/link/note_link/approved image references/check_item
  alignment and permitted presentation attributes

TableUsageIndex (derived)
  note_id, table_id, anchor, caption
  row_count, column_count, excerpt, indexed_note_revision
```

실제 저장 형식은 기존 코드 조사 후 확정한다. 원점 열 좌표와 병합이 덮는 격자는 행별 셀 순서·span에서 계산하는 검증/표시용 파생 정보다. 덮인 셀 위치마다 같은 본문을 중복 저장하지 않는다.

표·행·셀 ID는 표시 순서와 독립적이다. 행 삽입·열 너비 변경·캡션 수정으로 ID를 다시 만들지 않는다. 본문 안에서 표 위치를 옮기면 기존 ID를 유지하고, 표를 복사해 새 표를 만들면 표·행·셀·문단 ID를 새로 발급한다. 이미지 Asset 참조 재사용은 기존 자산 정책과 참조 수명 규칙을 따른다.

표 전체가 Note.body_doc에 속하므로 최종 수정 권한·충돌은 Note revision으로 확인한다. 이 모듈만의 별도 파일에 표를 저장해 본문과 독립 수정하지 않는다. 추가 table_revision을 도입하더라도 Note 원본 커밋과 일치해야 하며 초기 필수 계약은 아니다.

### 4.2 병합 셀과 격자 불변조건

표의 논리 너비를 column_count로 정하고 각 행의 셀 원점과 span을 점유 격자로 검증한다. span은 1 이상의 정수이며 마지막 행·열을 벗어나지 않는다. 같은 좌표를 두 셀이 점유하거나 병합 뒤 숨겨진 셀 값이 유실되는 상태는 거부한다.

- 병합 셀의 내용은 원점 셀이 소유하고 덮인 위치에 같은 값을 여러 번 저장하지 않는다.
- 직사각형 연속 영역만 병합한다. 떨어진 선택, 기존 병합을 일부만 가로지르는 선택은 거부하고 이유를 표시한다.
- 여러 셀을 병합할 때 내용은 행 우선 순서로 문단을 유지하여 합치는 결과를 보여준다. 조용히 좌상단 내용만 남기지 않는다.
- 분할 시 기존 내용은 원점 셀에 남기고 새 셀은 비운다는 기본 규칙을 표시한다. 실행취소로 정확히 원상 복구할 수 있어야 한다.
- 병합 셀을 관통하는 행·열 삭제는 영향받는 내용과 span 보정 결과를 안내하고 하나의 명령으로 적용한다.
- 유효한 병합을 지원할 수 없는 기존 편집기라면 S1에서 지원을 확장하거나 변환 미리보기·명시 선택 경로를 결정한다. 해당 제약을 숨긴 채 TABLE-02·03 완료로 표시하지 않는다.

초기 범위에서는 표 안에 다시 표를 넣지 않는다. 중첩 표 입력은 거부·보류 이유를 표시하거나 사용자가 검토한 변환안으로만 처리한다. 일반 텍스트 변환을 선택해도 원문 보관이 허용된 경로와 손실 설명을 제공하며 자동 평면화하지 않는다.

## 5. 붙여넣기 처리 순서

### 5.1 입력 형식과 선택

1. 붙여넣기 위치, 기대 Note revision, 편집 초안 스냅샷을 확보한다. IME 조합 중이라면 조합을 훼손하지 않는 경계에서 처리한다.
2. 읽기 권한·사내 정책·형식별 용량을 검사한다. 클립보드 보안 차단을 만나면 다른 형식·프로그램·임시 변환으로 우회하지 않고 기존 본문을 유지한다.
3. 허용 형식이 여럿이면 구조를 보존하는 HTML 표 → 명시적 탭 구분 텍스트 → 일반 텍스트 순으로 후보를 제안한다. 구조 해석 실패를 정책 차단과 구별한다.
4. HTML 형식은 비실행 파서에서 fragment 경계를 검증하고 필요한 table/row/cell/text/link 구조만 읽는다. 외부 URL, CSS, 이미지, 폰트, script, event, iframe, OLE 객체를 실행·조회하지 않는다.
5. 탭 구분 텍스트는 `표로 붙여넣기` 명령 또는 형식 선택 미리보기에서만 변환한다. 일반 문단의 탭·줄바꿈을 임의로 표로 바꾸지 않는다.
6. 행열·span·셀 내용·상한을 검증한 임시 TableBlock을 만든다. 표 수·행열·병합·제외된 서식·차단 이미지·변환 손실을 표시한다.
7. 사용자가 적용하면 새 ID와 자산 참조를 포함한 본문 변경을 한 명령으로 확정한다. 취소·실패는 원래 문서와 선택 위치를 유지한다.

HTML 파싱에 실패했지만 같은 클립보드에 허용된 일반 텍스트가 있으면 `텍스트로 붙여넣기`를 사용자가 명시 선택할 수 있다. 이것은 허용 형식 변환이지 보안 차단 우회가 아니다. 차단된 원본 내용을 다른 제공 형식으로 읽어 우회하는 경로와 혼동하지 않는다.

### 5.2 텍스트 표 변환 규칙

탭은 셀 경계, 조합 밖의 줄바꿈은 행 경계다. 인용 필드를 지원한다면 따옴표로 시작한 필드 안의 탭·줄바꿈을 셀 내용으로 유지하고 `""`를 따옴표 한 개로 해석하는 문법을 고정한다. 텍스트 입력이 실제로 이 문법을 사용하는지 미리보기에서 확인하며, 쉼표가 있다는 이유로 CSV로 추정하지 않는다.

행마다 열 수가 다르면 빈 셀 보충·오류 행 제외·텍스트 유지 중 결과를 명시한다. 기본은 최대 열 수까지 빈 셀을 보충하는 미리보기이며, 마지막 빈 셀·빈 행을 조용히 버리지 않는다. 긴 셀 안의 줄바꿈과 행 경계의 차이를 표시하여 사용자가 구조를 확인할 수 있게 한다.

일반 Excel/Word 등에서 **정책상 이미 허용된 클립보드 데이터**가 제공되면 같은 파이프라인으로 처리한다. 원본 파일을 열어 새 클립보드 형식을 만들거나 Office 자동화·보호 해제·원본 파일 추출을 수행하지 않는다. 수식·매크로·외부 연결은 데이터 구조에 가져오지 않는다.

### 5.3 이미지·링크·서식

링크는 표시 텍스트와 주소를 보존하되 실행 허용 정책은 기존 링크 모듈을 사용한다. 입력 과정에서 링크 목적지에 접속하지 않는다. 원격 이미지 URL은 다운로드하지 않고 차단된 자리와 대체 설명을 보여준다.

승인된 클립보드 이미지 또는 관리 Asset 참조가 있는 셀은 기존 staged 자산 준비·본문 참조 커밋 절차를 따른다. 새 이미지 파일 쓰기와 DB 커밋이 별도인 경우 복구 기록을 사용하며, 실패한 자산 때문에 빈 표를 저장하지 않는다.

열 너비·기본 정렬·머리행은 허용된 표현 속성으로 정규화한다. 임의 CSS·수식·실행 객체는 보존하지 않는다. 지원하지 않는 외부 서식은 제외 내역을 안내하고, 업무상 중요한 셀 내용·구조 손실은 확인 없이 진행하지 않는다.

## 6. 본문 표 편집과 키보드

셀을 클릭하면 해당 셀의 문단을 편집한다. 표 외곽 손잡이·메뉴로 표 선택, 행·열 추가/삭제, 표 삭제, 열 너비 조절, 머리행 지정, 셀 병합·분할을 수행한다. 본문 삭제와 표 구조 삭제를 명확히 구별하고 영향받는 셀 수·내용을 보존하는 실행취소를 제공한다.

표가 창보다 넓으면 표 영역에서 가로 스크롤하고, 최소 셀 폭을 유지한다. 좁은 스티키에서 전체 앱 레이아웃이 무한히 넓어지거나 본문이 화면 밖에 갇히지 않게 한다. 머리행·표 제목·행열 위치를 접근성 정보로 제공한다.

| 입력 | 표 안에서의 동작 |
|---|---|
| Tab | 다음 편집 가능한 셀로 이동; 마지막 셀에서는 행 추가 여부를 명시 설정으로 결정 |
| Shift+Tab | 이전 셀로 이동; 셀 문단 자동 내어쓰기보다 우선 |
| Enter | 같은 셀 안의 다음 문단. 목록 문단이면 [12 문단 규칙](12-outline-indentation.md)에 따른 같은 단계 다음 기호 |
| Shift+Enter | 같은 셀·같은 문단 안의 줄바꿈 |
| 셀 목록 내어쓰기 버튼 / Alt+Shift+Left | 해당 셀 문단만 2칸 내어쓰기; 표의 셀 이동과 구별 |
| 행·열 삭제 명령 | 선택 셀 범위와 병합 영향을 검증한 뒤 구조 삭제 |
| Undo / Redo | 표 입력·구조 변경·문단 자동 변환의 명령 단위 복구 |

표 셀 안의 문단 계층은 해당 셀에서만 계산한다. 다른 셀이나 표 밖의 `1.`을 상위 항목으로 검색하지 않는다. 자동 들여쓰기가 셀의 rowspan·colspan·행열 위치를 바꾸지 않는다. Shift+Tab의 셀 이동이 예상과 다르면 버튼·접근 가능한 단축키를 안내하고 문서 전체에서 동작을 하나로 오해하게 하지 않는다.

v1.3 CheckItem도 같은 셀 블록으로 지원한다. 체크박스 포커스의 Space만 토글하며 셀 본문 입력·IME Space를 가로채지 않는다. Enter는 같은 단계의 새 미체크 항목이고 Tab/Shift+Tab은 셀 이동 우선이다. 셀 이동·병합·복사 때 check_item_id/paragraph_id와 회차 snapshot 참조를 보존 또는 새 복사 ID로 매핑한다. 본문 표의 일반 텍스트 `[x]`를 자동 체크 구조로 추정하지 않는다. 체크/진행률·반복 운영 계약은 [13](13-capture-views-checklists.md)을 따른다.

## 7. 표 모아보기

이미지·하이퍼링크와 나란히 `표` 모아보기 탭을 추가한다. 각 항목은 표 제목/설명, 원본 메모 제목·경로·라벨, 행열 수, 셀 텍스트 일부, 수정시각과 원본 열기 명령을 제공한다. 캡션이 없으면 UI에서 `제목 없는 표`로 표시하며 원본 캡션을 임의 변경하지 않는다.

- 메모 하나에 표가 3개 있으면 표 항목은 3개다. 반복 캘린더 회차가 20개 보여도 같은 Note의 표를 20배 집계하지 않는다.
- 기본 목록은 활성 메모만 포함한다. 휴지통은 명시 필터에서만 보이고 완료·라벨·선택 가지·기간 필터는 기존 메모 검색 의미를 따른다.
- 클릭하면 note_id와 table_id를 이용해 정확한 본문 표로 이동·강조한다. 표 위에 문단을 추가하거나 표 순서를 바꾸어도 같은 ID로 찾는다.
- 이동 직전 원본 revision을 확인한다. 표가 삭제되었으면 최신 메모를 열고 삭제 상태를 설명하며 다른 표로 임의 이동하지 않는다.
- 목록의 캡션 수정·삭제는 원본 TableBlock 편집 명령이다. 파생 레코드만 수정하거나 본문 밖의 독립 사본을 만들지 않는다.
- 표 삭제는 해당 본문 표를 제거하는 동작이며 메모 삭제와 구별한다. 표가 쓰는 이미지·링크는 참조 수명 정책으로 정리한다.
- 미리보기는 작은 행열·텍스트 범위만 렌더링한다. 모든 표의 전체 셀과 이미지를 한꺼번에 읽어 메모리에 올리지 않는다.

## 8. 검색·파생 색인과 복구

표 내용은 행 우선·셀 원점 우선·셀 안 문단 순서로 검색 텍스트를 추출한다. 병합 셀 내용은 한 번만 추출한다. 셀 사이에는 검색 토큰 구분자를 넣되 원문 위치를 table_id/row_id/cell_id/paragraph anchor로 매핑한다. 옆 셀의 끝·시작 글자를 이어 붙여 존재하지 않는 단어를 만들지 않는다.

하이퍼링크 모아보기는 셀 내부 링크도 포함하고 이미지 모아보기는 셀 내부 Asset 참조도 포함한다. 원본 사용 위치에는 메모·표·셀 경로를 제공한다. 표 모아보기는 별도 TableUsageIndex를 쓰지만 본문이 유일한 원본이며 모든 색인은 재생성 가능하다.

본문 커밋과 색인 dirty 작업 기록은 같은 내구성 경계를 따른다. 표 색인에는 indexed_note_revision을 기록하고, 오래된 추출 결과가 최신 표를 덮어쓰지 못하게 한다. 전체 재색인은 새 generation을 완성한 뒤 전환하며 실패를 0개 표 정상 결과로 표시하지 않는다.

본문에서 표를 제거·휴지통 이동·복원하면 관련 모아보기·검색이 같은 정책으로 갱신된다. 색인이 손상되었다고 본문 표를 삭제하지 않는다. 표 원본이 손상된 경우에는 원시 문서·오류 위치를 승인된 복구 영역에 보존하고 미지원 또는 복구 필요 상태로 표시한다.

## 9. 상태기계와 명령 계약

```text
붙여넣기:
idle → permission_checked → decoding → parsed → validated → preview
preview → committing → committed
preview → cancelled (원본 불변)
permission/decoding/parsing/validation 실패 → rejected (이유·기존 문서 보존)
committing 중단 → 원본 또는 완전한 새 본문으로 복구

표 색인:
clean(N) → body committed N+1 → dirty → extracting → clean(N+1)
extracting 중 N+2 도착 → 오래된 결과 미적용·dirty(N+2)
실패 → retry/degraded (원본 불변)
```

```text
PreviewPasteTable(note_id, insertion_anchor, expected_note_revision, allowed_clipboard_payload)
  -> staged_table, structure_preview, losses, errors, preview_token
CommitPasteTable(note_id, expected_note_revision, preview_token, command_id)
EditTable(note_id, table_id, expected_note_revision, validated_patch, command_id)
NavigateToTable(note_id, table_id, expected_source_revision)
RebuildTableProjection(scope, expected_body_format_version)
```

미리보기 토큰은 원본 revision·삽입 위치·검증한 데이터 지문·정책 버전을 묶는다. 다른 창에서 본문을 수정하면 자동 덮어쓰지 않고 최신 위치에 다시 적용할 수 있도록 제안을 유지한다. 붙여넣기와 구조 변경은 실행취소 한 번으로 복구할 수 있는 의미 있는 작업 단위로 저장한다.

## 11. 예상 버그·상한·운영

| 위험 | 원인 | 예방·탐지 |
|---|---|---|
| 표가 그림이나 한 줄 텍스트가 됨 | 클립보드 형식 우선순위·구조 변환 손실 | 구조 미리보기·원본 비교·허용 HTML 우선 |
| 빈 셀·마지막 열 누락 | trim·빈 필드 제거 | 빈 행열 경계 fixture |
| 병합 뒤 숨은 값 유실 | 좌상단만 남기는 병합 | 영향 미리보기·문단 보존·Undo |
| 셀 번호가 엉뚱한 상위 수준을 찾음 | 문단 문맥을 표 밖까지 탐색 | 셀별 목록 스코프·12 규칙 회귀 |
| Shift+Tab이 셀 대신 목록을 이동 | 키 처리 우선순위 충돌 | 셀 이동 우선·명시 내어쓰기 동선 |
| 모아보기가 독립 사본으로 남음 | 파생 색인을 원본처럼 편집 | table_id 명령·본문 revision 추적 |
| 표 이동 뒤 원문 점프가 틀림 | 위치 인덱스만 영속 저장 | 안정 table/cell ID·삭제 확인 |
| 원격 이미지·외부 객체가 열림 | HTML 렌더러/OLE 재사용 | 비실행 파서·허용 노드·무접속 시험 |
| 큰 표가 앱을 멈춤 | 전체 셀 렌더·병합 점유 폭발 | 바이트·행열·셀수·span·시간 한도 |
| 구형 앱이 새 표를 삭제 | 미지원 노드 무시 저장 | 본문 버전·호환 검사·쓰기 차단 |

초기 스트레스 자료는 표 200개가 있는 메모 집합, 일반 표 20×10, 큰 표 1,000×30, 큰 셀·복수 병합·한글·링크·이미지를 포함하는 안으로 제안한다. 이 수치는 지원 상한이나 성능 보장이 아니다. 실제 입력 바이트·행열·전체 셀수·문단수·픽셀·span 한도와 최소 PC를 S1·실기기 측정으로 확정한다. 1,000×30 표 하나를 화면 전체에 즉시 렌더링해야 한다는 요구가 아니라, 거부·지연 로딩·취소·복구가 안전한지 확인하는 자료다.

백업에는 body_doc·본문 버전·안정 ID·사용 Asset을 포함한다. 표 색인은 재생성 가능하므로 제외할 수 있지만 제외 목록과 재생성 절차를 명시한다. 보안상 클립보드 원문 보관이 금지되면 진단을 위해 통째로 남기지 않는다. 로그에는 행열 수·작업 ID·오류 종류만 기본 기록한다.

## 12. 개발 순서와 인수 산출물

1. 기존 본문·표·클립보드·보안 정책 조사와 승인 표본 확보.
2. Table/Row/Cell 노드·격자 검증·문서 버전·무손실 직렬화 설계.
3. 비실행 HTML·명시 탭 구분 텍스트의 읽기 전용 미리보기 구현.
4. 표 붙여넣기·셀 편집·행열·병합·분할·Undo와 자산 안전 커밋 연결.
5. 셀 문단과 [12 자동 번호·들여쓰기](12-outline-indentation.md)의 키 우선순위 통합.
6. 셀 텍스트·링크·이미지 추출과 TableUsageIndex·모아보기·원본 이동 구현.
7. 다중 창·중단·큰 표·IME·정책 차단·무접속·접근성 시험.
8. 구형 데이터 이전·새 버전 호환 차단·빈 위치 복원으로 원본 대조.

완료 산출물은 표 스키마·본문 버전, 허용 붙여넣기 형식·손실 안내, 격자 검증·편집 명령·키보드 계약, 표 색인 재생성 절차, 실제 보안 PC 입력 결과, 모듈·통합 시험 결과와 알려진 상한이다.
