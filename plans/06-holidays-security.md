# 06. 한국 공휴일 오프라인 데이터와 폐쇄망 보안

> 문서 상태: 기존 코드·사내 정책 분석 전의 설계안. 기술 스택, 보안 제품 연동, 암호화 방식, 업데이트 반입 절차는 확인 후 결정한다. 이 문서는 현재 공휴일의 법적 목록을 확정하는 문서가 아니며, 실제 반입 시점의 공식 자료로 데이터를 검증해야 한다.

## 1. 운영 원칙

프로그램의 메모·검색·이미지·캘린더·알림·공휴일 표시는 인터넷이 없는 상태에서 모두 동작해야 한다. 공휴일은 앱에 포함한 검증 데이터와 승인된 오프라인 갱신으로 제공한다. 실제 운용 PC에서 웹 크롤링이나 API 호출을 시도하지 않는다.

즐겨찾기 HTML 가져오기·미리보기·검색도 완전 오프라인이다. 사용자 명시 클릭에 따른 허용 URL의 Chrome/Edge 실행은 별도 허용 동작이며, 실행 후 브라우저의 접근은 사내 네트워크 정책에 따른다. 자동 백그라운드 통신 금지와 명시적인 링크 열기를 구별한다. 앱이 URL 사전 검사·파비콘 수집·연결 테스트를 먼저 수행하지 않는다. [10](10-bookmarks-labels.md)의 비실행 HTML 파서·고정 브라우저 실행·URL 허용 정책을 적용한다.

미래에 지정될 임시공휴일, 선거 일정 변경, 법령 개정은 현재 반입된 자료만으로 미리 알 수 없다. 따라서 “영구히 정확한 공휴일 자동 계산”을 약속하지 않고 **지원 연도·확인 기준일·출처·버전**을 표시한다. 검증 범위 밖은 빈칸을 정상 데이터처럼 표시하지 않고 “해당 연도 공휴일 미검증”으로 안내한다.

보안 락으로 PDF/PPT/Excel을 읽을 수 없는 조건을 우회하지 않는다. 임의 변환기, OCR, 캡처, 다른 뷰어, Office 자동화, 보안 에이전트 종료, 확장자 변경 등으로 보호 파일의 내용을 읽는 기능을 설계하지 않는다.

표 붙여넣기는 조직이 허용한 클립보드 HTML/텍스트만 처리한다. 파일 읽기 권한이 없다는 이유로 Office/OLE를 실행해 데이터를 대신 추출하거나 클립보드 차단을 우회하지 않는다. 승인된 앱에서 복사된 표 데이터의 저장·재복제도 허용되는지 조사한다. HTML은 비실행 파싱하고 표의 수식·매크로·스타일·외부 링크·원격 이미지·외부 entity를 실행/접속하지 않는다. 새 표/문단 본문·실행취소·표 발췌 색인·클립보드 준비물도 원본과 동일한 보관·권한 정책을 적용한다. 상세는 [11](11-tables-collection.md)과 [12](12-outline-indentation.md)를 따른다.

## 3. 기존 환경에서 먼저 확인할 사항

| 확인 대상 | 조사 내용 | 결정에 미치는 영향 |
|---|---|---|
| 기존 앱 | 언어·UI·DB·편집기·배포·서명·자동 업데이트·파일 저장 위치 | 유지/확장 범위와 마이그레이션 경로 |
| Windows 환경 | 지원 버전, 표준계정 실행, 앱 허용목록, 설치 권한 | 패키징·창 제어·알림 구현 |
| 보안 프로그램 | 파일 종류별 읽기/복사/클립보드/캡처/썸네일 정책 | 이미지 삽입과 기존 첨부 이전의 허용 범위 |
| 반입 정책 | USB/공유폴더/내부 배포 채널, 검사·승인 주체 | 공휴일·앱 업데이트 전달 방식 |
| 저장 정책 | 허용 로컬 경로, 암호화·백업·휴지통·보존기간 | 저장소·캐시·실행취소·삭제 설계 |
| 계정/로그인 | 공유 PC 여부, 로컬 계정·도메인 정책 | 사용자별 데이터 격리·잠금화면 개인정보 |
| 기존 라이브러리 | 외부 통신, 라이선스, 런타임 다운로드, 오픈소스 승인 | 오프라인 번들·대체·도입 여부 |

정책이 불명확한 파일은 허용으로 간주하지 않는다. 사용자에게 “지원되지 않는 파일 형식”, “현재 권한으로 읽을 수 없음”, “조직 정책상 차단됨”을 가능한 범위에서 구분해 설명한다. 차단 이유를 알 수 없으면 확정적으로 추측하지 않는다.

## 4. 공휴일 데이터 설계

### 4.1 데이터 공급 모델

1. 인터넷 사용이 허용된 별도 환경에서 공식 자료를 수집한다. 운용 앱에는 수집기·API 인증키를 넣지 않는다.
2. 검증 담당자가 연도별 날짜, 명칭, 공휴일 유형, 근거와 확인 기준일을 검토한다.
3. 날짜가 확정된 목록을 작은 데이터 전용 패키지로 만든다. 실행파일·스크립트·매크로·원격 리소스를 포함하지 않는다.
4. 조직의 반입·악성코드 검사·승인을 거쳐 전달한다.
5. 운용 앱에서 검증 결과와 변경 미리보기를 확인한 뒤 활성화한다.

데이터 패키지는 앱 설치본에 기본 포함할 수 있다. 최초 지원 연도 범위는 예를 들어 “기존 메모가 있는 가장 이른 연도부터 배포 후 2년까지”로 협의하되, 실제로 공식 확인한 연도만 `verified`로 표시한다. 10년치를 넣었다는 이유만으로 모든 연도가 확정 상태가 되지는 않는다.

### 4.2 데이터 구조

```json
{
  "schema_version": 1,
  "package_id": "kr-holidays-YYYY-NNN",
  "dataset_version": "YYYY.N",
  "region": "KR",
  "calendar_system": "gregorian",
  "verified_as_of": "YYYY-MM-DD",
  "supported_years": ["YYYY"],
  "year_status": {"YYYY": "verified"},
  "source_refs": [
    {"id": "src-1", "title": "공식 자료 제목", "url": "https://official.example/record", "retrieved_on": "YYYY-MM-DD"}
  ],
  "entries_file": "holidays.json",
  "file_hashes": {"holidays.json": "sha256-value"},
  "signing_key_id": "organization-approved-key-id"
}
```

위 JSON은 `manifest.json` 구조를 설명하는 예시이며 실제 날짜·출처·해시를 제공하는 배포 패키지가 아니다. `holidays.json`에는 다음 형태의 레코드 배열을 저장한다. `manifest.json`의 원본 바이트에 대한 분리서명은 `manifest.sig`로 보관하고, 서명 검증 후 manifest에 기록된 데이터 파일 해시를 검사한다. manifest 자체의 해시를 자기 내부에 넣지 않는다. 실제 스키마는 enum 값, 최대 길이, 허용 연도, 필수 필드, 서명 대상 바이트를 별도로 고정한다.

```json
[
  {
    "id": "stable-entry-id",
    "date": "YYYY-MM-DD",
    "name": "공휴일 명칭",
    "type": "national",
    "status": "confirmed",
    "source_ref_ids": ["src-1"],
    "substitutes_for": []
  }
]
```

`type` 허용값은 `national`, `substitute`, `temporary`, `election`으로 고정하는 안이다. `status`는 `confirmed` 또는 `provisional`을 명시하며, 미확정 항목은 확정 자료와 별도 레이어로 취급한다.

- `date`는 한국의 민간 달력 날짜 문자열이다. UTC 자정 타임스탬프로 저장하지 않는다.
- 동일 날짜에 여러 사유가 있을 수 있으므로 date 하나를 유일키로 만들지 않는다. 목록에서는 배지를 합쳐 보여줘도 근거 항목은 보존한다.
- 정규 공휴일, 대체공휴일, 임시공휴일, 선거 관련 지정일을 구분한다. `provisional` 자료는 확정 목록과 분리하여 “예정/미확정”으로만 표시한다.
- 모든 일요일을 별도 원본 레코드로 대량 생성할지는 UI 요구에 따라 결정한다. 주말 색상과 공식 공휴일 이름은 구분한다.
- 근로자의 날, 지방별 휴무, 기관별 창립기념일, 휴가 등은 적용 범위가 다르므로 현재 법령/정책을 확인하고 별도 레이어로 관리한다. 모든 사용자에게 동일한 공식 공휴일이라고 단정하지 않는다.
- 회사 휴무는 `OrganizationDayOff`에, 개인 휴무는 `PersonalCalendarMarker`에 저장한다. 국가 데이터 갱신이 이들을 덮어쓰지 않는다.

### 4.3 음력과 대체공휴일

음력 변환과 공휴일 적용 규칙을 앱에서 즉석 계산하는 방식을 초기 기본안으로 삼지 않는다. 한국 음양력의 공식 날짜 자료와 공휴일 지정 자료를 확인한 뒤 연도별 확정 양력 날짜를 패키지에 포함한다.

규칙 기반 생성기를 나중에 사용하더라도 다음을 지켜야 한다.

- 음력 날짜 변환과 법령상 휴일 부여 규칙은 분리한다. 음력이 정확하다고 대체공휴일도 정확한 것은 아니다.
- 법령 규칙에는 시행일과 적용 연도 범위를 둔다. 최신 규칙을 과거 연도 전체에 소급 적용하지 않는다.
- 휴일 중첩, 토/일요일 조건, 연속 명절, 여러 대체 사유, 다른 공휴일과의 충돌을 날짜 집합으로 검증한다.
- “일요일이면 다음 월요일” 같은 일반화로 구현하지 않는다. 다음 날짜가 이미 공휴일일 수 있다.
- 생성 결과를 공식 확정 목록과 독립 비교하고, 불일치는 수동 검토 전까지 배포하지 않는다.
- 임시공휴일·선거 지정은 일반 달력 규칙만으로 추정 확정하지 않는다.

## 5. 오프라인 가져오기·갱신·복구

### 5.1 상태기계

```text
미설치 → 기본 패키지 검증 → active(version A)

새 파일 선택 → staged
  → 크기/경로/스키마/서명/버전 검증 → validated
  → 차이 미리보기 → 적용 명령 → activating
  → 원자적 active 포인터/트랜잭션 전환 → active(version B)

검증 실패 → rejected (기존 active A 유지)
activating 중단 → 시작 시 저널 검사 → 완전한 A 또는 B 복구
active B 문제 확인 → 이전 검증본 A로 복구 (사용자 일정은 변경하지 않음)
```

### 5.2 검사 항목

- 데이터 파일 크기·레코드 수·문자 길이 상한, 정확한 날짜 형식, 윤년/월말 유효성, 필수 필드, 고유 ID, 알 수 없는 필드 처리 정책을 검사한다.
- ZIP 같은 압축 패키지를 사용하면 경로 이탈·절대경로·중첩 압축·압축폭탄·심볼릭 링크를 거부한다. 단일 JSON+분리서명 형식이 운영상 더 단순하면 그것을 우선 검토한다.
- 해시는 전송 중 손상 탐지에 사용한다. 패키지 안에 함께 들어 있는 해시만으로 제작자 신뢰성을 증명할 수 없다.
- 제작자 인증은 조직이 승인한 전자서명과 앱에 배포한 신뢰 키 또는 이에 준하는 승인 절차로 검증한다. 서명 개인키를 앱에 포함하지 않는다.
- 서명 인증서의 온라인 확인이 불가능한 환경을 고려해 키 유효기간·폐기/교체 목록·오프라인 신뢰 갱신 절차를 정한다. 자체 암호 알고리즘을 만들지 않는다.
- 패키지에 임의 공개키가 포함되어 있어도 자동 신뢰하지 않는다. 신뢰 키 갱신은 별도의 승인 경로를 거친다.
- 하위 버전의 무심코 덮어쓰기를 막는다. 복구 목적의 롤백은 명시적 작업과 이력으로 처리한다.
- 출처 URL은 문자열 메타데이터로만 저장한다. 가져오기 검증 과정에서 실제 접속하지 않는다.

### 5.3 적용 미리보기

현재/새 버전, 지원 연도, 확인 기준일, 추가·수정·삭제된 날짜, 명칭 변경, 미확정→확정 전환, 서명 검증 상태를 보여준다. 메모·일정·알림의 날짜는 공휴일 데이터 변경으로 자동 이동하지 않는다.

실제 적용은 하나의 명령으로 실행한다. 적용 중 창을 닫거나 앱이 중단되어도 부분 데이터가 활성화되면 안 된다. 캐시와 분리 캘린더는 공휴일 데이터 generation 변경을 구독하여 갱신한다.

### 5.4 수동 보정과 책임

- 일반 사용자의 수동 추가는 “개인 표시”로 저장하고 공식 데이터와 시각적으로 구분한다.
- 조직 검증자가 지정한 수동 보정은 근거, 확인일, 작성자 또는 승인 식별자, 적용 연도, 만료/재검토일을 기록한다.
- 패키지 갱신 시 수동 보정과 충돌하면 비교 화면을 제공한다. 조용히 덮어쓰거나 공식 자료를 개인 설정으로 숨기지 않는다.
- 연 1회 다음 연도 준비 점검과 정부 지정 변경 발생 시 별도 반입 절차를 운영 문서에 적는다. 앱이 인터넷을 확인하여 변경을 감지한다고 가정하지 않는다.

### 6.1 저장 보호와 암호화 검토

- 기본 저장 위치는 사용자별 앱 데이터의 승인된 경로다. 다른 계정이 읽을 수 있는 임시 폴더나 바탕화면에 DB를 기본 저장하지 않는다.
- ACL 등 운영체제 권한을 확인한다. “앱 안에서 비밀번호를 요구함”과 디스크의 실제 암호화를 구분한다.
- 암호화 필요 여부와 사용할 OS/조직 승인 기능은 기존 배포 환경을 분석한 뒤 결정한다. 사용자 계정에 묶인 키는 다른 PC 복구·계정 변경 시 문제가 될 수 있으므로 복구 시나리오를 함께 검증한다.
- DB만 암호화하고 이미지·썸네일·색인·백업이 평문인 상태를 보호 완료로 간주하지 않는다.
- 키 저장·백업·분실 시 복구 책임을 정한다. 실행파일에 공통 비밀키를 넣지 않는다.
- 파일 삭제가 디스크·백업의 완전 소거를 보장한다고 표현하지 않는다. 실제 보존·폐기 정책에 따른다.
- 잠금화면/다른 사용자 세션에서 알림이 본문을 노출하지 않도록 기본값을 제목 최소 표시 또는 내용 숨김으로 검토한다.

### 6.2 실행과 외부 리소스

- 앱은 표준계정으로 실행한다. 관리자 권한, Windows 서비스, 예약 작업은 명시적인 필요와 조직 승인 없이 기본 의존성으로 넣지 않는다.
- 편집기에 HTML/Markdown을 도입할 경우 스크립트·외부 리소스·임의 파일 접근·위험 URL을 차단한다. 사용자가 입력한 본문을 실행 코드로 취급하지 않는다.
- 웹 기반 UI 후보를 쓰더라도 런타임, 폰트, 아이콘, 편집기, 날짜 라이브러리를 오프라인 번들로 제공한다. 첫 실행 시 런타임 다운로드가 필요한지 실기기에서 검사한다.
- 의존성 목록·버전·라이선스·검증 해시·승인 상태를 남긴다. 보안 수정본도 오프라인 반입 경로가 있어야 한다.
- “인터넷 연결 실패 시 재시도” 코드가 주기적으로 네트워크를 두드리지 않게 한다. 운영 앱은 해당 코드 경로 자체를 비활성화한다.

### 6.3 v1.3 입력·보기·업무일지의 최소 수집

전역 빠른 입력은 허용된 단축키 등록과 명시 입력으로 구현하며 다른 앱의 키 입력·클립보드·화면·방문 기록을 상시 수집하지 않는다. 키 등록/상주가 제한된 환경은 버튼 대안과 실행 범위를 안내한다. 저장 보기는 제한된 자료형·연산자만 허용하고 SQL/스크립트·임의 경로를 실행하지 않는다.

체크 항목·회차 snapshot은 해당 업무의 상태·분모 보존에 한정한다. 업무일지의 ActivityEvent는 생성·완료 방향·일정 이동의 최소 필드만 보관하고 원문·URL·이미지·이전 본문 전문을 담지 않는다. 사용자 선택/편집 없이 보고서 확정·메일/메신저 전송·외부 AI 호출을 하지 않는다. 후보·초안·선택·보고 메모·체크 운영 상태도 동일 권한·암호화·보존·백업 정책을 적용한다. 사용자 제외 항목인 메모별 변경 이력 화면·본문 버전 비교/복원은 추가하지 않는다.

공휴일 기대값은 코드의 같은 계산기로 생성하지 않는다. 별도 검토한 공식 날짜표를 고정 픽스처로 두고, 데이터 버전과 확인자를 기록한다. 테스트에 쓸 가상 충돌 사례와 실제 연도 자료를 구분한다.

확장 보안 시험은 [08](08-tests-acceptance.md)·[09](09-recurring-schedules.md)·[10](10-bookmarks-labels.md)와 함께 수행한다. 특히 즐겨찾기 HTML의 script/event/img/base/meta refresh 차단, 특수문자 URL의 명령 인수 경계, 미설치·실행 차단·지정 브라우저 보존을 검증한다. 공휴일 데이터 갱신이 평일/주말 반복이나 라벨·즐겨찾기를 수정하지 않아야 한다. 네트워크 관측 시험에서는 앱의 자동 요청 0건과 사용자가 실행한 브라우저의 허용 접근을 별도 기록한다.

## 9. 공식 참조와 적용 범위

- [국가법령정보센터 — 관공서의 공휴일에 관한 규정](https://www.law.go.kr/법령/관공서의공휴일에관한규정): 데이터 검증 시 현행·과거 시행일의 규정을 확인하는 기준. 본 계획은 특정 시행본의 휴일 목록을 재현하지 않는다.
- [공공데이터포털 — 한국천문연구원 특일 정보](https://www.data.go.kr/data/15012690/openapi.do): 인터넷 허용 환경에서 공휴일 관련 공식 데이터를 확보할 때 검토할 출처. 운용 앱이 이 API에 접속한다는 의미는 아니다. 이 문서 작성 중 해당 상세 페이지의 본문 수집은 성공하지 않아 실제 필드·범위·최신성은 구현 착수 시 확인해야 한다.
- [국민참여입법센터 — 관공서의 공휴일에 관한 규정 입법진행 정보](https://opinion.lawmaking.go.kr/lmSts/govLm/2000000326106/detailRP?yType=I): 개정 과정이 존재함을 확인하는 참고. 입법예고·진행 정보만으로 확정 시행 법령이나 날짜를 판단하지 않는다.

확인 기준일: 2026-11-08. 공식 자료가 있더라도 배포 대상 연도의 완전성을 자동 보장하지 않는다. 실제 데이터 패키지의 검증 기록은 별도 산출물로 남긴다.
