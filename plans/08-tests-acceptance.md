# 08. 통합 수용기준·시험 전략·예상 버그

상위 계획: [plan.md](../plan.md). 공통 계약은 [02 데이터 모델·상태기계](02-data-states.md), 이전·복구 절차는 [07 이전·운영](07-migration-operations.md)을 따른다.

정기 일정은 [09](09-recurring-schedules.md), 즐겨찾기·라벨은 [10](10-bookmarks-labels.md)의 핵심 요구다. 세 기능을 후속 선택 기능으로 미루거나 기존 단발 일정 시험만으로 완료 처리하지 않는다.

v1.2의 표 붙여넣기·표 모아보기는 [11](11-tables-collection.md), 문단 기호·자동 들여쓰기는 [12](12-outline-indentation.md)를 따른다. 사용자가 확인한 Enter 동작은 **같은 들여쓰기 수준에서 다음 번호·기호 이어쓰기**이며, 매번 하위 수준으로 들어가는 동작이 아니다. 아래는 구현 후 실행할 수용 시나리오이며 현재 시험을 수행했다는 보고가 아니다.

v1.3의 빠른 메모·수집함·저장 보기·본문 체크리스트는 [13](13-capture-views-checklists.md), 진행 상태·일정 겹침·하루 업무일지 초안은 [14](14-status-overlap-journal.md)의 핵심 요구다. **메모별 변경 이력 열람/이전 본문 비교 화면은 사용자 요청으로 제외**한다. 실행취소·실패 초안·백업·복구, 회차 체크 상태·최소 업무 이벤트는 각 기능의 안전한 처리에 필요한 범위로 검증한다.

이 문서는 기능 구현이 끝났다는 판단 기준을 정의한다. 현재 코드와 대상 PC 사양을 확인하지 못했으므로 성능 수치는 초기 검증 목표이며 보장값이 아니다. 코드 분석 단계에서 기존 동작·버그·저장 지연·메모리 사용량을 먼저 측정하고, 대상 PC에서 합의한 기준으로 확정한다.

## 1. 시험 운영 원칙

- 요구사항 → 모듈 설계 → 수용 사례 → 회귀 시험 → 실행 증거를 연결한다. 문서에 기능이 있다는 이유만으로 통과 처리하지 않는다.
- 핵심 데이터 불변식은 자동 시험으로 검증한다. 배치·시계·파일 시스템·창 이벤트는 제어 가능한 경계로 분리해 실패 상황을 재현한다.
- 창 전면 표시, 한글 입력기, 다중 모니터, 보안 제품, 권한, 클립보드, 설치는 실제 Windows 환경에서 확인한다. 모의 환경의 성공만으로 대체하지 않는다.
- 시험 데이터는 생성 데이터 또는 승인된 익명화 자료를 사용한다. 보호 파일을 해제하거나 실제 업무 파일을 시험 도구로 강제 열지 않는다.
- 성능과 안정성은 구분한다. 빨리 저장되어도 내용이 유실되면 실패다. 오류를 탐지하고 복구 안내를 제공한 경우와 조용히 잘못된 결과를 표시한 경우도 구분한다.
- 수용기준 변경은 이유와 영향받는 시험을 기록한다. 시험 실패를 감추기 위해 예상값을 바꾸지 않는다.

| S15 상태·겹침·일지 | 상태/완료 조합, 숨긴/맞닿은/중복 시간 일정·반복 예외, 자정·다른 시간대의 생성/완료취소/이동 이벤트·일지 초안 | 상태 범위·half-open 교차·검사 범위·날짜별 후보·저장 멱등 |

S5는 승인된 이미지 포맷만 사용한다. 초기 표본은 100KiB급 이미지 700개, 2MiB급 250개, 10MiB급 50개 등으로 구성하되 최종 입력 한도·픽셀 수 한도는 대상 PC 검증 후 정한다. 압축 크기가 작아도 디코딩 후 메모리가 큰 이미지를 따로 포함한다. 이 표는 제품에서 무한 크기 파일을 지원한다는 뜻이 아니다.

S3의 100MiB 텍스트 기준과 S4의 긴 본문 스트레스 시험을 분리한다. S4·S5는 별도 추가 부하이며 S3 성능 수치에 묵시적으로 합치지 않는다. 통합 부하로 함께 시험한 결과는 합친 실제 용량·픽셀 수·자산 수를 별도로 보고한다.

S9는 우선 계열 100개·저장 예외 200개·조회 월의 실제 표시 발생 1,000개 이내를 기준으로 측정한다. 종료 없는 계열도 1개월 조회 때문에 전체 미래 행을 생성하면 실패다. 1,000계열·많은 예외는 별도 확장 부하로 구분한다. S10 실제 내보내기 표본에는 외부 접속이 필요 없는 승인 테스트 주소를 사용하고 개인정보·실제 사내 URL은 허가 없이 수집하지 않는다.

S11은 초기 성능 표본으로 일반 표 20×10, 단일 큰 표 200×20, 전체 표 1,000개를 각각 분리해 측정한다. 이 숫자는 지원 상한이나 보장값이 아니다. 최대 바이트·행·열·셀·병합 범위는 11의 정책·실기기 실측 후 확정하고 허용/거부 경계값을 포함한다. 클립보드 차단 표본은 보호 내용을 추출하지 않으며 조직이 허용한 데이터만 사용한다. S12는 깊이 성능과 문자 종류를 분리하고 원문·논리 level·가상 기호·커서 위치의 기대값을 독립 fixture로 둔다.

S13~S15는 각 기능의 단독 부하와 통합 부하를 구분한다. 일지 후보는 우선 최소 이벤트 10만 건 중 하루 범위를 조회하는 자료로 제안하며, 실제 보존기간·최대 건수는 코드 분석 후 정한다. 반복 체크 스냅샷은 실제 시작/완료한 회차만 유한하게 저장하고 끝없는 미래 전체를 만들지 않는다. 전역 키·포커스·OS 실행 정책은 모의 시험만으로 승인하지 않는다.

## 4. 기능별 추적표와 수용 사례

아래 요구 ID는 03~07·09~12의 요구사항 표를 참조한다. `T-*`는 이 문서의 통합 시험 ID이며 요구 ID와 별개다. 05·06·09~12의 `M05-*`·`M06-*`·`M09-*`·`M10-*`·`M11-*`·`M12-*` 모듈 시험을 통과해도 실제 화면·저장소를 연결한 통합 시험을 생략하지 않는다. 요구사항이 바뀌면 대응 시험과 기대 결과를 함께 갱신한다.

선택 기능은 S1에서 채택 여부와 근거를 기록한다. 미채택 월페이퍼(WIN-05) 시험 부분은 사유와 함께 해당 없음으로 둘 수 있으나, 같은 시험 행에 포함된 분리 캘린더(WIN-04) 검증은 생략하지 않는다. 백링크 등 권장 확장도 채택 범위를 기록하며, 사용자 핵심 요구는 선택 기능으로 바꾸어 면제하지 않는다.

무작위 명령 시퀀스 시험은 시드를 기록한다. 예를 들어 메모 생성·이동·완료·관계 추가·휴지통·복원·일정 변경을 섞어 실행한 뒤 불변식을 검사한다. 실패 시 동일한 순서를 재현할 수 있어야 한다.

정기 일정의 한 건 이동·이후 분할·발생 완료·알림 미루기와 라벨 연결·삭제도 시퀀스에 포함한다. 단순 날짜 배열 대신 원래 발생 계보와 별칭을 따라가는 독립 기준 모델로 결과를 비교한다. 기대값을 구현의 같은 반복 전개 함수로 생성하지 않는다.

v1.3 시퀀스에는 수집함 정리·저장 보기 수정/실행·체크·템플릿 변경·회차 분할·진행 상태·완료 취소·겹침 경고 강행·일지 후보 갱신/저장을 포함한다. 보존해야 하는 회차 스냅샷과 사용자가 편집한 일지 문장을 독립 기준으로 비교하고, 이벤트 수집과 사용자에게 보이는 메모별 변경 이력을 같은 기능으로 확장하지 않는다.

단위 시험에서 예외만 던지는 것으로 끝내지 않고, 승인된 시험 환경에서 프로세스 강제 종료와 실제 파일 손상을 별도로 검증한다. 전원 차단에 준하는 시험은 업무 PC가 아닌 승인된 시험 장비에서 실시한다.

## 7. 시간·다중 창 결정론 시험

- 시스템 시각 조회와 예약 대기를 추상화해 시험 시계를 주입한다. 실제 시계의 몇 분을 기다리는 시험을 핵심 회귀에 의존시키지 않는다.
- `현재 시각`, `실행 중 경과시간`, `시간대`, `날짜`를 구별해 시험한다. 재시도 지연에는 단조 경과시간이 필요한지 검토한다.
- 같은 시각 알림 100건, 자정 경계, 월말, 윤일, 시계 2시간 전진·후퇴, 절전 3일 뒤 복귀를 포함한다.
- 다른 시간대를 지원한다면 일광절약 전환의 존재하지 않는 시각·중복 시각 정책을 시험한다. 한국 시간만 지원할 경우에도 생성·표시 시간대의 변경 제한과 가져오기 처리 기준을 검사한다.
- 창 A와 B가 같은 개정을 읽은 뒤 A 저장→B 저장, B 저장→A 저장을 각각 실행한다. 자동 병합을 도입하면 겹치지 않는 수정과 같은 필드 수정의 결과를 분리 검증한다.
- 닫힌 창에 예약된 이벤트, 삭제된 메모를 늦게 여는 이벤트, 재생성한 창의 과거 이벤트가 잘못 적용되지 않아야 한다.
- 같은 반복 계열에 실제 날짜가 교차하는 예외를 만들고 ‘이후’ 경계를 원래 순번으로 재현한다. 반복 분할 후 옛 창의 occurrence 키를 전달해도 별칭 해석 또는 명시 충돌로 처리하며 다른 발생을 수정하지 않아야 한다.
- 알림은 같은 `(lineage_id, global_ordinal)`에 같은 설정 generation이면 논리 1건이다. 단일 이동 전후 settings generation이 그대로인 경우도 건별 delivery_revision으로 과거 실행을 막고, 다른 건의 acknowledged/snoozed를 보존하는지 확인한다.
- 주간·평일·주말 반복은 날짜 집합과 현지 시각의 의미를 검사한다. 평일에서 공휴일을 자동 제외하지 않으며, 그 기능을 추가하면 독립 규칙·출처·갱신 시험이 필요하다.
- 라벨 필터가 켜진 창에서 다른 창이 마지막 선택 라벨을 제거할 때, 행이 사라져도 미저장 초안과 선택 복구 동선을 유지한다. 반복 발생별 완료를 전체 Note 완료로 처리하지 않는지도 함께 확인한다.
- 저장 보기의 상대 `오늘/이번 주`는 저장 당시 절대 날짜가 아니라 실행 시점의 civil date를 기준으로 평가한다. 자정·월/연말·시간대 변경을 시험 시계로 재현하고 삭제 참조 때문에 조건이 사라져 전체 목록이 되는지 검사한다.
- 체크리스트 스냅샷을 생성한 뒤 템플릿·원본 메모·반복 회차를 서로 다른 창에서 바꾼다. 진행률의 분자·분모와 체크 identity가 원래 슬롯에 남는지 확인한다. Note 전체 완료가 무한 미래 스냅샷을 선생성하지 않아야 한다.
- 겹침은 실제 UTC 구간과 설정 시간대의 표시 의미를 분리한다. 맞닿는 구간·자정 통과·DST·이동 예외·숨김 필터·검사 horizon을 독립 expected interval 자료로 검증하며 구현의 같은 overlap 함수를 기대값으로 사용하지 않는다.
- 업무일지 보고 날짜는 이벤트 발생 시각을 지정 시간대로 변환한 날짜다. 예정일과 달라도 이벤트가 난 날짜에 표시한다. 완료 취소·분할 이동·늦게 도착한 이벤트·같은 명령 재시도와 일지 원본 제외를 제어한 순서로 재현한다.

알림 전달은 장애까지 포함해 화면 표시를 정확히 한 번 보장한다고 표현하지 않는다. 발생 ID에 의한 논리적 중복 식별, 확인 상태 영속화, 확인 전 재시도 가능성, 과거 세대 무효화를 각각 시험한다.

## 12. 배포 판정과 증거 보관

배포를 막는 조건은 미해결 S0, 핵심 사용자 흐름을 막는 S1, 검증되지 않은 이전·복구, 보안 제약 위반, 지원 범위를 알 수 없는 공휴일 자료, 재현 불가능한 설치물이다. 정기 일정 범위 이동·즐겨찾기 반입/승인 브라우저 실행·사용자 라벨은 이번 핵심 범위이므로 미구현을 선택 기능 제외로 처리하지 않는다. 낮은 심각도 결함을 남겨 배포한다면 영향·우회 방법·수정 계획을 기록하고 승인 담당자가 판단한다.

표 붙여넣기·편집 가능한 본문 표·표 모아보기·문단 자동 들여쓰기도 핵심 범위다. Enter 의미를 사용자의 확인과 다르게 구현하거나, 표를 모두 평문/이미지로 바꾸어 기능 완료로 보고하지 않는다. 사내 클립보드가 차단된 경우의 안전한 거부는 별도 검증하되, 허용된 표 입력까지 미구현으로 남긴 것을 완료로 간주하지 않는다.

빠른 메모·수집함, 저장한 보기, 본문 체크리스트, 진행 상태, 일정 겹침 안내, 하루 업무일지 초안도 사용자에게 채택된 핵심 범위다. 핵심을 빠뜨린 상태를 선택 기능 제외로 처리하지 않는다. 메모별 변경 이력 UI·예전 본문 비교·부분 복원은 제외 범위이며, 일지 기능을 그 기능으로 확장하지 않는다. 반면 제외를 이유로 기존 실행취소·실패 초안·백업/복원이나 회차 체크 스냅샷의 보존을 제거해서도 안 된다.

시험 보고서에는 앱·스키마·패키지 버전, 대상 PC·보안 환경, 데이터 세트, 실행 시각, 단계, 예상·실제 결과, 통과/실패, 재현 순서, 관련 결함 번호를 포함한다. 화면·로그는 승인된 범위에서만 보관한다. 실제 업무 본문은 시험 증거에 불필요하게 복사하지 않는다.

운영 중 발견한 결함은 재현 가능한 최소 데이터와 시나리오를 만든 뒤 회귀 시험으로 편입한다. 수정 후에는 영향받는 저장·계층·일정·알림·복구 경로를 중심으로 재시험하며, 관련 없는 전체 시험을 관성적으로 반복하기보다 변경 영향과 남은 위험에 근거해 범위를 정한다.
