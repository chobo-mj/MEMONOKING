# 07. 기존 데이터 이전·백업·복구·폐쇄망 배포 계획

> 최신 범위: [23 프로젝트 단일 분류·아이콘 도구](23-projects-icon-toolbar.md)에 따라 라벨과 `LABEL-*` 계약은 폐기되었다. 이 문서의 라벨 모델·필터·시험은 과거 설계 참조이며 구현하지 않는다. 프로젝트와 메모 자체 색상, 위키/정리 폴더는 유지한다.

이 문서는 기존 업무관리툴의 데이터를 보존하면서 업그레이드하기 위한 실행 계획이다. 현재 코드·저장 형식·사내 보안 제품의 동작은 확인되지 않았다. 따라서 아래 절차는 목표 설계이며, 실제 변환기·백업 명령·설치 방식은 기존 코드 분석 및 대상 PC 검증 후 확정한다. 기존 저장소를 직접 수정하면서 변환하는 방식은 기본안으로 채택하지 않는다.

분석은 원본의 읽기 전용 사본으로 시작한다. 개발자에게 실제 업무 내용을 제공하기 어렵다면 사용자가 승인한 익명화 표본과 빈 테스트 데이터로 먼저 변환 규칙을 검증한다. 암호화·DRM이 적용된 저장 형식은 승인된 접근 수단이 있는지 확인하며, 우회 도구를 만들지 않는다.

## 3. 이전 데이터 대응 기준

### 3.1 식별자와 본문

- 새 ID 체계를 도입해야 한다면 `source_store_id + legacy_id → new_note_id` 대응을 영구 기록한다. 기존 ID가 안정적이고 충돌하지 않으면 보존 가능성을 먼저 검토한다.
- 원본마다 고유한 `source_store_id`를 부여한다. 이름이 같은 메모는 중복 ID로 간주하지 않는다.
- 제목 없음은 빈 제목으로 보존하고 화면에서만 임시 표시명을 제공한다. 날짜·번호 등을 임의 제목으로 덮어쓰지 않는다.
- 구형 본문을 구조화 문서로 변환할 때 원문 바이트 또는 손실 없는 원문 파일을 승인된 백업 영역에 보관한다. HTML 변환은 스크립트·외부 자원·위험 URL을 제거하고 제거 내역을 보고한다.
- 지원되지 않는 본문 구성요소는 사라지게 하지 않고 읽기 가능한 표시와 원본 참조를 남긴다. 보호된 문서는 허용된 메타데이터만 보존하며 내용 변환을 시도하지 않는다.
- 기존 본문에 포함된 이미지·링크의 순서와 사용 위치를 보존한다. 한 이미지를 여러 메모에서 사용한 경우 참조 개수를 검증한다.

### 3.2 계층과 관계

- 부모 참조는 ID 매핑 완료 후 연결한다. 부모가 누락된 메모는 별도 복구 그룹으로 표시하고 원래 부모 ID를 보존한다.
- 자기 자신이 부모이거나 순환이 있으면 해당 연결을 격리한다. 정상 부분은 복구 가능하게 하되, 어느 연결을 임시 분리했는지 사용자가 확인할 수 있어야 한다.
- 기존 관계가 방향성을 가진다면 무방향 관련 메모 링크로 변환해도 의미가 보존되는지 검토한다. 의미가 달라지면 별도 기존 관계 속성을 보존하고 변환 결정을 남긴다.
- 중복 관계는 논리상 한 관계로 묶되 원본 중복 개수와 출처를 보고한다. 없는 메모를 가리키는 링크는 텍스트와 원래 주소를 보존한다.
- 완료·휴지통 상태를 독립적으로 옮긴다. 부모 완료가 자식 완료를 뜻한다고 추정하지 않는다. 삭제 시각이 없으면 현재 시각을 삭제 시각으로 위조하지 않는다.

02 기준 모델은 `completed_at_utc=null`을 미완료, `trashed_at_utc=null`을 활성 상태로 해석한다. 기존 데이터가 ‘완료=true, 완료시각 없음’ 또는 ‘삭제=true, 삭제시각 없음’처럼 상태는 알려져 있고 시각만 없다면 null로 옮길 때 의미가 바뀐다. 이 경우 원래 상태 플래그·원시 시각·출처를 `MigrationStaging`에 보존하고 해당 항목의 일반 운영 저장소 활성화를 보류한다. 상태와 시각을 분리하는 모델 확장 또는 근거가 확인된 매핑을 먼저 결정한다. 임의 시각을 채우거나 활성·미완료로 정규화하여 통과시키지 않는다. 보류 항목은 보고서 개수와 원본 대응에 포함하며 사용자 화면에서 누락 사실을 숨기지 않는다.

### 3.3 시각·일정·알림

| 기존 값 | 변환 원칙 | 사용자가 확인할 항목 |
|---|---|---|
| 날짜만 있음 | 종일 일정의 지역 날짜로 보존 | 시간 없는 일정임을 표시 |
| 시간대가 확인된 시각 | 원래 시간대 정보를 남기고 UTC로 변환 | 변환 전·후 예시 |
| 시간대 없는 지역시각 | 기존 프로그램·설정·운영 기록으로 시간대 확인 | 확정 불가하면 `시간대 미확인` 상태 |
| 생성시각 없음 | 미상으로 남기고 이전시각은 별도 기록 | 생성시각과 이전시각 구분 |
| 수정시각 정밀도 낮음 | 원래 정밀도 메타데이터 보존 | 초·분 단위 정밀도 |
| 여러 독립 일정 정의가 한 메모에 존재 | 기준안은 메모당 정의 1개이므로 변환을 일시 중지하거나 승인된 매핑 적용. 반복 정의 1개의 여러 회차와는 구별 | 복수 정의 지원 확대 또는 자식 메모 분리 여부 |
| 지난 알림 또는 처리 여부 미상 | 이전 직후 자동 팝업을 보류하고 검토 목록에 넣음 | 유지·해제·시간 조정 |
| 단발 일정 | 같은 메모에 안정 Schedule ID와 `mode=once` 부여 | 날짜가 비슷하다는 이유로 정기 일정 추정 금지 |
| 기존 반복 규칙·예외 존재 | 규칙·종료 조건·원래 발생 키·실제 변경 날짜·완료/알림 상태를 함께 매핑 | 지원 규칙과 맞지 않으면 원시값 보존·보류 |

알림의 발생 기록이 없다면 새 앱에서 이미 확인한 알림이라고 추정하지 않는다. 반대로 모든 과거 알림을 한꺼번에 띄우지도 않는다. 전환 완료 화면에서 과거 알림을 요약하고, 사용자가 유지하기로 한 항목만 재예약한다. 전환 중 새 알림이 발생하지 않도록 이전 모드에서는 알림 전달을 중지한다.

### 3.4 정기 일정 모델 확장과 이력 보존

정기 일정은 [09 정기 일정](09-recurring-schedules.md)의 기본 기능이다. 메모당 Schedule 원본은 최대 1개지만 그 원본이 여러 발생 건을 만든다. 기존의 `note_id` 기반 단발 일정은 안정 `schedule_id`를 부여하여 무손실 변환한다. 같은 날짜의 동일 제목 메모를 합치거나, 일정 간격을 분석해 사용자 동의 없이 반복 규칙을 만들지 않는다.

이전·백업의 원본 집합에 Schedule의 once/recurring 모드, RecurrenceSeries 세그먼트와 연결, RecurrenceException, 발생 건별 OccurrenceState, OccurrenceAlias, 반복 계보·원래 순번, 기존 알림 확인·미루기·generation·건별 delivery_revision을 포함한다. 정기 발생의 안정 신원은 `(lineage_id, global_ordinal)`이며 `series_id+original_key` 주소는 분할 후 별칭으로 해석한다. 화면에 생성한 달력 캐시는 파생 데이터이지만 **옮긴 날짜와 예외·완료 상태는 원본**이다. 캐시처럼 폐기하거나 새 규칙만으로 재생성해서는 안 된다.

- 원래 발생 날짜/순서와 실제 표시 날짜를 별도 대조한다. 한 번 옮긴 예외를 새 기본 날짜로 오인하지 않는다.
- ‘이 날짜 이후 모두’로 이미 분할한 계열은 세그먼트 경계와 후속 규칙·예외·별칭을 함께 옮긴다. 경계는 현재 화면 날짜가 아닌 원래 발생 순서다.
- 기존 완료 날짜·실제 일정 날짜·확인 이력은 그대로 보존한다. Note 전체 완료와 발생 건 하나의 완료를 합치지 않는다.
- 알림 발생 건의 중복 방지 키를 reminder_id+설정 generation+정규 발생 키(계보 슬롯)로 확장한다. 단발·메모 절대 알림의 기존 1건은 명시적 단발 키로 매핑한다. null 비교 규칙에 의존해 여러 단발 건이 생기지 않게 한다. 단일 발생 이동은 해당 건의 delivery_revision을 바꾸며 무관한 확인·미루기 기록을 새 generation으로 재생성하지 않는다. 전달 실행의 세대·delivery_revision·유효 규칙/예외 버전도 복구 시 재검증한다.
- 끝없는 반복은 무한 행으로 변환하지 않는다. 규칙·예외·유한한 저장 이력만 옮기고 승인된 날짜 구간에서 결과를 전수 대조한다. 종료 횟수·종료일·cutoff의 포함/제외 의미도 대조한다.
- 구버전이 반복 예외·발생별 완료·별칭을 이해하지 못하면 열기를 차단한다. 단발 일정만 남기고 반복 데이터를 버리는 자동 다운그레이드는 제공하지 않는다.

### 3.5 즐겨찾기 HTML 가져오기와 라벨 이전

[10 즐겨찾기·라벨](10-bookmarks-labels.md)의 HTML 가져오기는 기존 메모 이전과 별도 ImportJob으로 처리한다. Chrome/Edge 프로필 DB를 읽거나 동기화·비밀번호·쿠키를 가져오지 않는다. 내보낸 파일을 승인된 경로에서 읽고 폴더 구조·순서·제목·주소·인코딩·잘못된 항목·중복 후보를 미리 보여 준다. HTML을 브라우저로 열어 파싱하거나 스크립트·외부 아이콘·원격 자원을 실행하지 않는다.

가져오기 원본 지문, 작업 ID, 원본 폴더/항목 대응, 사용자가 고른 중복 정책을 보존한다. 같은 작업 재시도는 같은 결과로 수렴하고, 재반입은 별도 미리보기 없이 기존 항목을 덮어쓰지 않는다. 취소·파싱 오류·저장 실패는 활성 즐겨찾기에 부분 반영하지 않는다. 주소는 원문을 보존하며 실행 허용 여부는 별도 정책 검사 결과다.

기존에 태그·색상 분류가 있으면 Label·NoteLabel에 명시적으로 매핑한다. 같은 이름의 다른 분류, 같은 색의 다른 이름, 대소문자·NFC 정규화 후 중복 이름은 대조표에 남기고 사용자 확인 없이 합치지 않는다. 색을 라벨 ID로 사용하지 않는다. 대표 라벨·표시 순서·여러 라벨 연결·라벨 없는 메모를 보존한다. 새 기능이 없던 데이터는 라벨 없는 상태로 옮기며 자동 분류하지 않는다.

Chrome/Edge 실행 설정의 바이너리 경로·설치 상태는 PC마다 다를 수 있다. 복구 파일의 임의 경로를 곧바로 실행하지 않고 대상 PC에서 승인된 설치 경로를 다시 탐지·검증한다. 브라우저를 열 수 있어도 폐쇄망에서 외부 사이트에 접속할 수 있다는 뜻은 아니다.

### 3.6 표·문단 자동 들여쓰기의 본문 형식 이전

[11 표·표 모아보기](11-tables-collection.md)와 [12 문단 기호·들여쓰기](12-outline-indentation.md)는 이번 핵심 범위다. 새 본문 형식의 버전과 기능 표식을 등록하고, 읽기·쓰기 가능한 앱 버전 범위를 사전 검사한다. 구형 앱이 표·문단 메타데이터를 해석하지 못하면 변경 전에 차단하며, 모르는 노드를 삭제한 뒤 정상 저장하는 다운그레이드를 허용하지 않는다.

- 표는 `body_doc` 안의 원본 구조다. `table_id`, `row_id`, `cell_id`, 문단 ID, 행·열 순서, rowspan/colspan과 병합 좌표, 셀 본문·링크·허용된 이미지 참조를 함께 옮긴다. 셀 좌표만 ID로 사용하면 앞 행 삽입 후 원본 위치를 잃으므로 안정 ID 대응을 유지한다.
- 기존 표를 지원되는 표 노드로 변환할 때 행·열·셀 수와 점유 격자를 검증한다. 병합·중첩 표·지원하지 않는 구조는 조용히 평탄화하지 않는다. 승인된 원문 보존, 명시적 변환 미리보기 또는 보류 목록 중 가능한 경로를 적용한다. 보류·차단 건수도 원본 대조 합계에 포함한다.
- 기존 텍스트에 `1.`, `i)`, `A)`, `ㄱ)`, `가)`, `-`, `*` 또는 앞 공백이 있다고 자동 목록으로 재해석하지 않는다. 이전과 재열기 자체는 입력 이벤트가 아니다. 기존 본문·공백·사용자 번호를 그대로 보존하며 명시적인 사용자 변환 또는 기존의 확인된 구조 메타데이터가 있을 때만 새 문단 모델로 매핑한다.
- 문단의 논리 level·marker family·ordinal·목록 문맥·수동 보정 값과 paragraph_id를 본문과 같은 저장 단위로 옮긴다. 두 칸 들여쓰기를 실제 공백 2개와 구조 level 양쪽에 중복 반영하지 않는다. 변환 전·후 렌더링과 안전한 텍스트 추출을 따로 대조한다.
- 사용자 확인에 따라 Enter는 **같은 수준의 다음 번호·기호**다. 이전 후 설정·실행 동작도 이 의미를 유지하고 ‘다음 레벨’이라는 과거 모호한 설명만으로 매 Enter마다 하위 수준을 추가하지 않는다. Shift+Tab으로 수동 보정한 문단을 다시 열었다고 원래 자동 수준으로 되돌리지 않는다.
- `TableUsageIndex`와 표 미리보기·검색 색인은 파생 데이터다. 백업에서 제외할 수 있지만 본문에서 재구축하고 같은 table_id/원본 위치로 이동할 수 있어야 한다. 파생 색인만으로 표를 복원하거나, 오래된 색인을 원본 본문에 역으로 덮어쓰지 않는다.
- 새 표 붙여넣기는 승인된 클립보드 데이터만 받는다. HTML/TSV 입력 가능성은 사내 정책·실제 클립보드 표본으로 확인하며, 잠긴 PDF/PPT/Excel 파일을 열거나 OLE·Office 자동화·변환으로 표를 추출하지 않는다. 복구 도구도 같은 제한을 지킨다.

전환 전 리허설에는 병합 표·셀의 한글/줄바꿈/이미지/링크, 수동 들여쓰기 보정·상위 번호 복귀, 표 셀 안의 목록을 포함한다. 변환 또는 저장 도중 중단 후 재개해도 표·행·셀·문단 ID를 중복 생성하지 않는지 확인한다. 알 수 없는 본문 버전을 발견하면 원본 복사본과 설명을 남기고 이전을 보류한다.

### 3.7 빠른 수집·저장 보기·체크리스트·진행 상태·일지의 확장

v1.3의 [13 빠른 수집·저장 보기·체크리스트](13-capture-views-checklists.md)와 [14 진행 상태·겹침·업무일지](14-status-overlap-journal.md)는 이번 핵심 범위다. 사용자 요청에 따라 **메모별 변경 이력 열람·이전 본문 비교/부분 복원 화면은 제외**한다. 이 제외는 실행취소·저장 실패 초안·일관 백업·복구와 반복 완료/체크 상태의 보존을 제거하는 뜻이 아니다.

- 기존 Note는 `collection_state=filed`로 옮긴다. 기존 데이터 전체를 수집함에 새로 넣거나 생성시각을 이전 시각으로 바꾸지 않는다. 신규 빠른 메모는 `inbox`로 생성하고 사용자의 명시적 정리 완료로 `filed`가 된다. 라벨·일정·부모 변경만으로 수집함을 자동 비우지 않는다. 기존 앱에 실제 미정리 표시가 있었다면 확인된 의미를 매핑하고 차이를 보고한다.
- 전역 단축키는 사용자 설정으로 백업하되 대상 PC에서 등록 충돌·사내 허용·상주 여부를 재검증한다. 과거 키를 강제로 빼앗거나 복원만으로 관리자 권한·서비스·자동 시작을 새로 설정하지 않는다. 완전 종료 중 단축키가 동작한다고 보장하지 않는다. 빠른 입력 초안·중복 방지 요청 ID의 재개는 정상 메모 저장과 같은 규칙을 따른다.
- 저장 보기는 `SavedView`의 ID·이름·조건 스키마 버전·허용 조건 AST·정렬·화면 설정·revision을 보존한다. SQL/실행 스크립트로 변환하지 않는다. `이번 주`는 고정 날짜로 내보내지 않고 상대 기간과 기준 시간대를 보존해 복원 후 현재 날짜에서 다시 계산한다. 삭제된 라벨·없는 부모·미지원 조건을 발견하면 무효/확인 필요로 표시하고 조건을 제거해 전체 메모로 조용히 넓히지 않는다.
- 본문 체크항목은 안정 `check_item_id`와 내용·배치·일반 메모의 체크 상태를 본문 형식과 함께 이전한다. 기존 평문의 `[ ]`, `[x]`나 기호만으로 자동 체크리스트를 추정하지 않는다. 확인된 구조 체크박스만 매핑하거나 사용자의 명시 변환을 거친다. 체크 개수와 Note 전체 완료는 독립이다.
- 정기 일정 체크는 `(lineage_id,global_ordinal,check_item_id)`의 `OccurrenceChecklistState`와 최초 상호작용/완료 시 확보한 `ChecklistOccurrenceSnapshot`을 함께 보존한다. 어제 체크를 오늘·미래 회차에 복제하지 않는다. 이미 사용한 스냅샷의 항목·분모·내용은 템플릿 추가/삭제로 조용히 바뀌지 않으며, 시작하지 않은 미래 회차는 최신 템플릿의 미체크 상태를 사용한다. 세그먼트 분할 시 정규 슬롯 identity로 연결을 유지한다. 이 스냅샷은 업무 체크 상태이며 과거 메모 본문을 열람하는 이력 기능이 아니다.
- 진행 상태 `todo/in_progress/waiting/on_hold`와 완료시각을 분리한다. 완료 표시용 `done`을 두 원본에 중복 저장하지 않는다. 기존 상태가 없으면 `todo`로 매핑하고 기존 완료시각은 유지한다. 회신 대기/보류만으로 일정·알림을 끄거나 부모/자식·다른 반복 회차 상태를 바꾸지 않는다. 반복 회차 상태는 정규 키에, 원본 전체 상태는 Note에 별도 보존한다.
- 겹침 목록·확인한 경고 캐시는 원본 일정에서 다시 계산할 수 있다. 백업 복원 직후 유효한 단발·반복 예외·완료·취소·휴지통·시간대 정책으로 재검사한다. 과거의 ‘겹침 없음’ 표시를 다른 날짜 범위나 새 규칙에서 재사용하지 않는다.
- 업무일지의 원본은 최소 `ActivityEvent`와 사용자가 편집·저장한 일지 Note다. 이벤트에는 발생 시각·종류·원본 ID·회차 키·명령 ID·필요한 일정 전후 구간만 보존하고 예전 본문·키 입력·클립보드·스크린샷을 쌓지 않는다. 생성/완료/완료취소/일정 이동을 표현하되 이후 일정을 무한히 바꾼 명령은 범위 이벤트 한 건으로 보존하며 무한 미래 이벤트를 선생성하지 않는다.
- 기존 이벤트가 없으면 이전 날짜의 활동을 실제로 수집했다고 꾸미지 않는다. 일지 후보에 사용할 수 있는 자료 기준일·수집 시작 전의 미수집 기간을 표시한다. 확인된 생성/완료 시각을 참고로 표시할 수 있어도 실제 이벤트와 재구성 자료를 구분한다. 이전 작업 자체를 오늘의 신규 메모/완료 업무로 집계하지 않는다. `ActivityCoverage`의 tracking_started_at_utc/retained_from_utc/last_committed_watermark/known_gaps도 함께 이전·백업하여 조회 기간의 완전성을 설명한다.
- `JournalDraft`의 선택·편집 내용·기준 날짜/시간대·입력 범위·원본 참조·저장 결과 ID·멱등 키를 보존한다. 저장한 일지는 일반 Note 본문·자산으로 복구하고 다시 생성해 사용자 문장을 덮어쓰지 않는다. 일지 메모와 일지 생성 이벤트는 다음 일지의 업무 후보에서 제외해 재귀 증식을 막는다. 원본이 삭제되어도 일지에 사용자가 남긴 문장을 조용히 삭제하지 않고 링크 상태를 표시한다.

전환 대조에는 수집함/정리됨 개수, 저장 보기의 조건·동적 기간·무효 참조, 체크항목/회차 스냅샷 ID·분모·완료 수, 진행/완료 조합, 최소 이벤트 개수·기준 기간, 일지 초안/저장 Note를 포함한다. 상태·뷰·일지 후보를 정확히 옮길 수 없으면 원시값·보류 원인을 남기며 정상값으로 위장하지 않는다. 구형 앱이 새 체크·상태·뷰·일지 스키마를 이해하지 못하면 수정 전에 차단한다.

## 4. 일관된 백업 세트

### 4.1 백업에 포함할 항목

1. 기준 시점의 정식 DB 또는 구조화 저장소. DB가 로그·저널을 사용한다면 해당 엔진의 지원 백업 기능을 우선 사용한다. 파일 하나만 복사해도 안전하다고 가정하지 않는다.
2. 같은 기준 시점의 관리 자산 원본. 썸네일·검색 색인처럼 재생성 가능한 데이터는 제외할 수 있으나, 제외 목록과 재생성 절차를 기록한다.
3. 복구에 필요한 설정과 스키마·앱·본문 형식 버전, 공휴일 패키지 버전 및 사용자 수정 휴일.
4. 백업 매니페스트, 파일별 크기·해시·상대 경로, 백업 생성 시각·완료 시각, 저장소 ID, 일관성 기준 ID.
5. 암호화된 데이터라면 승인된 복구 키 관리 절차. 키를 백업 데이터와 같은 평문 파일에 넣지 않는다.
6. 반복 규칙·세그먼트·예외·발생별 완료·별칭·알림 확인/미루기 상태, 즐겨찾기 폴더·항목·가져오기 대응, Label·NoteLabel·대표 라벨·표시 순서. 라벨별 필터·브라우저 선택 등 재현할 설정도 승인 범위에서 포함한다.
7. 표·셀·행·문단 구조와 안정 ID, 병합 정보·표 설명, 셀의 이미지/링크 자산 참조, 목록 기호 family/ordinal/level·수동 보정·목록 문맥. 자동 서식 설정은 재현 가능한 사용자 설정으로 포함한다. 실행취소 이력은 보존 정책에 따르며, 현재 확정 본문을 대신하는 유일한 사본으로 삼지 않는다.
8. 수집함 분류·빠른 입력 보호 초안과 재개 상태, 전역 키 설정, 저장 보기 조건·스키마·revision·정렬, 본문 체크 ID·체크 상태·회차 체크 상태/스냅샷, Note/회차 진행 상태, 최소 업무 이벤트의 보존 대상과 ActivityCoverage, 일지 초안·선택·편집·저장 Note 대응·source_kind/원본 참조. 파생 겹침 결과·보기 조회 결과는 제외 가능하나 재계산 절차를 기록한다.

자산이 변경 불가능한 파일로 저장되어 있다면 DB 스냅샷이 참조하는 자산 목록을 고정한 뒤 그 자산들을 복사하고 완료까지 정리 작업을 막는 방식을 검토한다. 그렇지 않으면 짧은 쓰기 중지 구간을 두어 DB와 자산을 함께 고정한다. 실제 방법은 기존 저장소가 제공하는 일관성 기능에 맞춘다.

### 4.3 백업 상태기계

`대기 → 기준점 확보 → 복사 중 → 무결성 검사 → 완료`

- 어느 단계든 오류가 나면 `실패`로 끝내고 완성된 백업과 구별한다.
- 임시 이름으로 쓰고 마지막에 완료 마커와 매니페스트를 확정한다. 완료 마커만으로 신뢰하지 않고 파일 목록·크기·해시도 확인한다.
- 백업 실패로 기존 정상 백업을 삭제하지 않는다. 보존기간에 따른 정리는 새 백업 검증 후 별도 실행한다.
- 백업 중 디스크 부족·권한 변경·보안 제품 차단은 사용자에게 저장 위치와 재시도 방법을 안내한다. 업무 본문을 오류 로그에 넣지 않는다.

백업 주기·보존기간·위치는 사내 정책 확인 후 확정한다. 초안 운영값은 매일 자동 백업, 이전·업데이트 직전 별도 백업, 최소 1회 다른 승인된 매체에 복구 가능한 사본 확보로 두되, 정책과 용량을 검증하기 전 제품 보장으로 표시하지 않는다.

## 5. 단계별 이전 절차와 상태기계

`분석 → 사전 검사 → 원본 스냅샷 → 임시 저장소 변환 → 검증 → 전환 대기 → 전환 → 운영 검증 → 완료`

오류 분기는 `수정 필요`, `재시도 가능`, `복구 필요`로 구분한다. 변환 실패가 원본 데이터 변경으로 이어져서는 안 된다.

### 단계 A. 분석·사전 검사

- 앱과 저장소 버전을 확인하고 지원하지 않는 버전은 중지한다.
- 원본 개수·부모 연결·관계·이미지·링크·일정·알림의 기준 통계를 저장한다.
- 반복 계열/세그먼트/저장된 예외/발생별 완료/별칭, 즐겨찾기 폴더·항목·라벨·연결의 개수를 기준 통계에 추가한다. 무한 반복의 총 발생 건수를 유한 개수처럼 보고하지 않는다.
- 디스크 여유를 원본·임시 결과·백업·최대 변환 팽창량의 합으로 계산한다. 단순히 원본의 고정 배수만으로 통과시키지 않는다.
- 다른 앱 인스턴스·열린 저장소·쓰기 작업을 확인한다. 강제로 파일 잠금을 해제하지 않는다.
- 백업 파일이 실제 복구되는지 표본 시험한다. 검사 실패 시 전환하지 않는다.

### 단계 B. 임시 저장소 변환

- 변환 전용 폴더에 새 저장소를 만든다. 원본은 읽기 전용 유지한다.
- 이전 작업 ID, 원본 스냅샷 해시, 변환기 버전, 단계별 체크포인트를 기록한다.
- 메모 → 자산 → 계층 → 관계 → 일정·알림 → 파생 색인 순으로 처리한다. 순서는 엔진에 맞춰 조정해도 참조 검증을 생략하지 않는다.
- 반복 원본 → 예외·발생별 상태·별칭 → 알림 참조, Label → NoteLabel, 즐겨찾기 폴더 → 항목·가져오기 대응 순의 의존성도 검증한다. 파생 발생 캐시는 원본 검증 후 재생성한다.
- 배치 완료는 새 저장소 커밋과 체크포인트가 일관되게 남도록 한다. 기존 완료 배치를 반복해도 `(작업 ID, 원본 ID)` 기준으로 중복 삽입되지 않게 한다.
- 원본 스냅샷이 달라졌으면 같은 이전 작업을 이어서 실행하지 않는다. 새 작업으로 시작하거나 명확한 증분 규칙을 적용한다.
- 알 수 없는 속성은 확장 메타데이터 또는 원문 보관 영역에 보존하고 보고한다. 개인정보가 든 실패 항목을 일반 로그로 내보내지 않는다.

### 단계 C. 자동·수동 검증

자동 검증은 개수 일치뿐 아니라 ID·계층·본문·자산·시간 의미를 확인한다. 정상·격리·보류 항목의 합이 원본 항목 수와 일치해야 한다. 정규화로 달라지는 값은 허용 차이 목록에 근거가 있어야 한다.

수동 검증은 긴 한글 본문, 중첩 메모, 여러 이미지, 잘못된 링크, 종일 일정, 과거 알림, 완료·휴지통 메모를 반드시 포함한다. 실제 사용자 업무 흐름으로 검색 → 원본 열기 → 수정 → 재시작 → 재검색을 확인한다.

정기 일정은 매일·매주·선택 요일·평일·주말, 한 번 옮긴 건, 이후 일정 분할, 완료·다시 알림 이력이 있는 건을 검증한다. 즐겨찾기는 폴더 중첩·동일 주소 여러 위치·한글 제목을 대조하고, 실행은 승인된 시험 주소로 명시적 클릭 때만 시험한다. 라벨은 상단 띠·대표 순서·any/all/없음 필터와 색상 변경 후 원본 메모 수정시각 불변을 확인한다.

빠른 수집은 단축키→한 번 저장→수집함→정리 완료를 확인한다. 저장 보기는 `이번 주+라벨+미완료`를 복원해 상대 날짜를 새로 평가한다. 체크리스트는 표 셀·일반 문단·정기 회차를 구분하여 진행률을 대조하고 템플릿을 바꾼 뒤 과거 스냅샷을 확인한다. 진행 중·회신 대기·보류·완료를 결합하여 상태가 알림을 암묵 취소하지 않는지 확인한다. 숨긴 일정과 맞닿은 구간을 포함한 겹침 경고, 날짜별 최소 이벤트→선택→일지 편집/저장→다시 생성의 멱등·원문 보존도 검증한다.

### 단계 D. 전환과 사후 확인

- 짧은 전환 시간 동안 기존 앱의 쓰기를 중지한다. 전환 중 작성이 필요하면 전환을 미루거나 승인된 별도 기록 절차를 정한다.
- 기존 경로를 덮어쓰지 않고, 새 저장소 경로를 활성 경로로 지정하는 원자적 설정 변경을 우선 검토한다.
- 전환 직전·직후 저장소 ID와 기준 통계, 설정 경로, 앱 버전을 기록한다.
- 새 앱에서 핵심 화면을 열고 읽기·쓰기·재시작·검색·알림·자산 표시를 확인한다.
- 구형 앱이 새 저장소를 여는 것을 막는다. 호환되지 않는 앱 버전은 안내 후 읽기·쓰기를 중지한다.
- 운영 확인 기간·원본 보관기간은 조직 정책과 담당자가 정하며, 완료 처리 전에 복구 가능한 이전 백업을 다시 확인한다.

## 6. 롤백과 업데이트 후 생성 데이터 보존

전환 전에 실패했다면 임시 결과를 보류하고 원본 앱을 계속 사용한다. 임시 결과를 삭제하기 전 실패 진단에 필요한 비민감 기록과 격리 목록을 보존한다.

전환 후 수정이 없으면 검증된 원본 스냅샷과 기존 앱으로 복귀할 수 있다. 전환 후 수정이 있으면 원본 백업만 복원하면 새 업무가 유실되므로 다음 중 사전에 검증된 절차를 적용한다.

1. 전환 후 변경·새 자산을 새 앱의 별도 일관된 백업으로 보존하고, 지원되는 역변환기로 기존 형식에 반영한 뒤 차이를 확인한다.
2. 역변환을 지원하지 않으면 새 저장소 전체를 보존하고 읽기 가능한 변경 내역을 승인된 형식으로 추출한다. 사용자가 재반영할 수 있도록 원본 ID·변경시각·내용·자산 대응을 제공한다.
3. 새 앱 자체의 데이터 무결성이 의심되면 쓰기를 중지하고 마지막 정상 시점과 이후 변경을 분리 보관한 뒤 복구한다. 조용히 과거 백업으로 덮어쓰지 않는다.

전환 후의 반복 분할·예외 날짜·완료·알림 확인, 즐겨찾기 가져오기·수정, 라벨 추가·변경·연결도 새 업무 데이터다. 역변환 대상 앱이 이 기능을 표현하지 못하면 새 저장소와 설명 가능한 변경 내역을 별도 보존하고 지원 불가를 명시한다. 미래 발생을 유한한 메모 사본으로 펼쳐 손실을 숨기지 않는다.

어느 방식이든 새 작업을 잃지 않고 되돌리는 절차를 리허설해야 한다. 역변환이 검증되지 않았다면 ‘원클릭 완전 롤백’을 약속하지 않는다. DB 스키마를 올린 뒤 바이너리만 구버전으로 내리는 것은 롤백으로 인정하지 않는다.

## 7. 복구 리허설

| 상황 | 복구 방법 | 통과 기준 |
|---|---|---|
| 앱 강제 종료 | 마지막 커밋 복원, 미커밋 초안 처리 | 저장 완료 표시된 메모가 유지됨 |
| DB 손상 | 별도 폴더에서 정상 백업 복원 후 검사 | 메모·계층·관계·자산이 열리고 수정됨 |
| 이미지 일부 유실 | 누락 참조 보고, 자산 백업에서 복원 | 깨진 위치가 식별되고 내용이 무관하게 삭제되지 않음 |
| 검색 색인 손상 | 원본으로 색인 재생성 | 결과가 기준 데이터와 일치 |
| 사용자 PC 교체 | 승인된 백업·키·런타임으로 복원 | 시간·설정·자산·알림 정책이 검증됨 |
| 백업 파일 손상 | 해시 불일치 탐지, 이전 정상 백업 선택 | 손상본을 정상으로 표시하지 않음 |
| 업데이트 도중 중단 | 커밋 전후 상태 판별 후 재개 또는 복원 | 혼합 스키마로 실행되지 않음 |
| 반복 분할·예외 손상 | 규칙·원래 키·별칭·발생 상태가 포함된 백업 복원 | 특정 건 이동과 이후 규칙, 완료·알림 상태가 같은 발생 건을 가리킴 |
| 즐겨찾기·라벨 복원 | 폴더·항목·가져오기 대응·라벨 연결을 함께 복원 | 중복 반입·연결 유실 없음, 대상 PC 브라우저 경로 재검증 |

복구는 빈 시험 프로필 또는 별도 폴더에서 수행한다. 복원 버튼이 성공했다고 끝내지 않고 메모 열기·수정·재시작·이미지 표시·검색·관계 이동·알림 1건을 실제 확인한다. 업무 본문이 드러나는 화면 기록은 조직 허용 범위에서만 남긴다.

추가로 정기 일정의 ‘이번만 이동’과 ‘이후 모두 이동’을 한 번씩 수행하고 원래 완료 이력·알림 키를 확인한다. 즐겨찾기 폴더 탐색·승인 브라우저 열기, 라벨 띠·필터·색상 수정도 실제 실행한다. 브라우저 실행 실패나 네트워크 도달 실패를 백업 데이터 손상과 구분한다.

v1.3 복원 실연에는 빠른 메모 저장·수집함 정리, 저장 보기 실행/수정 충돌, 본문 체크·회차 체크·스냅샷 분모, 진행 상태·완료 독립, 숨긴 일정 겹침 재계산, 업무일지 초안 선택/편집/저장과 재생성 보호를 포함한다. 로그·이벤트·백업을 점검해 전체 본문 버전·키 입력·클립보드가 추가 기록되지 않았는지 확인하고 메모별 이력 열람 UI가 설치되지 않았음을 확인한다. 일지 원본 참조가 끊긴 경우 사용자 일지 문장은 유지한다.

표·목록 복구는 모아보기 개수만 보지 않는다. 병합 구조와 셀 내용을 열고, 표 모아보기에서 같은 table_id의 셀로 이동하고, 셀 이미지/링크와 검색을 확인한다. 문단에서는 `1.` 아래 `a)`를 만든 뒤 Enter의 같은 수준 자동 기호, `2.` 입력의 상위 수준 복귀, Shift+Tab 2칸 내어쓰기를 실제 수행한다. 표 안의 Tab/Shift+Tab이 셀 이동이며 들여쓰기 변경은 별도 버튼·단축키라는 우선순위도 검증한다.

## 8. 폐쇄망 배포·업데이트

- 설치물에는 승인된 런타임·라이브러리·폰트·정적 자원·라이선스 자료를 포함한다. 설치 후 자동 패키지 다운로드에 의존하지 않는다.
- 설치·업데이트 패키지와 공휴일 데이터 패키지를 분리 버전 관리한다. 공휴일 수정만으로 앱 전체를 바꾸지 않아도 되는 구조를 검토한다.
- 패키지 출처·버전·해시·서명 검증, 악성코드 검사, 사내 반입 승인을 조직 절차에 맞춰 수행한다.
- 일반 사용자 설치 가능 여부와 사전 설치가 필요한 구성요소를 확인한다. 관리 권한 요구는 필요한 부분에 한정한다.
- 자동 시작·트레이 상주·알림 전달이 사내 정책에서 허용되는지 확인한다. 앱이 완전히 종료된 동안의 알림은 실행 중 알림과 구분한다.
- 배포 전 승인된 Windows·보안 에이전트 조합의 실제 PC에서 설치·실행·업데이트·제거를 시험한다. 앱 제거 시 데이터 삭제는 별도 선택으로 분리하고 기본적으로 업무 데이터를 보존한다.
- 업데이트 직전 백업·스키마 호환 검사·디스크 검사·다중 인스턴스 검사를 수행한다. 실패 시 새 버전 실행을 차단하고 복구 안내를 제공한다.

## 10. 이 모듈의 개발·수용 순서

1. 기존 저장 구조 분석과 필드 대응표 작성.
2. 읽기 전용 사전 검사기 및 기준 통계 작성.
3. 일관된 백업·검증·복구 기능을 먼저 구현.
4. 임시 저장소 변환기·ID 매핑·격리 보고서 구현.
5. 단계별 중단·재개·중복 방지 시험.
6. 실제 승인 표본으로 이전 리허설 및 차이 확인.
7. 전환·호환성 차단·사후 검증 구현.
8. 전환 후 새 데이터가 있는 롤백 리허설.
9. 실제 폐쇄망 PC에 소수 배포 후 운영 결과로 확대 여부 판단.

완료 조건은 ‘변환기가 오류 없이 종료됨’이 아니라 DATA-01~05와 OPS-01~04의 증거가 확보되고, 보류·격리·유실 가능 항목의 처리 방침이 확정된 상태이다.
