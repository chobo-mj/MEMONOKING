# 00. 기존 코드·실행 환경 조사와 결정 전 확인사항

> 최신 범위: [23 프로젝트 단일 분류·아이콘 도구](23-projects-icon-toolbar.md)에 따라 라벨과 `LABEL-*` 계약은 폐기되었다. 이 문서의 라벨 모델·필터·시험은 과거 설계 참조이며 구현하지 않는다. 프로젝트와 메모 자체 색상, 위키/정리 폴더는 유지한다.

상위 계획: [plan.md](../plan.md). 이 단계가 구현의 시작점이다. 현재 기술 스택과 데이터 형식은 미확인이다.

## 1. 조사 원칙

원본 데이터에 쓰지 않는다. 승인된 저장 위치에 복사본을 만들고 기존 앱으로 열리는지 확인한다. 조사에 실제 업무 내용을 채팅·원격 서비스로 전송하지 않는다. 테스트 자료도 사내 정책에 맞게 익명화하며, 보안 문서를 복호화하거나 추출해서 익명화하지 않는다.

소스가 있다면 기존 구조를 우선 존중한다. 소스가 없거나 빌드가 안 된다고 곧바로 재개발을 결정하지 않는다. 소유권·수정 권한, 복구 가능한 저장소, 공급자의 공식 내보내기·확장 경로부터 확인한다.

분석 명령 결과에는 환경 경로·사용자명·본문 같은 민감정보가 포함될 수 있으므로 공유용 보고서는 필요한 메타데이터만 남긴다.

## 3. 코드 분석 순서

1. 저장소의 기존 개발 규칙과 빌드 설명을 읽고 기준 버전·작업 복사본을 기록한다. 기존 변경 사항은 보존한다.
2. 현행 앱의 정상 동작을 촬영 또는 체크리스트로 기록하고 익명 샘플의 데이터 개수·대표 값을 확인한다.
3. 실행 진입점부터 화면→서비스→저장 경로를 추적한다. 코드와 다른 오래된 설명은 사실과 구분한다.
4. 기존 데이터 읽기·쓰기, 메모 ID, 부모 관계, 시간 처리, 자동저장, 첨부 저장, 외부 실행·통신 경계를 찾는다.
5. 전역 가변 상태, 화면 직접 DB 접근, 재귀 트리, 타이머 알림, HTML 실행, 절대 파일 경로 의존을 확인한다.
6. 기존 테스트·실패 로그·크래시 복구·버전 변경 코드를 확인한다. 이미 안전한 기능은 재사용 후보로 남긴다.
7. 아래 위험 시제품과 데이터 이전 리허설을 작은 범위로 수행한다. 운영 데이터는 사용하지 않는다.
8. 현행 유지·점진 개선·부분 교체를 비용·회귀·보안 승인 기준으로 비교한다. 전면 재작성은 근거가 있을 때 별도 결정한다.

## 4. 기술 스택 선택은 이 단계 이후

다음은 선택 항목이다. 현재 결론이나 설치 지시가 아니다.

| 항목 | 판단 기준 | 확인 방법 |
|---|---|---|
| UI와 창 기술 | 기존 UI 재사용, IME, 다중 창, 접근성, DPI, 사내 런타임 허용 | 기존 기술 확장 시제품과 필요 시 대안 시제품 비교 |
| 저장 기술 | 현재 DB의 트랜잭션·버전·백업 지원, 파일 잠금·설치 부담 | 기존 저장소 장애 시험; 부족한 기능만 대안 검토 |
| 본문 편집기 | 한글 조합, 선택·붙여넣기, 로컬 이미지, 문서 버전, 보안 | 오프라인 패키지와 스크립트·원격 자원 차단 실험 |
| 표·문단 확장 | 행/열/병합/셀 내부 문단·안정 ID·기호 직접 입력·같은 단계 이어쓰기 | 표 paste round-trip, `1.→a)→Enter→2.`·Shift+Tab·IME·키 경합 실험 |
| 검색 | 한국어 부분 문자열 정확성, 데이터량, 증분 갱신 | 익명 실제 분포 비교; FTS 도입 필요성 측정 |
| 알림·상주 | 표준 권한에서 트레이·자동 실행·전면 전환 지원 | 사내 Windows·보안 제품 실PC 시험 |
| 반복 엔진 | 날짜·요일·예외·이후 분할·완료 이력, 끝없는 반복의 범위 생성 | 독립 기대 날짜표, 드래그·중단·별칭 매핑 시험 |
| 브라우저 실행 | 지정된 Chrome/Edge 실행, 구조화 인수·표준 권한·URL 정책 | 실제 설치/미설치·차단·특수문자 주소·오프라인 시험 |
| 이미지 처리 | 사내 허용 API, 디코더 취약점·상한, DRM 승인 경로 | 허용 이미지·차단 이미지·클립보드 시험 |
| 암호화 | 회사 표준과 키 복구 가능성, 백업·PC 교체 | 보안 담당 검토 및 다른 승인 장치 복원 시험 |

후보의 최신 유행보다 기존 코드 적합성, 사내 승인, 오프라인 유지 가능성을 우선한다. 선택 기록에는 버전, 라이선스, 대체 가능성, 오프라인 설치 용량, 보안 패치 반입 방법을 포함한다. 데이터베이스나 편집기 이름을 계획 단계에서 임의 고정하지 않는다.

## 6. 결정 기록 초안

모든 행의 초기 상태는 미확정이다. 담당자·근거·결정일·관련 코드·시험 ID를 붙여 관리한다.

| 결정 | 기본 제안 | 변경 시 영향 |
|---|---|---|
| D01 일정 정의 수 | 메모당 0~1개, 단발/정기 선택; 반복 회차는 별도 식별 | 복수 독립 정의가 필요하면 스키마·캘린더·알림·이전 재검토 |
| D02 자식 완료 | 자동 전파 안 함 | 묶음 완료는 미리보기·별도 명령·되돌리기 필요 |
| D03 삭제 | 휴지통·하위 트리 묶음 삭제 제안 | 자식 살리기 선택과 복원 정책 일치 필요 |
| D04 날짜 알림 | 날짜만 지정하면 알림 자동 생성 안 함 | 기본 시간·휴일·날짜 변경 재계산 규칙 필요 |
| D05 종료 | 닫기/트레이/완전 종료 동작을 설정으로 구분 | 상주 금지 시 종료 중 즉시 알림 불가 안내 |
| D06 본문 | 버전 있는 안전한 구조 문서 | 현행 HTML·텍스트의 무손실 변환 방법 필요 |
| D07 공휴일 | 승인된 연도별 검증 자료 패키지 | 담당·반입 주기·오류 수정 경로 확보 |
| D08 저장·암호화 | 현행 안전한 구조 재사용 우선 | 암호화 변경은 복원·키 이전 시험 필수 |

## 7. 조사 완료 수용기준

- DISC-01: 기준 빌드와 현행 동작이 재현되거나 재현 불가 이유·필요 자료가 구체적으로 기록되어 있다.
- DISC-02: 실 데이터 형식·시각 의미·첨부 위치를 샘플로 확인했다. 추정과 사실이 구별된다.
- DISC-03: 보안 기능별 허용·차단·미확인 표와 승인 경로가 있다. “폐쇄망이면 안전”이라고 대체하지 않는다.
- DISC-04: 기술 선택 기록과 기존 코드 변경 범위, 이전 가능성, 위험 시제품 결과를 검토했다.
- DISC-05: 예상 일정은 작업별 규모·인력·의존성·승인 지연 가정을 근거로 산정한다. 소스 미확인 상태에서 완료일을 확약하지 않는다.

다음 단계 착수 기록에 미해결 항목과 영향받는 기능을 명시한다. 이미지가 차단되었다고 메모 텍스트 설계를 중단할 필요는 없지만, 이미지 기능이 승인·검증됐다고 보고해서는 안 된다.
