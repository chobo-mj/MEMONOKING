# 21. 스티커 노트·독립 창 상태·화면 정돈

> 최신 범위: [23 프로젝트 단일 분류·아이콘 도구](23-projects-icon-toolbar.md)에 따라 라벨과 `LABEL-*` 계약은 폐기되었다. 이 문서의 라벨 모델·필터·시험은 과거 설계 참조이며 구현하지 않는다. 프로젝트와 메모 자체 색상, 위키/정리 폴더는 유지한다.

v1.7 · 2026-11-09. 최신 사용자 요청에 따라 16/20의 접기 전환과 메모 창 배치를 갱신한다. 이 문서와 이전 창 동선이 충돌하면 이 계약을 적용한다. 저장·백업·알림·반복 엔진의 제품 인수 조건은 유지한다.

## 화면 구성과 시각 규칙

전체 편집창은 제목·본문과 일정/기간·완료·분류 속성을 편집하는 곳이다. 스티커는 빠른 읽기·쓰기용 제목/본문만 보여준다. 둘은 동일한 원본 ID와 공통 본문 입력 엔진을 사용한다. 현재 프로토타입의 본문 엔진은 다중행 텍스트이며, 이 UI 추가가 표·본문 이미지·문단 자동 들여쓰기 엔진의 완성으로 해석되지 않도록 한다.

- 전체 편집 헤더: 접기와 스티커 진입을 나란히 놓고, 헤더 우측은 도움말·닫기를 묶는다. 본문에서 자주 쓰지 않는 관리 속성이 제목/본문을 압도하지 않게 정리한다.
- 제목 한 줄: 접기 아이콘, 드래그 가능한 제목, 전체 편집 아이콘만 제공한다. 닫기 아이콘·펼치기 텍스트는 두지 않는다. 제목 클릭과 제목 드래그를 이동 거리 임계값으로 구별한다.
- 스티커 헤더: 왼쪽 접기와 제목, 오른쪽 `+`·편집·도움말·닫기. 편집 아이콘은 전체 편집 폼을 열고, 본문 클릭은 바로 입력한다. 도움말은 닫기 바로 옆에 놓는다.
- 스티커 본문: 색상 배경 위에 충분한 대비의 글자, 본문 여백과 자연스러운 줄바꿈. 초기 창은 정사각형이며 사용자의 크기 조절을 허용하고 마지막 스티커 크기를 기억한다. 제목과 본문 경계를 간결하게 표시한다.
- 색상 네모: 제목·속성 텍스트 없이 선택 색을 표시. 단순 클릭은 기억한 모드로 복원, 중앙 드래그는 이동, 모서리 드래그는 크기 변경. 전체 제목과 복원 목적은 툴팁/접근성 이름으로 제공한다.

아이콘은 코드로 정의한 같은 선 두께·크기의 집합을 사용하고 글꼴마다 다른 유니코드 기호로 대체하지 않는다. 시각 아이콘만 제공하는 버튼도 툴팁과 접근성 이름을 가진다. 도움말은 현재 상태별 클릭/드래그·접기·편집·새 스티커·닫기 의미와 등록된 실제 단축키를 설명한다. 설정 화면에 입력 중인 미등록 문자열을 사용 중인 키로 안내하지 않는다.

기본 버튼의 대략적인 목표 포인터 영역은 28~32 논리 픽셀, 제목 한 줄은 40픽셀 안팎으로 검토한다. 수치는 여러 배율과 실제 장치로 확인한 뒤 확정한다. 작은 창에서 아이콘끼리 겹치거나 제목이 조작 버튼을 가리지 않게 최소 크기와 말줄임/툴팁을 함께 적용한다.

## 창 상태와 전환

논리 상태는 `Editor`, `TitleBar`, `Sticker`, `Swatch`로 구분한다. 창이 닫힌 상태는 표시 상태와 별개다. `preferred_compact_mode`는 색상 네모에서 복원할 목적을 나타낸다.

| 시작 상태 | 동작 | 결과 |
|---|---|---|
| Editor, 일반 모드 | 접기 | TitleBar |
| TitleBar | 접기 | Swatch, 일반 복원 목적 유지 |
| TitleBar | 제목 클릭 | Sticker, 이후 접기 복원 목적을 Sticker로 지정 |
| TitleBar | 편집 아이콘 | Editor |
| Editor | 스티커 노트 버튼 | Sticker, 복원 목적을 Sticker로 지정 |
| Sticker | 접기 | Swatch, 복원 목적=Sticker |
| Swatch, 복원 목적=Sticker | 클릭 | Sticker |
| Swatch, 일반 복원 목적 | 클릭 | 기존 일반 편집 경로의 Editor로 복원 |
| Sticker | 편집 아이콘 | 같은 원본의 Editor, 스티커 복원 목적은 유지 |
| Editor, 스티커 복원 목적 | 접기 | Swatch, 다음 클릭은 Sticker |
| Sticker/Editor | 닫기 | 해당 창만 닫힘, 원본 메모와 다른 창 유지 |
| Sticker | `+` 또는 전역 스티커 추가 | 새 메모·새 Sticker, 기존 창 유지 |

사용자가 스티커를 선택한 뒤에는 `Editor→접기→TitleBar→Swatch`의 일반 중간 경로를 다시 강제로 거치지 않는다. 전체 편집으로 잠깐 이동해도 기존 스티커 사용 의도는 보존한다. 기본 일반 모드의 이전 접기 흐름은 유지하되 제목 클릭이라는 새 스티커 진입 동작을 추가한다.

드래그 상태는 `Idle → Pressed → Moving/Resizing → Released`이며 `Pressed→Released`가 임계 거리 이하일 때만 클릭으로 판정한다. 이동/크기 변경이 끝난 뒤 단순 클릭 이벤트로 처리해 스티커가 뜻하지 않게 펼쳐지지 않아야 한다. 모드 전환 전에 IME 조합과 현재 입력을 공통 편집 정책으로 처리한다. 보류 중인 날짜 선택/완료 범위 대화상자는 새 작은 창 크기에 갇히지 않도록 소유자 기준으로 취소하거나 닫는다.

## 데이터와 다중 창 아키텍처

원본 `Note`의 제목·본문·생성시각·관계·위키·일정과 창의 표시 설정을 분리한다.

- `MemoWindow(window_id,note_id,presentation,preferred_compact_mode,editor_bounds,sticker_bounds,swatch_bounds,always_on_top,swatch_rgba,is_open)`.
- `ShortcutBinding(action=AddSticker,chord,enabled,registration_state)`를 기존 빠른 메모·분리 캘린더 바인딩과 함께 관리한다.
- `HelpContext(window_id,presentation,active_shortcuts)`는 오프라인 설명 표시 상태이며 업무 데이터로 저장하지 않는다.

여러 스티커는 각기 `window_id`와 `note_id`를 캡처한다. 전역 `active_note_index` 하나에 모든 창이 의존해 새 스티커를 만들자 기존 창의 내용이 새 메모로 바뀌는 구조를 피한다. 같은 메모를 여러 화면에서 보는 경우는 같은 원본 명령을 통해 동기화한다. 새 스티커의 제목·본문은 새 원본에만 기록되며 폴더/프로젝트/일정 기본값은 신규 메모 정책을 따른다.

창 중앙은 가능한 경우 사용자 작업 모니터의 작업 영역 중앙으로 정의한다. 현재 활성 스티커 또는 앱이 있는 모니터를 기준으로 하고, 화면 정보가 없으면 주 모니터 작업 영역을 사용한다. 작업표시줄 영역과 최소 여백을 고려해 화면 밖으로 생성하지 않는다. 여러 개가 중앙에 겹치면 새 창을 전면에 표시하고 기존 창 위치는 그대로 둔다. 자동으로 다른 모니터/사용자 창을 재배치하지 않는다.

완료 시간 표시는 `CanEditCompletion(note_id,occurrence_id?)` 투영으로 제어한다. 기간 메모의 다른 날짜가 완료됐더라도 현재 선택 발생이 미완료이면 `완료 시간 :`와 선택박스를 함께 숨긴다. 체크 해제/범위 취소 후에는 즉시 숨기고, 보이지 않는 컨트롤의 오래된 값이 나중에 다른 기록에 적용되지 않게 한다. 표시되는 경우에만 해당 완료 ID의 보정 명령을 허용한다.

## 단축키 등록과 실패 처리

설정에 ‘스티커 노트 추가’를 기존 두 전역 동작과 같은 방식으로 제공한다. 사용자가 조합을 입력한 뒤 적용하며 문법 오류·중복 동작 키·OS 점유·등록 실패를 표시한다. 바인딩 세 개를 일관된 순서의 action ID로 매핑하고 부분 등록/부분 복구를 성공으로 표시하지 않는다. 실패 시 이전 등록 집합을 복구하고, 복구 실패는 비활성 상태와 대체 버튼을 알린다. 앱 종료 시 모두 해제한다. 입력 키 전체를 기록하는 후킹이나 외부 전송을 추가하지 않는다.

앱이 종료된 상태에서 호출되는 상주 실행/자동 시작은 별도 운영 선택이다. 이번 단축키는 실행 중 앱의 Windows 전역 등록 기능이며 사내 정책이 막으면 메뉴/스티커 `+`로 동일 생성 명령에 접근한다.

## 마이그레이션과 현재 프로토타입 범위

기존 창 설정의 접기 모드를 `Editor/TitleBar/Swatch`로 보존하고, 기존 메모의 스티커 선호는 false로 초기화한다. 사용자가 새 스티커 버튼이나 제목 클릭을 선택한 시점에만 Sticker 선호를 부여한다. 기존 본문·관계·일정·완료 기록은 변환하지 않는다. 단일 활성 창 구조에서 다중 창 목록으로 옮길 때 열려 있던 원본 ID 하나를 첫 window_id에 매핑하고 임의 메모 복제를 하지 않는다. 새 AddSticker 단축키는 기존 키와 충돌하지 않는지 확인한 뒤 등록한다.

현재 UI 프로토타입에서는 앱 상태·스티커·창 위치/크기·단축키 변경이 메모리에만 존재하며 종료하면 초기화된다. 이미지 내보내기 등 사용자가 명시적으로 만든 파일과 구분한다. 제품 저장 단계에서는 창 설정과 메모 초안·종료/재시작 복구를 01/07 계약에 연결한다. 스티커가 여러 개 열린다는 사실을 저장·복구 완료로 보고하지 않는다.
